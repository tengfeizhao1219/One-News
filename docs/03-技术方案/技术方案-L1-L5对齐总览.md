## 2. 架构总览
```
小程序 pages/
  home/        首页：卡片滑动 + 侧边栏（WXS 手势，暗色，5 分类）
  detail/      详情页（跨分类阅读模式已完成）
cloudfunctions/
  getNewsList/    列表：L1 news_cache → L2 天行 → L3 聚合 → L4 内存 → L5 AI兜底 🆕
  getNewsDetail/  详情：L1 news 集合(where id) → L2 AI 兜底；正文缺失抓原文兜底
  refreshNews/    🆕 v4.0：智谱 GLM-4-Flash 联网搜索(主力) → DeepSeek API(降级) → 校验 → 安全审核 → 写 news_cache（每小时触发，15条/分类）
  common/         adapter / tianApi / juheApi / zhipuSearch 🆕 / llmSearch(已弃用) / contentExtractor / validator / config / cache / aiNewsService / aiNewsData / securityCheck
云数据库
  news          详情正文（getNewsList L1 成功时同步写入）
  news_cache    列表缓存（refreshNews 写入，TTL 10min）
```

## 3. 数据流
- **列表**：`getNewsList` → L1 news_cache(智谱生成) → L2 天行 → L3 聚合 → L4 内存 → L5 AI静态。
- **详情**：`getNewsDetail` → `news` 集合（按自定义 `id` 查）→ 未命中则 `aiNewsService.getById` 兜底；`content` 不足 30 字时 `contentExtractor` 抓原文，失败用 `summary` 兜底；阅读数 +1（`viewCount`）。
- **刷新**：`refreshNews` 🆕 v4.0 智谱 GLM-4-Flash `web_search` 全分类 → `validator` 质量校验+去重 → `securityCheck` 内容安全 → 按分类清旧写新到 `news_cache`。智谱失败自动降级 DeepSeek API。

## 4. 关键实现点（v11-v13）
- `contentExtractor`：实体解码 + 噪音过滤 + 首页标题截断（CSS `word-break`+摘要限 3 段）。
- `enrichMissingSummaries`：空摘要抓正文首段兜底。
- `adapter`：分类透传（移除不可靠的 `JUHE_TYPE_TO_APP` 反向映射）。
- `config`：聚合（Juhe）配置就绪；三套 API Key 经环境变量注入（见 `API-Key环境变量管理规范.md`）。
- 测试：数据层回归 178/178 通过。
