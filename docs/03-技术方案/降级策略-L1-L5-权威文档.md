## 1. 总览

新闻列表获取采用**五层降级**，目标：天行实时优先，任一层失效自动下沉，保证"永远有内容可看"，除非全部数据源不可用。

```
请求 getNewsList(category, pageNum, pageSize)
   │
   ├─ L1 天行实时 API ──── 成功 ──→ 返回（并同步写 news 集合缓存）
   │      │ 失败
   ▼
   ├─ L2 内存缓存 ──────── 命中 ──→ 返回
   │      │ 未命中
   ▼
   ├─ L3 云数据库缓存 ──── 命中 ──→ 返回（refreshNews 写入，TTL 10min）
   │      │ 未命中
   ▼
   ├─ L4 聚合数据 API ──── 成功 ──→ 返回
   │      │ 失败
   ▼
   ├─ L5 AI 静态缓存 ──── 命中 ──→ 返回（aiNewsService.getByCategory）
   │      │ 空
   ▼
   全部不可用 → { code:-1, errorCode:ALL_DOWN, message:"新闻服务暂时不可用，请稍后重试" }
```

---

## 2. 各层明细

| 层 | 数据源 | 触发条件 | 数据时效 | 依赖环境变量 | 失败/空处理 |
|----|--------|----------|----------|--------------|-------------|
| **L1** | 天行数据实时 API（`tianApi`） | 每次请求直连 | 实时 | `TIAN_API_KEY` | catch → 下沉 L2 |
| **L2** | 内存缓存（`cache` 全局变量） | L1 失败后查 `memoryKey=news:list:{cat}:{page}` | TTL ~5min（进程内） | 无 | 未命中 → 下沉 L3 |
| **L3** | 云数据库 `news_cache`（`refreshNews` 写入） | L2 未命中后查 DB | TTL 10min | 无（云开发自带） | 空 → 下沉 L4 |
| **L4** | 聚合数据 API（`juheApi`） | L3 空后调用 | 实时 | `JUHE_API_KEY`（**可选**） | catch → 下沉 L5 |
| **L5** | AI 静态缓存（`aiNewsService`） | L4 失败后读本地 JSON | 静态（构建/定时生成） | `DASHSCOPE_API_KEY`（**仅生成时需要**） | 空 → `ALL_DOWN` |

---

## 3. 关键行为

- **L1 成功时**：除返回外，还会 `enrichMissingSummaries` 补全空摘要，并 `syncNewsToCollection` 写回 `news` 集合（供 `getNewsDetail` 使用，约 ~100ms）。返回 `meta.source='tian_api'`、`synced:true`。
- **L4 可选**：未配置 `JUHE_API_KEY` 时 `juheApi` 抛 `API_KEY_INVALID`，自动下沉 L5。**聚合不是必选层**。
- **L5 兜底**：数据来自 `refreshNews` 云函数经百炼 DeepSeek 生成的静态 JSON（生成期落地），不实时。返回 `meta.source='ai_cache'` + `cacheVersion` + `cacheGeneratedAt`。
- **ALL_DOWN**：仅当 L1~L5 全部失败/空，返回 `{ code:-1, message, errorCode:ALL_DOWN }`。前端应展示错误态而非空白。

## 4. 环境变量（与任务 T-10 对齐）

| 变量 | 用途 | 必填 | 配置位置 |
|------|------|------|----------|
| `TIAN_API_KEY` | L1 天行实时 | ✅ 必填 | 微信云开发 → 云函数 → 环境变量 |
| `JUHE_API_KEY` | L4 聚合降级 | ⚠️ 可选 | 同上 |
| `DASHSCOPE_API_KEY` | L5 静态缓存的"生成"数据源（百炼 DeepSeek） | ⚠️ 仅生成时需要 | 同上 |

> 注意：`DASHSCOPE_API_KEY` **不用于 `getNewsList` 运行时**，仅用于 `refreshNews` / `llmSearch` 生成 AI 缓存。运行时 L5 读取的是已生成的静态 JSON。

## 6. 监控 / 排障要点

- 看到大量"AI 缓存命中" → 说明 L1~L4 在退化，优先查天行 / JUHE Key 与配额。
