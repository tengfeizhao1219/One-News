# B-16 新闻存储保留机制：收藏/分享新闻 30 天保留 — 技术决策方案

> **任务**：B-16 | **负责人**：技术负责人（TL）决策 → 后端开发（BE）执行云函数 → 前端开发（FE）执行前端改动
> **状态**：🔄 已认领（TL，2026-08-01）｜ 依赖：无（独立任务）
> **关联**：B-04（收藏功能）、B-05（分享功能）、`cloudfunctions/refreshNews/`、`cloudfunctions/getNewsDetail/`
> **决策参数**：保留期限 = 30 天；分享 + 收藏同套保留机制
> **最后更新**：2026-08-01

---

## 0. TL 结论（先看这里）

当前 refreshNews 每次运行 `clearOldCache(category)` → 全量删除 `news_cache` → 重写 15 条，导致**历史新闻在列表中永久消失**。收藏/分享通过 `news.id` 回查 `news` 集合，但智谱每轮生成新 id，旧文档虽未主动删除却无法被列表找到，收藏功能实质上不可靠。

**修复策略**：在 `news` 集合引入 `isRetained`（布尔）标记，收藏/分享时标记为保留，refreshNews 写入时跳过已保留文档（不覆盖），30 天后自动清理非保留旧文档。

---

## 1. 现状诊断

### 1.1 写入侧（refreshNews v4.0）

```
refreshNews() 触发
  │
  ├─ for each 分类:
  │   ├─ clearOldCache(cat)          ← 🔴 news_cache 全量删除本分类
  │   └─ batchInsert(15条)
  │       ├─ news_cache.add()        ← 写 15 条（cacheExpire = now + 65min）
  │       └─ news:                   ← 按 id 查重（exist → update / 否 → add）
  │
  └─ 下次触发 → clearOldCache → 再删再写...
```

### 1.2 两个集合的生死

| 集合 | 写入 | 删除 | 查询方 | 后果 |
|------|------|------|--------|------|
| `news_cache` | 每轮 5×15=75 条 | **每轮全量清除**（`clearOldCache` → `.remove()`） | `getNewsList`（仅读未过期） | 永远只有最新一批，历史归零 |
| `news` | 每轮按 id 查重 update/add | **不主动删除** | `getNewsDetail`（按 id 查） | 旧文档堆积但不被列表引用 |

### 1.3 收藏的致命缺陷（代码为证）

- 收藏写入（`pages/detail/detail.js:529-537`）：存 `{id, title, category, source, addedAt}` —— **不存 content**，回查依赖 `getNewsDetail`
- 收藏点击（`pages/home/home.js:700-706`）：`/pages/detail/detail?id={favItem.id}` → `getNewsDetail` 去 `news` 集合按 `id` 查
- 智谱每轮生成新 id（`zhipu_{category}_{timestamp}_{index}`），每轮都是全新文档
- **结论**：收藏存了 id，但该 id 对应的文档在 `news` 中存在（因未被删除），但**不在 `news_cache` 列表中**——用户无法从列表找到它，只能从收藏 tab 进入。而如果将来 `news` 集合被清理，收藏就打不开了。

## 2. 方案设计

### 2.1 核心机制：`isRetained` 标记保护

```
             收藏/分享 ──→ setNewsRetained(id, true)
                                  │
                                  ▼
news 集合:  { id, title, content, ..., isRetained: true, retainedAt: now }
                                  │
refreshNews 写入时 ──→ 检测 isRetained === true → 跳过，不覆盖
                                  │
30 天后 ──→ isRetained === false && createdAt < 30天前 → 自动清理
```

### 2.2 各环节行为

| 环节 | 行为 | 说明 |
|------|------|------|
| **收藏** | 调用 `setNewsRetained(id, true)` | 标记该新闻正文需保留 |
| **取消收藏** | 调用 `setNewsRetained(id, false)` | 释放标记（若无其他引用） |
| **分享** | 调用 `setNewsRetained(id, true)` | 与收藏同机制 |
| **refreshNews 写入** | `news` 已存在且 `isRetained=true` → 跳过 update | 不覆盖被引用的文档 |
| **refreshNews 清理** | `news.where({isRetained: false, createdAt < 30天前}).remove()` | 防止 news 无限膨胀 |
| **收藏列表加载** | 若对应 id 在 news 中已不存在 → 显示「已过期」 | 优雅降级，不删收藏记录 |

## 3. 实现清单

### 3.1 后端（BE）：新增 `setNewsRetained` 云函数

**文件**：`cloudfunctions/setNewsRetained/index.js`（新建，v4.1 平铺自包含风格）

```
输入：{ newsId: string, retained: boolean }
逻辑：
  1. 按 newsId 查 news 集合
  2. 存在 → 更新 isRetained + retainedAt（retained=true 时写时间戳，false 时清空）
  3. 不存在 → 返回 { code: 0, message: '文档不存在，无需操作' }
输出：{ code: 0, data: { newsId, isRetained, updated } }
```

**文件**：`cloudfunctions/setNewsRetained/package.json`

```json
{ "name": "setNewsRetained", "version": "1.0.0", "dependencies": { "wx-server-sdk": "latest" } }
```

### 3.2 后端（BE）：修改 `refreshNews/index.js`

**改动点 1** — `batchInsert()` 中 news 写入逻辑：

```js
// 现有（行 83-91）：
if (exist.data && exist.data.length > 0) {
  // 更新（保留 viewCount）
  await db.collection('news').doc(exist.data[0]._id).update({ data: doc })
} else {
  await db.collection('news').add({ data: { ...doc, viewCount: 0, createdAt: now } })
}

// 改为：
if (exist.data && exist.data.length > 0) {
  const existing = exist.data[0]
  if (existing.isRetained) {
    // 被收藏/分享引用 → 跳过，不覆盖
    console.log(`[refreshNews] 跳过保留文档: ${item.id}`)
    continue
  }
  await db.collection('news').doc(existing._id).update({ data: doc })
} else {
  await db.collection('news').add({
    data: { ...doc, viewCount: 0, isRetained: false, createdAt: now }
  })
}
```

**改动点 2** — 主函数末尾追加定期清理：

```js
// 7. 清理 30 天前的非保留文档（追加在 elapsed 计算之后、return 之前）
try {
  const cutoff = Date.now() - 30 * 24 * 60 * 60 * 1000
  const cleanRes = await db.collection('news')
    .where({
      isRetained: db.command.neq(true),
      createdAt: db.command.lt(cutoff)
    })
    .remove()
  const cleaned = cleanRes.stats?.removed || 0
  if (cleaned > 0) {
    console.log(`[refreshNews] 清理 ${cleaned} 条过期非保留文档`)
  }
  // 附加到返回体
  resultData.cleanedExpired = cleaned
} catch (err) {
  console.warn('[refreshNews] 清理过期文档失败:', err.message)
}
```

## 5. 部署注意事项

1. `setNewsRetained` 云函数需在微信云控制台**上传并部署**
2. `refreshNews` 修改后需**重新部署**（含新增的清理逻辑）
3. `news` 集合无需迁移——`isRetained` 字段缺失时查询条件 `neq(true)` 自动匹配
4. 首次部署后，已有收藏不会自动标记 `isRetained`——用户下次打开详情页时（`_checkFavorite` 命中）不会触发 setNewsRetained。**建议**：在 `_checkFavorite` 中也追加一次 `setNewsRetained(newsId, true)` 调用（幂等），实现存量收藏的渐进式标记。

## 6. 验收标准

- [ ] `setNewsRetained` 云函数可正常调用，标记/取消标记均返回 `code: 0`
- [ ] 收藏一条新闻后，`news` 集合对应文档 `isRetained === true`
- [ ] 取消收藏后，`isRetained === false`，`retainedAt` 清空
- [ ] 分享新闻后，对应文档也被标记为保留
- [ ] `refreshNews` 运行时，`isRetained === true` 的文档不被覆盖（日志出现「跳过保留文档」）
- [ ] `refreshNews` 运行时，`createdAt < 30天前` 且 `isRetained !== true` 的文档被清理（日志出现清理条数）
- [ ] 收藏列表中，若某条新闻在 `news` 中已不存在，点击时提示「已过期」而非白屏/报错
- [ ] 正常收藏的新闻（未过期）可从收藏列表点击正常打开详情页
- [ ] `news` 集合大小在持续运行中趋于稳定（不再无限增长）

## 7. 风险与边界

| 风险 | 缓解 |
|------|------|
| 30 天清理阈值首次触发时可能删大量旧文档（一次性） | 微信云 `.remove()` 单次上限 1000 条，超过需分批。建议首次手动确认 news 集合大小 |
| `setNewsRetained` 调用失败（网络/冷启动） | 前端 catch 静默失败，不阻塞收藏操作；`isRetained` 标记缺失时最坏后果是文档被清理，收藏打不开——与现状一致，不更差 |
| 分享与收藏同时引用同一文档，取消收藏释放标记 → 分享链接也失效 | 可接受的降级：分享时调用 setNewsRetained 本质是「最后一次分享时间起保 30 天」，实际使用中不太出现分享后 30 天内取消收藏且无再次分享的场景 |
| 存量收藏首次部署时未标记 | 见 §5.4：在 `_checkFavorite` 中追加幂等调用实现渐进式标记 |
