## 2. 现状核查（代码为唯一真源）

### 2.1 写入侧（refreshNews v4.0 → zhipuSearch.js）
- `searchAllCategories()` 顺序遍历 `CATEGORY_PROMPTS`（**仅 5 个**：recommend/tech/sports/international/life）。
- 每分类：智谱 GLM-4-Flash 联网搜索 → 失败则 DeepSeek 降级 → `validateAndClean` → `SecurityCheck` → `batchInsert` 双写 `news_cache`+`news`。
- `config.cache.dbCacheTTL = 65min`，覆盖每小时刷新间隔。

### 2.2 读取侧（getNewsList v4.2）
- **只**从 `news_cache` 读，空了就诚实返回空列表（无降级、无兜底）。
- `meta: { source: 'news_cache', engine: 'zhipu/deepseek' }`。

### 2.3 🔴 分类覆盖缺口（本次核查新发现）
| 层 | 分类 | 有 LLM 数据？ |
|----|------|:---:|
| UI 侧边栏（`utils/constants.js`） | recommend / tech / international / sports / life / **agriculture / science** | 7 个 |
| LLM 生成（`zhipuSearch.CATEGORY_PROMPTS`） | recommend / tech / sports / international / life | **仅 5 个** |
| **结论** | **农业（agriculture）、科学（science）无 prompt → refreshNews 永不生成 → getNewsList 永久返回空** |

> 简报称「聚合生成 7 大分类新闻」，但代码实际仅生成 5 类。农业/科学是 UI 已暴露却无供给的「死分类」，属真实功能缺口，必须在 B-09 重建范围内解决。

### 2.4 config.js / config.json 文档债（非阻塞，记录待清）
- 两个 `config.js` 顶部注释仍写「news_cache→天行→聚合→内存→AI兜底」旧 v4.0 链，与 v4.2 代码不符。
- `refreshNews/config.json` 定时器仍为 `0 0 6/11/20`（**每天 3 次**），与 ADR-002「每小时 `0 * * * *`」要求不符（见 B-12 配额测算影响 + DEP-01 核对项）。

## 3. 技术决策（TL 拍板）

### 决策 A：数据源切换 — 确认闭环，不再改代码
- news_cache 的唯一 feeder = 智谱/DeepSeek（refreshNews）。天行/聚合/百炼在 v4.2 中已移除，不恢复。
- **BE 无需为「切换」写任何代码**。

### 决策 B：重建机制 — 以 refreshNews 为主，TTL 65min 兜底
- 周期重建：`refreshNews` 定时触发（频率见 DEP-01 核对，目标每小时）。
- 即时重建：用户手动刷新按钮触发 `refreshNews`。
- 数据新鲜度：写入 `cacheExpire = now + 65min`；getNewsList 仅读未过期条目。
- **重建动作本身属 DEP-01（云函数部署 + 首次手动触发灌入）**，不在此任务重复。

### 决策 C：分类覆盖缺口 — 补齐 agriculture / science 两个 prompt 🔴
- **TL 决策**：在 `zhipuSearch.CATEGORY_PROMPTS` 中**新增农业、科学两个分类 prompt**（结构与现有 5 个一致，配可信新闻源域名）。
- 理由：UI 已暴露这 2 个分类，用户预期有内容；补齐成本极低（纯 prompt 文本），且让「7 大分类」名副其实。
- 风险：智谱免费档对新增 2 类的调用量略有增加（每日 +2~4 次/运行），B-12 限流策略已覆盖。

### 决策 D：聚合独立分类 tab（体育/生活）— 抛给产品决策 🟡
- **TL 建议：不引入聚合**。v4.2 已刻意移除以简化架构、去除额外 Key 依赖；智谱/DeepSeek 已覆盖全部 7 类，无必要 reintroduce 聚合。
- 若产品坚持要聚合作为某分类的专属/兜底源，则需：① 新增 `JUHE_API_KEY` 环境变量；② BE 在 `zhipuSearch` 为指定分类增加聚合 fallback 分支；③ 重新评估 B-12 配额（聚合 100 次/日免费）。
- **此决策点阻塞 B-09 的「聚合」分支，但决策 C（补 2 prompt）不依赖它，可先行。**
