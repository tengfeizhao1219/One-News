## RQ-01 跨分类衔接 — 方案定夺

### 结论：采用方案 A（全分类预合并列表）

| 维度 | 方案 A（预合并） | 方案 B（按需拉取） | 判定 |
|------|:---:|:---:|:---:|
| 阅读连贯性 | 无缝 | 分类边界短暂 loading | A 胜 |
| 内存占用 | 5 分类 × 默认 pageSize 条索引 ≈ 50 条对象引用（KB 级） | 仅当前分类 | A 可接受 |
| 首屏耗时 | 多一次 getNewsList 批量（可并行预取） | 不需预拉 | A 可控 |
| 网络开销 | 首屏多拉 4 个分类首页（可合并为一次串行/并行调用） | 省流量 | B 略胜但差距小 |
| 实现复杂度 | 修改 `detailContext` 构建逻辑 + 合并列表 | 需懒加载 + 状态机 | 相近 |

**参数确认**：
- 预取策略：`detailContext.list = 各分类首 pageSize 条合并`（默认 10 条/分类，共 ≈ 50 项索引，< 5KB）
- 读到底后若 `hasMore=true`，追加调用 `getNewsList(cat, page+1)` 扩展列表
- 合并顺序按 `constants.js` 的 CATEGORIES 定义顺序（top → tech → finance → sports → life）

**WXS 红线**：跨分类手势层复用现有手势，纯 ES5，`detail.js` 中处理分类边界；WXS 不感知分类上下文（满足红线 #1 #2）。

## RQ-10 内容安全 API 接入

### 结论：refreshNews 入库前串行接入 `msgSecCheck`，保守策略兜底

**架构位置**：`refreshNews/index.js` 中 `validateAndClean` 之后、`batchInsert` 之前新增 `securityCheck` 步骤。

**实现方案**：
```
refreshNews 流程（新增步骤标 ★）
  LLM 搜索 → validator(质量/来源) → ★ securityCheck(违规) → batchInsert
                                              │
                                         命中违规 → 拦截 + 记 sync_logs + 告警
                                         API不可用 → 该批暂缓 + 告警 + 队列重试（不绕过）
```

**技术选型**：
| 项 | 决策 |
|-----|------|
| 调用方式 | 云函数内 `cloud.openapi.security.msgSecCheck({ content })`（微信云开发原生集成，免 access_token 管理） |
| 图片审核 | 新闻图片 URL 先 `cloud.downloadFile` → `imgSecCheck`；优先 `picUrl`，无图则跳过 |
| 批量限频 | refreshNews 单次最多 ~50 条，按 10 QPS 串行调用安全 API（≤ 5s），超时降级为保守策略 |
| 日志 | `sync_logs` 集合新增 `securityCheck` 字段：`{ passed, hitType, hitReason, checkedAt }` |
| 告警 | 单次刷新命中率 > 20% 或 API 连续 3 次不可用 → 云函数日志 ERROR 级 |
| 兜底 | validator 为第一道低成本防线（不变）；安全 API 为第二道强约束 |

**与 validator 分工**：`validator` 管字段完整性/来源白名单/垃圾词/URL 占位符；`securityCheck` 管政治敏感/色情/暴力/违法。两者互补，不合并。

**风险**：QPS 超出微信配额时保守策略导致 news_cache 空窗，L3 云库缓存过期后 L4/L5 接住（符合降级策略）。

## RQ-03 收藏存储方案

### 结论：本地优先，预留云端同步扩展

| 项 | 决策 |
|-----|------|
| 本期方案 | `wx.setStorageSync('favorites', [{id, title, category, categoryName, addedAt}])` |
| 容量上限 | 500 条（LRU 淘汰） |
| 排序 | `addedAt` 倒序（最近收藏在前） |
| 按钮态 | `detail.js` 中维护 `isFavorited` 状态，进入详情时查本地存储判定 |
| 入口 | 侧边栏新增"我的收藏" tab（不建独立页面，符合 PRD §5.4 范围控制） |
| 云端预留 | 数据结构保留 `openid` 字段（本期 null），`sync_logs` 扩展 `favoriteLog`；下迭代加云函数 `syncFavorites` |

**与 RQ-06 阅读历史共享存储**：可共用 `localStorage` 封装但数据结构独立（favorites vs history），避免耦合。PRD §5.7 建议合并规划——同意"共享存储层"，分两个 key：`favorites` / `readHistory`。
