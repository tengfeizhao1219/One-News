## 二、技术评审议题（T-01 主导）

### T-01-1：RQ-01 跨分类衔接 — 方案 A vs B 定夺

| 方案 | 做法 | 取舍 |
|------|------|------|
| A（推荐） | 进入详情时，`globalData.detailContext` 扩展为全分类合并有序列表，翻页在同一列表上移动 | 体验连贯；首屏需预拉多分类，注意流量/性能 |
| B | 到达末尾时按需 `getNewsList(nextCategory)` 拉下一分类首条 | 流量省；衔接处短暂加载，体验略断 |

**待确认**：
- 方案选型及理由（性能/流量/体验 trade-off）
- 预拉条数 N 的取值策略
- 是否需要 WXS 手势层感知分类边界（纯 ES5 限制）

### T-01-2：RQ-10 内容安全 API 接入

- 微信 `msgSecCheck` / `imgSecCheck` 调用方式（云函数中 `cloud.callContainer` vs 服务端直调）
- QPS / 配额评估：refreshNews 批量入库时的限频策略
- 异步队列设计：失败重试 + 保守策略（API 不可用时暂缓入库并告警，不绕过）
- 日志与告警落点（`sync_logs` 结构扩展 + 运维通道）
- 与现有 `validator.js` 的分工边界（validator 管质量/来源，内容安全 API 管违规）

### T-01-3：RQ-03 收藏存储方案

- 本地优先 `wx.setStorageSync` 方案确认
- 后续云端 openid 同步的数据结构预留
- 收藏列表排序规则与容量上限
- 与 RQ-06 阅读历史共享存储层的可行性

### T-01-4：其他技术关注点

- RQ-04 字体：`--font-scale` CSS 变量与 `theme.json` 现有颜色变量的兼容性
- RQ-07 分享：`onShareAppMessage` 封面图生成（picUrl 优先 → 分类占位色兜底）
- RQ-05/RQ-06（P2）：本地缓存封装 `localCache` 的统一设计概要

## 三、交互评审议题（D-02 主导）

### D-02-1：跨分类衔接交互细节

- 进度指示升级：从「3 / 20」→「3 / 20 · 科技」（显示当前分类名）
- 跨分类衔接动画：复用现有 `out-up/in-up`，是否需要区分"同分类翻页"与"跨分类切换"的动效
- 边界提示：「已经是最后一条」的展示样式与消失时机
- 网络不可用时的兜底：「网络开小差，下拉重试」而非空白

### D-02-2：字体设置入口与交互

- 设置入口位置：建议复用左滑面板增加「设置」区（或首页/详情页浮层）
- 档位切换即时生效，无白屏/闪烁
- 首入跟随系统字体的判断逻辑

### D-02-3：收藏 / 分享按钮布局

- 详情页底部操作栏新增「🤍 收藏」+「↗️ 分享」
- 收藏按钮态切换（空心→实心）的动效
- 收藏列表入口：侧边栏新增「我的收藏」tab（不新建独立页面）

## 四、视觉评审议题（D-03 主导）

### D-03-1：全局字号系统

- 新增 `--font-scale` CSS 变量（标准 / 大 / 特大 / 超大 4 档）
- 首页卡片、详情正文、侧边栏列表统一引用
- 超大字号下标题/摘要换行与卡片布局保护（截断 + 行高）
- 与暗色模式的共存兼容

### D-03-2：收藏 / 分享按钮样式

- 按钮 icon 风格（线性/面性）与现有操作栏一致
- 已收藏态（❤️ 实心）vs 未收藏（🤍 空心）视觉区分
- 分享按钮与微信原生转发卡片样式的一致性

### D-03-3：分享卡片兜底

- 无图新闻的分享卡片兜底视觉（分类主题色占位图）
- 分享语截断保护（标题 + 一句摘要 ≤ 推荐字数）

## 五、测试评审议题（测试工程师主导）

### 测试策略预审

- 跨分类边界场景：末条上滑→下一分类首条 / 全部分类末条→边界提示 / 网络不可用→兜底
- 合规拦截场景：命中内容安全 API→不入库 + 日志 / API 不可用→保守暂缓 + 告警
- 弱网/离线场景：收藏可读 / 缓存可读 / 恢复后静默补充
- 字体兼容性：4 档字号 × 暗色模式 × 不同机型（iOS/Android）
- 回归范围：基于现有 178 用例基线的增量用例设计
