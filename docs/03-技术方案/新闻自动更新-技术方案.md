# 新闻自动更新 — 技术方案

> 版本：v1.0  
> 日期：2026-07-28  
> 状态：待评审

---

## 1. 概述

### 1.1 背景

当前新闻数据流：

```
WorkBuddy 搜索新闻 → mock/ai-news-cache.js (静态 JSON)
    → scripts/build-ai-cache.js → cloudfunctions/common/aiNewsData.js
    → 随代码部署到 CloudBase
```

**痛点：**
- 每次更新新闻内容需要修改代码 + 重新部署云函数
- 新闻时效性依赖人工触发，无法自动更新
- 静态缓存与云数据库缓存层级关系模糊（当前 DB 缓存为外部 API 的缓存，非 AI 新闻缓存）

### 1.2 目标

实现新闻内容自动更新，无需重新部署代码。核心思路是将 AI 新闻数据从"编译期内联"升级为"运行时从 GitHub 拉取 + 云数据库持久化"。

### 1.3 核心架构

```
┌─────────────────────────────────────────────────────────────────────┐
│                        WorkBuddy 搜索新闻                            │
│                   生成 data/news.json 推送 GitHub                      │
└────────────────────────────────┬────────────────────────────────────┘
                                 │
                                 ▼
┌─────────────────────────────────────────────────────────────────────┐
│                   GitHub raw URL (data/news.json)                    │
│         https://raw.githubusercontent.com/{owner}/{repo}/main/...    │
└────────────────────────────────┬────────────────────────────────────┘
                                 │
                                 ▼  fetch (Node.js https)
┌─────────────────────────────────────────────────────────────────────┐
│                CloudBase 定时触发器 (每天 8:00 北京时间)                │
│                          │                                          │

│              ┌──────┴──────┐                                        │
```

## 2. 架构设计

### 2.1 数据流 — getNewsList

```
请求进入
    │
    ▼
┌─────────────┐    命中     ┌──────────┐
│ 内存缓存     │ ──────────→ │ 直接返回  │
│ (5 min TTL) │             └──────────┘
└──────┬──────┘
       │ 未命中
       ▼
┌─────────────────┐    命中     ┌──────────┐
│ 云数据库缓存     │ ──────────→ │ 直接返回  │  ← ★ 提升到此层级
│ (24h cacheExpire)│             └──────────┘
└──────┬──────────┘
       │ 未命中
       ▼
┌─────────────────┐    命中     ┌──────────┐
│ AI 静态缓存     │ ──────────→ │ 直接返回  │  ← 降级兜底
│ (aiNewsData.js) │             └──────────┘
└──────┬──────────┘
       │ 未命中
       ▼
┌─────────────────┐
│ 外部 API        │  ← 最后降级
│ (天行/聚合)      │
└─────────────────┘
```

**变更说明：**
- **当前层级：** 内存缓存 → AI静态缓存 → 云数据库缓存 → 外部API
- **调整后层级：** 内存缓存 → **云数据库缓存（提升）** → AI静态缓存（降级） → 外部API
- **理由：** 云数据库的数据由 refreshNews 定时刷新，时效性优于部署期生成的静态缓存

### 2.2 数据流 — searchNews

```
请求进入
    │
    ▼
┌─────────────┐    命中     ┌──────────┐
│ 内存缓存     │ ──────────→ │ 直接返回  │
│ (10 min TTL) │             └──────────┘
└──────┬──────┘
       │ 未命中
       ▼
┌──────────────────────┐    命中     ┌──────────┐
│ 云数据库全量拉取+过滤 │ ──────────→ │ 直接返回  │  ← ★ 新增层级
│ (全量读取 → 内存过滤) │             └──────────┘
└──────┬───────────────┘
       │ 无数据/无匹配
       ▼
┌─────────────────┐    命中     ┌──────────┐
│ AI 静态缓存搜索 │ ──────────→ │ 直接返回  │
└──────┬──────────┘             └──────────┘
       │ 无匹配
       ▼
┌─────────────────┐
│ 外部 API 搜索   │
│ (天行数据)       │
└─────────────────┘
```

**实现细节：** searchNews 从云数据库执行全量读取（不加 where 条件），然后在内存中用关键词过滤标题和摘要，再进行分页截取。原因：CloudBase 云数据库不支持全文检索，只能客户端过滤。

### 2.3 降级策略总览

| 场景 | 行为 | 影响 |
|------|------|------|
| GitHub 不可用 | refreshNews 返回错误码，不写入 DB | 保留旧缓存数据 |
| 云数据库无数据 | getNewsList 降级到 AI 静态缓存 | 兜底数据可用 |
| AI 静态缓存也无数据 | 降级到外部 API | 实时但有费用 |
| 全部数据源不可用 | 返回 ALL_DOWN 错误码 | 用户看到错误提示 |
| refreshNews 写入失败 | 不清除旧数据，保留上一版本 | 数据不丢失 |

## 3. 核心模块设计

### 3.1 refreshNews 云函数

**文件路径：** `cloudfunctions/refreshNews/index.js`

**伪代码流程：**

```
main()
  │
  ├─ 1. 从 GitHub raw URL 拉取 news.json
  │     URL: https://raw.githubusercontent.com/{owner}/{repo}/main/data/news.json
  │     使用 Node.js https 模块
  │
  ├─ 2. 校验 HTTP 状态码
  │     200 → 继续
  │     非200 → 返回错误，不清除旧数据
  │
  ├─ 3. 解析 JSON，校验数据结构
  │     校验: Array.isArray && length > 0
  │     校验: 每条包含 id, title, category
  │     失败 → 返回错误
  │
  ├─ 4. 清除旧缓存（按分类批量删除过期数据）
  │     db.collection('news_cache')
  │       .where({ cacheExpire: db.command.lte(now) })
  │       .remove()
  │
  ├─ 5. 逐条写入新数据
  │     for each item:
  │       db.collection('news_cache').add({
  │         data: {
  │           ...item,
  │           cacheExpire: now + 24 * 60 * 60 * 1000,  // 24小时后过期
  │           createdAt: now,
  │         }
  │       })
  │
  └─ 6. 返回结果
        { code: 0, count: N, updatedAt: ISO timestamp }
```

**错误处理：**

| 错误类型 | 处理方式 | 返回码 |
|----------|----------|--------|
| GitHub 连接超时 (10s) | 不写入，返回错误 | GITHUB_TIMEOUT |
| GitHub 返回非 200 | 不写入，返回错误 | GITHUB_ERROR |
| JSON 解析失败 | 不写入，返回错误 | JSON_PARSE_ERROR |
| 数据校验失败 | 不写入，返回错误 | DATA_VALIDATION_ERROR |
| 单条写入失败 | 跳过该条，继续写入 | (日志警告) |
| 全部写入失败 | 返回错误 | DB_WRITE_ERROR |

**关键设计决策：**
- 先校验 JSON 再清除旧数据 → 防止 GitHub 异常时清空有效缓存
- 逐条写入而非批量 → CloudBase 小程序 SDK 不支持批量 add，逐条写入更可控
- cacheExpire 设为 24 小时 → 即使定时器故障，数据也不会永久保留过期内容

### 3.3 getNewsList 数据流调整

**当前代码（`getNewsList/index.js`）：**
```
内存缓存 → AI静态缓存 → 云数据库缓存 → 外部API
```

**调整后代码：**
```
内存缓存 → 云数据库缓存(提升) → AI静态缓存(降级) → 外部API
```

**具体修改（伪代码）：**

```js
// 第 1 层：内存缓存（不变）
const memoryCached = cache.get(memoryKey)
if (memoryCached) return ...

// 第 2 层：云数据库缓存（★ 从第3层提升到第2层）
const dbCached = await getFromDbCache(category, pageNum, pageSize)
if (dbCached && dbCached.list.length > 0) {
  cache.set(memoryKey, dbCached, { ttl: config.cache.memoryTTL })
  return { code: 0, data: dbCached, meta: { source: 'db_cache' } }
}

// 第 3 层：AI 静态缓存（★ 降级兜底）
const aiResult = aiNews.getByCategory(category, pageNum, pageSize)
if (aiResult.list.length > 0) {
  cache.set(memoryKey, responseData, { ttl: config.cache.memoryTTL })
  return { code: 0, data: responseData, meta: { source: 'ai_cache' } }
}

// 第 4 层：外部 API（不变）
```

**同步调整：** 当外部 API 返回数据时，`saveToDbCache()` 的 `cacheExpire` 应从 15 分钟改为 24 小时，避免与 refreshNews 写入的数据产生冲突。

### 3.4 searchNews 数据流调整

**新增：云数据库全量搜索层**

```js
// 第 2 层：云数据库全量拉取 + 内存过滤（★ 新增）
async function searchInDbCache(keyword, pageNum, pageSize) {
  try {
    const now = Date.now()
    const MAX_LIMIT = 100  // CloudBase 单次查询上限
    const res = await db.collection('news_cache')
      .where({ cacheExpire: db.command.gt(now) })
      .limit(MAX_LIMIT)
      .get()

    if (!res.data || res.data.length === 0) return null

    // 内存过滤
    const kw = keyword.toLowerCase()
    const filtered = res.data.filter(item =>
      (item.title || '').toLowerCase().includes(kw) ||
      (item.summary || '').toLowerCase().includes(kw)
    )

    if (filtered.length === 0) return null

    const total = filtered.length
    const start = (pageNum - 1) * pageSize
    const pagedList = filtered.slice(start, start + pageSize)

    return { list: pagedList, total }
  } catch (err) {
    console.warn('[searchNews] 云数据库搜索失败:', err.message)
    return null
  }
}
```

**注意：** CloudBase 云数据库 `limit` 上限为 100，当前新闻总量约 40 条，在安全范围内。若未来新闻量超过 100 条，需要使用游标分页多次读取。

## 4. 数据模型

### 4.1 news_cache 集合

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `_id` | string | 自动 | CloudBase 自动生成 |
| `id` | string | 是 | 新闻唯一标识，如 `ai_tech_001` |
| `title` | string | 是 | 新闻标题 |
| `summary` | string | 是 | 新闻摘要 |
| `category` | string | 是 | 分类 ID: recommend / tech / sports / international / life |
| `categoryName` | string | 是 | 分类中文名: 推荐 / 科技 / 体育 / 国际 / 生活 |
| `source` | string | 是 | 来源，如 "CSDN" |
| `publishTime` | string | 是 | 发布时间，ISO 8601 格式 |
| `cacheExpire` | number | 是 | 过期时间戳（毫秒），24 小时后过期 |
| `createdAt` | number | 是 | 写入时间戳（毫秒） |

### 4.2 news.json 格式（GitHub 源文件）

```json
[
  {
    "id": "ai_tech_001",
    "title": "WAIC 2026世界人工智能大会闭幕",
    "summary": "2026世界人工智能大会（WAIC）于7月22日圆满闭幕...",
    "category": "tech",
    "categoryName": "科技",
    "source": "CSDN",
    "publishTime": "2026-07-22T16:00:00Z"
  }
]
```

与 `ai-news-cache.js` 格式完全一致，确保 `scripts/build-ai-cache.js` 可直接生成。

### 4.3 索引设计

在 CloudBase 控制台为 `news_cache` 集合创建以下索引：

| 索引字段 | 类型 | 说明 |
|----------|------|------|
| `category` + `cacheExpire` | 复合索引 | getNewsList 按分类查询时使用 |
| `cacheExpire` | 单字段索引 | refreshNews 清除过期数据时使用 |
| `publishTime` | 降序索引 | 排序使用 |

## 5. 性能评估

### 5.1 refreshNews 云函数

| 步骤 | 预计耗时 | 说明 |
|------|----------|------|
| GitHub raw URL 拉取 | ~500ms | 小文件，CDN 加速 |
| JSON 解析 + 校验 | ~10ms | 40 条数据 |
| 清除旧缓存 | ~500ms | 按过期时间批量删除 |
| 逐条写入 (40 条) | ~3000ms | 每条 ~75ms |
| **总计** | **~4s** | 目标 < 5s |

**优化方向：** 如果新闻量增长到 100+ 条，可考虑分批并行写入（每批 10 条并发）。

| **典型耗时** | **~150ms** | 云数据库命中场景 |

### 5.3 searchNews 云函数

## 9. 附录

### A. refreshNews 云函数完整示例代码

```js
// cloudfunctions/refreshNews/index.js
const cloud = require('wx-server-sdk')
const https = require('https')

cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })
const db = cloud.database()

const GITHUB_URL = 'https://raw.githubusercontent.com/{owner}/{repo}/main/data/news.json'
const CACHE_TTL = 24 * 60 * 60 * 1000  // 24 小时

function fetchJson(url) {
  return new Promise((resolve, reject) => {
    const req = https.get(url, { timeout: 10000 }, (res) => {
      if (res.statusCode !== 200) {
        reject(new Error(`HTTP ${res.statusCode}`))
        return
      }
      let data = ''
      res.on('data', chunk => data += chunk)
      res.on('end', () => {
        try {
          resolve(JSON.parse(data))
        } catch (e) {
          reject(new Error('JSON parse failed'))
        }
      })
    })
    req.on('error', reject)
    req.on('timeout', () => { req.destroy(); reject(new Error('Timeout')) })
  })
}

function validateNewsData(data) {
  if (!Array.isArray(data) || data.length === 0) return false
  return data.every(item =>
    item.id && item.title && item.category
  )
}

async function clearExpiredCache() {
  const now = Date.now()
  try {
    await db.collection('news_cache')
      .where({ cacheExpire: db.command.lte(now) })
      .remove()
  } catch (e) {
    console.warn('[refreshNews] 清除过期缓存失败:', e.message)
  }
}

async function writeNewsToDb(newsList) {
  const now = Date.now()
  const expireAt = now + CACHE_TTL
  let successCount = 0

  for (const item of newsList) {
    try {
      await db.collection('news_cache').add({
        data: {
          ...item,
          cacheExpire: expireAt,
          createdAt: now,
        }
      })
      successCount++
    } catch (e) {
      console.warn(`[refreshNews] 写入失败 [${item.id}]:`, e.message)
    }
  }

  return successCount
}

exports.main = async (event, context) => {
  console.log('[refreshNews] 开始刷新新闻缓存...')

  try {
    // 1. 拉取数据
    const newsData = await fetchJson(GITHUB_URL)
    console.log(`[refreshNews] 拉取成功，共 ${newsData.length} 条`)

    // 2. 校验
    if (!validateNewsData(newsData)) {
      return { code: -1, errorCode: 'DATA_VALIDATION_ERROR', message: '数据格式校验失败' }
    }

    // 3. 清除旧缓存
    await clearExpiredCache()

    // 4. 写入新数据
    const count = await writeNewsToDb(newsData)
    console.log(`[refreshNews] 写入完成，成功 ${count}/${newsData.length} 条`)

    return {
      code: 0,
      count,
      total: newsData.length,
      updatedAt: new Date().toISOString(),
    }

  } catch (err) {
    console.error('[refreshNews] 刷新失败:', err.message)

    const errorCode = {
      'Timeout': 'GITHUB_TIMEOUT',
      'HTTP': 'GITHUB_ERROR',
      'JSON parse failed': 'JSON_PARSE_ERROR',
    }[Object.keys({Timeout:1,'HTTP':1,'JSON parse failed':1}).find(k => err.message.includes(k))] || 'UNKNOWN_ERROR'

    return {
      code: -1,
      errorCode,
      message: `新闻刷新失败: ${err.message}`,
    }
  }
}
```
