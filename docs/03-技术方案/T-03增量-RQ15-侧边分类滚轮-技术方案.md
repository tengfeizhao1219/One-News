## 2. 关键技术决策评估

### 2.1 scroll-snap 可行性（TL 核心裁定）

**评估对象**：规范 §8 要求技术负责人评估 `scroll-snap-type: y mandatory`（基础库 3.0.0+）可行性。

**结论：不采用 CSS scroll-snap，沿用 JS `translateY` 方案。**理由：

1. **语义不匹配**：规范 v2 起采用「**顶部锚定范式**」——选中项固定于容器第二行，其他分类围绕其滚动。这是「列表位移 + 固定锚点」模型（`translateY = -(idx-1)×itemHeight`），并非滚动容器的 snap 对齐语义（scroll-snap 对齐的是滚动视口与子项，无法表达「锚点恒在第二行且上方保留前一项」）。
2. **实现形态不兼容**：当前组件用 `view` + `transform` 实现列表位移，不是 `scroll-view` 滚动容器；引入 scroll-snap 需重构为 scroll-view + 逐项占位，且 `home.json` 已 `disableScroll:true`（页面级禁滚），scroll-view 内部滚动与页面手势存在叠加复杂度。
3. **兼容性风险**：微信 WebView 对 scroll-snap 的支持依赖基础库版本与 iOS/Android 内核差异（已知 iOS WKWebView 旧版 mandatory 行为不稳），上线前需真机矩阵回归（BLK-09 现状下无法闭环）。
4. **现有方案已达标**：JS transform 方案已落地并通过 BUG-PD-017 修复验收（8 项逐条落地、PD 二次验收），动画走合成层（`will-change: transform`），`setData` 已去重，性能与体验均有实据。

**备选（若未来需要真实惯性滚动）**：`scroll-view` + `scroll-into-view` 锚定 + `scroll-with-animation`，但需重写组件核心，仅当 owner 明确要求惯性滚动时启动。

### 2.2 手势隔离（红线：WXS 纯 ES5 / 禁 return false）

**现状**：滚轮位于侧边栏面板内；面板打开时 `card-stage` 被 `display:none`（BUG-PD-019 注释确认），卡片流 WXS 手势不响应 → **滚轮手势与卡片手势天然互斥，无冲突**。组件 touch 事件（`bindtouchstart/move/end/cancel`）在组件根 view 绑定，未向页面冒泡消费，不触碰卡片 WXS。

**方案（本组件不需要 WXS）**：滚轮手势全部用 JS 事件处理（`category-wheel.js`），无 WXS 文件 → 不涉及 ES5 红线。若未来滚轮改为**独立右侧驻留浮层**（与卡片流并存），须：
- 滚轮 touch 事件改 `catchtouchmove`（组件内消费，阻止冒泡到卡片 WXS）；
- 禁止在 touch 回调中 `return false`（红线 SOP v1.6 §15.4）；
- 真机校验：滚轮拖动不触发卡片翻动、卡片拖动不触发滚轮切换（规范 §6）。

### 2.3 惯性 / bounce

| 项 | 规范要求 | 当前实现 | 判定 |
|----|---------|---------|------|
| 惯性 | 快速滑动惯性最多跨 3 类后减速停止（AC-05） | **无动量惯性**：`deltaIndex` 由手指实时位移映射，无 velocity 累积，松手即停 | ✅ 以「无惯性」满足（无"一滑到底"风险，行为更可预期） |
| 边界 | 首/末类继续滑 → 轻微 bounce 弹跳，不切换（AC-06） | `idx` clamp 至 `[0, len-1]`，无弹跳动画 | ⚠️ 差距项，见 §4 FE 待办 |

> 若 owner 坚持要惯性滑动，最小改动路径：`onTouchEnd` 内基于最近 3 个采样点计算速度 → 附加 `deltaIndex` 动量（上限 3）→ `_updateTranslate` 加过渡动画。改动面小，但需真机验证手感。

### 2.4 震动反馈

- 现状：`onTouchMove` 中索引变化即 `wx.vibrateShort({type:'light'})`（`_lastVibrateIndex` 去重）。
- 规范：每次 `snap`（touchend）触发一次。
- **TL 意见**：现状为「滑动中逐档震动」，反馈更即时、符合滚轮逐档切换的直觉；规范「每 snap 一次」在实时切换模式下反而信息量少。**建议保持现状**，由 PD/owner 确认后回写规范（交互口径变更需 PD 批准）。

### 2.5 性能

- 渲染：`transform: translateY` 仅合成层移动，不触发布局重排；`will-change: transform` 已声明。
- 数据：仅索引变化时 `setData`（去重）；`touching` 状态切换一次。每帧最多 1 次 setData，频率受手指移动速率约束，无风险。
- 可选优化（非必需）：引入 WXS 手势响应（`touch.wxs`）将 deltaY→index 计算移入渲染线程，减少 setData 次数；但引入即受 ES5 红线约束，且当前性能已达标，**不建议本期做**。

### 2.6 暗色适配

- 组件已用 `@media (prefers-color-scheme: dark)` + `var(--highlight-bg)`（`theme.json` 已定义 light `.06` / dark `.10`，BUG-TL17-016 闭环后落地）。
- 依赖 RQ-15-UI（视觉设计师）按规范 §5 Token 表输出完整暗色 token（`--wheel-text-idle` 等），FE 对照 token 表收尾。

## 3. 组件架构与数据流

```
home.wxml:130
  <category-wheel categories="{{panelCategories}}" activeId="{{panelCategory}}" bind:change="onWheelChange"/>
        │ 属性（受控组件：分类列表 + 当前选中）
        ▼
category-wheel.js
  observers['categories, activeId'] → 校正 _activeIndex → _updateTranslate（顶部第二行锚定）
  onTouchStart/Move/End（组件内消费）
    ├─ touchmove：deltaIndex=round(deltaY/itemHeight) → idx clamp → 变化才 setData+triggerEvent('change',{category,index})
    ├─ 震动：索引变化即 vibrateShort('light')
    └─ touchend：touching=false → 300ms transform 过渡回弹（snap）
        │ triggerEvent('change')
        ▼
home.js onWheelChange(e)
  ├─ 分类提示 _showCategoryHint（BUG-20260802-006，600ms+120ms 淡入淡出）
  ├─ 面板 subtitle 更新
  ├─ 同源（==currentCategory）→ _syncPanelList(newsList)（BUG-PD-019 显式传参）
  └─ 异源 → loadCategory(cat)（切换唯一数据源）
```

- **受控组件**：选中态由页面 `activeId` 驱动（observers 校正），组件内手势仅上报 `change`，不自行改状态 → 单向数据流，页面 `loadNews`/`onCategoryChange` 核心逻辑零侵入（PRD §7 约束 ✅）。
- **事件契约**：`triggerEvent('change', { category, index })`，页面按 `detail.category` 分发。
