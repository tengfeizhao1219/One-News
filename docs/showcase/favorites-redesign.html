1
无缩略图：纯文字行，与首页有图的卡片视觉语言割裂，扫读效率低。
2
无分类标签：看不出条目属于哪个频道，无法快速归类回顾。
3
无删除/管理入口：只能从详情页加收藏，想取消收藏无处下手（反直觉）。
4
无收藏总数统计：用户不清楚自己攒了多少条，缺少「量化成就感」。
5
无分类筛选：收藏多了只能滚动硬找，无快捷过滤。
3 · 落地规格（FS 照此实现）
维度现状优化后
列表项标题 + 来源·时间两行标题(2行截断) + 分类标签 + 来源·时间（无缩略图）
分类色标识不展示缩略图；分类用 --flash-* 文字色做视觉区分（owner 决策：列表去缩略图）
收藏计数无nav 右侧「共 N 条」；随筛选联动（全部=N / 某类=该类数）
分类筛选无nav 下横滑胶囊（全部+各分类），纯前端 filter，不改数据结构
删除交互无入口长按列表项 → ActionSheet「取消收藏 / 取消」（微信习惯，零破坏）
取消收藏写入本地 localCache.favorites 立即移除 + 云端 setUserFavorite(false) 双写；列表即时重渲染
空态「还没有收藏任何新闻」保留 + 引导「收藏后这里会按分类整理」；筛选无结果变体「该分类下暂无收藏」
前置依赖确认 localCache.favorites 字段完整性（标题/分类/来源/时间）；不依赖 thumbUrl
token 来源全部色值取自 theme.json，分类标识用 --flash-* 文字色，零新增
交互边界：① 筛选只改视图、不动底层 list 数组；② 取消收藏走异步双写，列表乐观更新（先移除再回滚失败）；③ 缩略图缺失一律色块兜底。
验收点：卡片与首页四要素一致 · 计数实时准确且随筛选联动 · 长按删除有二次确认 · 空态/筛选空态文案区分 · 暗色模式全部 token 生效。
