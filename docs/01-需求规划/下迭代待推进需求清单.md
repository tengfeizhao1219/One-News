### 🟡 P2 · RQ-05 离线/弱网缓存阅读

| 维度 | 内容 |
|------|------|
| **痛点** | 地铁隧道断网，已加载内容不可读 |
| **方案** | `wx.setStorageSync` 缓存 getNewsList 结果与详情；弱网读缓存，恢复后静默补充 |
| **核心 EARS** | WHILE 网络不可用 THE SYSTEM SHALL 展示已缓存列表；WHEN 恢复 THEN 静默补充 |
| **依赖** | 与 B-06 `localCache.js` 共享存储层；技术负责人评估 Storage 容量上限（10MB 限制） |
| **工时估算** | 前端 2-3d + 后端 1d（缓存策略） |
| **PRD** | ❌ 待产品经理撰写 |

### 🟡 P2 · RQ-06 阅读历史

## 四、建议排期方案

### 方案 A：快速迭代（推荐）

```
下迭代 = RQ-15（滚轮） + RQ-08（console清理） + RQ-09（SOP）
```

- **理由**：RQ-15 是用户直接反馈的交互痛点，PRD 已就绪，工时可控（~4d）。两个技术债顺手清掉。
- **风险**：低。无后端依赖，纯前端 + 文档。

### 方案 B：中等迭代

```
下迭代 = RQ-15（滚轮） + RQ-05（离线缓存） + RQ-06（阅读历史）
```

- **理由**：RQ-05/06 共享存储层，合并开发效率高。用户体验提升明显（弱网可读 + 不重复看）。
- **风险**：中。Storage 10MB 容量限制需评估；localCache 封装涉及前后端协同。

### 方案 C：全量

```
下迭代 = RQ-15 + RQ-05 + RQ-06 + RQ-08 + RQ-09
```

- **风险**：高。工期可能超过一个迭代周期，建议拆为两个迭代。
