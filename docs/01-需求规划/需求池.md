## 一、说明

本需求池是「一页」阶段一需求规划的**唯一需求来源**。它整合了：

- **已落地需求基线**：历史上已完成开发、已在 `main` 上线的功能（作为产品当前能力边界，不重复建设）；
- **候选需求（Backlog）**：待规划 / 待开发 / 待决策的新功能、体验优化、技术债与合规项；
- **待确认问题**：需用户或项目经理拍板后才能推进的阻塞点。

> 需求描述遵循 **EARS 原则**（Ubiquitous / Event-driven / Unwanted / State-driven / Optional）。详细用户故事与验收标准沉淀在对应的「需求概要 / PRD / 技术方案」中，本池只给索引与要点。

## 四、候选需求详情

### RQ-01 详情页阅读模式（跨分类连续阅读）

> 来源：CONTEXT「待办优先级 #1」、TASK_BOARD T-01。详情页**已支持同分类内上下滑连续阅读**（已实现），真实缺口是**跨分类衔接**（看完某分类末尾无法顺滑进入下一分类）。PRD 级设计见 `docs/02-产品设计/PRD-阶段二功能增强.md`（D-01，已完成）。

- **用户价值**：通勤/午休场景下连续阅读，减少返回跳转，提升沉浸感与停留时长。
- **核心行为（EARS 要点）**：
  - **WHEN** 用户在详情页上滑 **THEN THE SYSTEM SHALL** 展示当前分类下一条新闻；
  - **WHEN** 滑到当前分类末尾 **THEN THE SYSTEM SHALL** 自动衔接下一分类首条（跨分类切换）；
  - **IF** 网络不可用且本地无缓存 **THEN THE SYSTEM SHALL** 展示「网络开小差，下拉重试」而非空白；
  - **WHILE** 阅读模式激活 **THE SYSTEM SHALL** 保持分类上下文与进度指示。
- **依赖/风险**：依赖技术负责人给出滑动手势与跨分类分页数据方案（T-01）；需复用首页 WXS 纯 ES5 红线，禁止 `return false` 阻断子元素 tap。
- **归属**：阶段二 D-01（PRD）→ 阶段三 T-01（技术方案）→ 阶段四 前端。

### RQ-02 聚合数据源开放为独立分类 tab

> 来源：CONTEXT「待办 #5」。聚合（Juhe）已接入并做分类透传，但目前对外仍按现有 8 分类展示，未把体育/生活/农业/科学等开放为独立 tab。

- **用户价值**：满足小李（午休族）「快速切换不同主题」需求，丰富垂类覆盖。
- **决策点**：是否新增「体育」「生活」等独立 tab？涉及分类体系变更与首页导航重构，**需用户拍板**（权限边界：产品可提议，立项范围由项目经理确认）。
- **状态**：⛔ 待用户决策，本期不擅自推进。

### RQ-03 收藏功能

> 来源：用户画像 P1（小李/老张强需求）。

- **用户价值**：午休看不完可稍后看；老张偏严肃内容可沉淀。
- **核心行为**：**WHEN** 用户点击收藏 **THEN THE SYSTEM SHALL** 将该条加入收藏列表并本地/云端持久化；**WHERE** 用户进入收藏页 **THE SYSTEM SHALL** 展示其收藏列表。
- **依赖**：需用户体系或 openid 维度存储（当前无登录），本期建议先用本地缓存兜底，云存储后续迭代。

### RQ-04 字体大小调节

> 来源：用户画像 P1（老张老花强需求）。

- **用户价值**： Accessibility，覆盖中老年用户。
- **核心行为**：**WHILE** 用户设置大字号 **THE SYSTEM SHALL** 全局应用并记忆；**WHEN** 首次进入 **THEN THE SYSTEM SHALL** 跟随系统字体设置。
- **注意**：与暗色模式同属全局样式系统，建议阶段二与视觉规范一并定义。

### RQ-05 离线/弱网缓存阅读

> 来源：用户画像 P2（小王通勤弱网强需求）。

- **用户价值**：地铁隧道断网仍可看已加载内容。
- **核心行为**：**WHILE** 网络不可用 **THE SYSTEM SHALL** 展示已缓存新闻列表；**WHEN** 恢复网络 **THEN THE SYSTEM SHALL** 静默补充新内容。

### RQ-06 阅读历史

### RQ-17 全局返回主页入口

> 来源：用户直连 2026-08-03。当前所有非首页页面（详情页、以及后续新增的浏览记录页、收藏列表页等）均无快捷返回主页的入口，用户只能通过微信系统左上角返回箭头逐层回退，体验割裂。

- **用户价值**：用户在任何深层页面停留时，可一键返回主页，减少逐层返回的操作步骤，提升导航效率。
- **核心行为（EARS 要点）**：
  - **Ubiquitous**：**THE SYSTEM SHALL** 在除首页（一级页面）外的所有页面（二级/三级/四级）的固定位置提供一个"返回主页"图标入口。
  - **Event-driven**：**WHEN** 用户点击"返回主页"图标 **THEN THE SYSTEM SHALL** 立即跳转至首页（`pages/home/home`），并清除导航栈（使用 `wx.reLaunch` 或等效方式）。
  - **State-driven**：**WHILE** 用户在非首页页面 **THE SYSTEM SHALL** 始终在固定位置展示该图标，不受页面滚动影响。
  - **Unwanted**：**IF** 用户已在首页 **THEN THE SYSTEM SHALL** 不展示该图标。
- **适用范围**：
  - **当前已有页面**：详情页 `pages/detail/detail`（二级页面）
  - **规划中页面**：浏览记录页 `pages/history/history`（二级）、收藏列表页 `pages/favorites/favorites`（二级）
  - **后续新增页面**：任何非首页页面均需遵守此规则
- **设计要点**：
  - 图标位置建议：页面左上角或导航栏左侧固定位（不与微信系统返回按钮冲突）
  - 图标样式：房屋/首页图标（🏠），需产品设计师出精确规格
  - 交互反馈：点击有触觉反馈（`hover-class` 或微动效）
- **归属**：阶段二 D-01 PRD v1.2 新增 → 下迭代三同版本迭代（与 RQ-03/06/07/16 一起）

### RQ-19 持续关注新闻

> 来源：用户直连 2026-08-06。需求描述基于用户原话并细化。

- **用户价值**：对某条新闻特别感兴趣时，一键关注该事件，每天打开小程序时该事件的最新进展和相关话题自动出现在推荐列表顶部，省去手动搜索的麻烦。
- **用户决策**（PM 已澄清）：
  - **按钮位置**：详情页底部操作栏（与收藏/分享并排）
  - **存储方式**：纯本地（`wx.Storage`），沿用 DG-04 刚落地的本地存储模式，后续可扩展云端同步
  - **展示位置**：推荐列表**置顶 + 带「已关注」标识**
  - **更新内容**：同一事件最新进展 + 相关话题推荐，两者都放进推荐列表
- **核心行为（EARS 要点）**：
  - **Event-driven**：**WHEN** 用户在详情页点击「🔍 关注」按钮 **THEN THE SYSTEM SHALL** 将该新闻的关键词/事件标识存入本地关注列表，并给予关注成功反馈（如按钮态变化 + toast）。
  - **Event-driven**：**WHEN** 用户再次点击已关注按钮 **THEN THE SYSTEM SHALL** 取消关注并从列表中移除。
  - **State-driven**：**WHILE** 用户打开小程序首页（推荐分类）**THE SYSTEM SHALL** 检查本地关注列表，对每条被关注的新闻，使用 AI 搜索获取该事件的最新进展与相关话题，**置顶插入推荐列表**，并带「已关注」标识。
  - **Event-driven**：**WHEN** 推荐列表已展示关注更新 **THEN THE SYSTEM SHALL** 点击可进入对应新闻详情。
  - **Unwanted**：**IF** 关注列表为空 **THEN THE SYSTEM SHALL** 正常展示推荐列表，无置顶条目。
  - **Optional**：**THE SYSTEM SHOULD** 对关注条数设置上限（建议 5 条），防止关注过多导致首页内容失衡。
- **交互设计要点**：
  - 详情页底部操作栏现有 2 个按钮（收藏 🤍/❤️ + 分享 ↗️），关注按钮作为第 3 个加入
  - 关注按钮图标建议：🔍（搜索/追踪语义）或 👁️（关注语义），待设计师确定
  - 已关注态：按钮高亮/实心 + toast「已关注，每天为你追踪最新动态」
  - 取消关注：再次点击 → 按钮恢复默认 + toast「已取消关注」
  - 推荐列表顶部置顶条：左侧「已关注」标签（Tag/胶囊样式），右侧新闻标题 + 摘要
- **技术依赖**：
  - **依赖 RQ-18 的 AI 搜索能力**：关注更新需要"根据事件关键词搜索最新新闻"，与 RQ-18 的智谱 web_search 链路一致。**建议 RQ-18 先行落地，RQ-19 在其基建上构建**。
  - 关注列表存储：复用现有 `localCache` 全局单例（与历史/收藏同源），key 建议 `followedNews`，上限 5 条。
  - 每天更新时机：`refreshNews` 云函数定时触发时同步查询关注事件的最新进展；或首页 onLoad 时异步拉取。
- **依赖/风险**：
  - RQ-18 未落地前，关注更新的搜索链路无法走通 → 建议排期在 RQ-18 之后
  - 搜索准确度：事件匹配依赖关键词提取质量，需 AI 摘要已有 `summary` 字段可复用
  - 性能：关注条数上限 5 条，每次首页加载最多 +5 次搜索调用，需评估耗时
- **与已有功能的边界**：
  - **≠ 收藏**：收藏是「保存这条新闻稍后看」；关注是「每天追踪这个事件」
  - **≠ 推荐**：关注是用户主动选择的定向追踪，推荐是系统自动推送的热门内容
  - **≠ RQ-11 个性化推荐**：关注是显式行为（用户明确点关注），个性化推荐是隐式行为（基于浏览行为推断）
