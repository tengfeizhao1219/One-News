## 一、说明

本需求池是「一页」阶段一需求规划的**唯一需求来源**。它整合了：

- **已落地需求基线**：历史上已完成开发、已在 `main` 上线的功能（作为产品当前能力边界，不重复建设）；
- **候选需求（Backlog）**：待规划 / 待开发 / 待决策的新功能、体验优化、技术债与合规项；
- **待确认问题**：需用户或项目经理拍板后才能推进的阻塞点。

> 需求描述遵循 **EARS 原则**（Ubiquitous / Event-driven / Unwanted / State-driven / Optional）。详细用户故事与验收标准沉淀在对应的「需求概要 / PRD / 技术方案」中，本池只给索引与要点。

## 四、候选需求详情

### RQ-01 详情页阅读模式（跨分类连续阅读）

> 来源：CONTEXT「待办优先级 #1」、TASK_BOARD T-01。详情页**已支持同分类内上下滑连续阅读**（已实现），真实缺口是**跨分类衔接**（看完某分类末尾无法顺滑进入下一分类）。PRD 级设计见 `docs/02-产品设计/PRD-阶段二功能增强.md`（D-01，已完成）。

- **用户价值**：通勤/午休场景下连续阅读，减少返回跳转，提升沉浸感与停留时长。
- **核心行为（EARS 要点）**：
  - **WHEN** 用户在详情页上滑 **THEN THE SYSTEM SHALL** 展示当前分类下一条新闻；
  - **WHEN** 滑到当前分类末尾 **THEN THE SYSTEM SHALL** 自动衔接下一分类首条（跨分类切换）；
  - **IF** 网络不可用且本地无缓存 **THEN THE SYSTEM SHALL** 展示「网络开小差，下拉重试」而非空白；
  - **WHILE** 阅读模式激活 **THE SYSTEM SHALL** 保持分类上下文与进度指示。
- **依赖/风险**：依赖技术负责人给出滑动手势与跨分类分页数据方案（T-01）；需复用首页 WXS 纯 ES5 红线，禁止 `return false` 阻断子元素 tap。
- **归属**：阶段二 D-01（PRD）→ 阶段三 T-01（技术方案）→ 阶段四 前端。

### RQ-02 聚合数据源开放为独立分类 tab

> 来源：CONTEXT「待办 #5」。聚合（Juhe）已接入并做分类透传，但目前对外仍按现有 8 分类展示，未把体育/生活/农业/科学等开放为独立 tab。

- **用户价值**：满足小李（午休族）「快速切换不同主题」需求，丰富垂类覆盖。
- **决策点**：是否新增「体育」「生活」等独立 tab？涉及分类体系变更与首页导航重构，**需用户拍板**（权限边界：产品可提议，立项范围由项目经理确认）。
- **状态**：❌ 已取消（用户决策：保留 8 分类现状，不新增独立 tab）。

### RQ-03 收藏功能

> 来源：用户画像 P1（小李/老张强需求）。

- **用户价值**：午休看不完可稍后看；老张偏严肃内容可沉淀。
- **核心行为**：**WHEN** 用户点击收藏 **THEN THE SYSTEM SHALL** 将该条加入收藏列表并本地/云端持久化；**WHERE** 用户进入收藏页 **THE SYSTEM SHALL** 展示其收藏列表。
- **依赖**：需用户体系或 openid 维度存储（当前无登录），本期建议先用本地缓存兜底，云存储后续迭代。

### RQ-04 字体大小调节

> 来源：用户画像 P1（老张老花强需求）。

- **用户价值**： Accessibility，覆盖中老年用户。
- **核心行为**：**WHILE** 用户设置大字号 **THE SYSTEM SHALL** 全局应用并记忆；**WHEN** 首次进入 **THEN THE SYSTEM SHALL** 跟随系统字体设置。
- **注意**：与暗色模式同属全局样式系统，建议阶段二与视觉规范一并定义。

### RQ-05 离线/弱网缓存阅读

> 来源：用户画像 P2（小王通勤弱网强需求）。

- **用户价值**：地铁隧道断网仍可看已加载内容。
- **核心行为**：**WHILE** 网络不可用 **THE SYSTEM SHALL** 展示已缓存新闻列表；**WHEN** 恢复网络 **THEN THE SYSTEM SHALL** 静默补充新内容。

### RQ-06 阅读历史

> 来源：用户画像 P2。

- **用户价值**：避免重复阅读，支持「接着看」。
- **依赖**：与 RQ-03 共享存储层设计，建议合并规划。

### RQ-07 分享功能

> 来源：用户画像 P1。

- **用户价值**：社交传播，低成本拉新。
- **核心行为**：**WHEN** 用户点击分享 **THEN THE SYSTEM SHALL** 调起微信转发卡片（标题+摘要+封面）。

### RQ-08 首页诊断 console.log 清理

> 来源：待办 #2。纯技术债，无用户可见影响，低优。

### RQ-09 SOP 更新（WXS 红线 + return false 禁令）

> 来源：待办 #4。将 CONTEXT「关键开发红线」固化进 `docs/SOP-软件开发流程基准.md`，防止回归。

### RQ-10 内容合规审核（微信内容安全 API）

> 来源：风险 R3/R8（违规内容可致小程序下架，影响极高）。

- **用户价值/业务价值**：守住合规底线，保障线上存续。
- **核心行为**：**IF** 待入库新闻命中敏感词或内容安全 API 拒识 **THEN THE SYSTEM SHALL** 拦截该条、记录日志并告警，不进入 news_cache。
- **优先级**：P0（合规强约束，建议在下一数据同步链路中落地）。

- **决策点**：用户已拍板——**不做搜索功能**，RQ-13 移出阶段二范围，不在后续迭代排入。
- **状态**：❌ 已砍掉（用户决策），不占用排期。

### RQ-15 侧边分类滚轮选择器（🆕 用户反馈）

> **来源**：用户实测反馈。当前分类切换需「左滑打开面板 → 横向找 Tab → 点选 → 关闭面板」，四步操作，单手不便。**按用户要求：将分类选择改为右侧垂直滚轮**，类似 iOS 时间选择器式交互 — 选中项固定在中间高亮，上下滑动切换，松手吸附。

**核心 EARS 描述**：
- **WHILE** 首页卡片流展示 **THE SYSTEM SHALL** 在屏幕右侧始终显示半透明分类滚轮（opacity 0.35），选中的分类名居中高亮（opacity 0.7）；其余分类以上下渐变淡出排列。
- **WHEN** 用户手指触碰滚轮区域 **THEN THE SYSTEM SHALL** 激活滚轮：整体 opacity 升至 0.9，选中项加深为主题色并加粗，上下出现中心指示线，背景附毛玻璃效果。
- **WHEN** 用户上下滑动滚轮 **THEN THE SYSTEM SHALL** 即时切换主卡片流到对应分类（不等松手）；松手后 snap 吸附到最近分类，触发轻微震动反馈（`wx.vibrateShort`）。
- **IF** 用户手指离开滚轮 **THEN THE SYSTEM SHALL** 300ms 后恢复半透明默认态。
- **WHERE** 分类滚轮生效 **THE SYSTEM SHALL** 在卡片流顶部居中显示当前分类标题（如「科技」），作为辅助标识。

**设计要点**：
1. **位置**：屏幕右侧，卡片流右边缘内 8rpx，宽 88rpx，与卡片流等高
2. **分类列表**：推荐 → 科技 → 国际 → 体育 → 生活 → 三农 → 科学 → ❤️收藏（最后一项用分割线隔开）
3. **吸附**：`scroll-snap-type: y mandatory`，惯性一���最多跨 3 个分类后减速停止
4. **兼容**：不抢占卡片左右滑动手势（滚轮区域为独立窄条）；现有分类数据源不变
5. **侧边栏简化**：面板中的分类 tab 可移除，面板仅保留新闻列表 + 收藏列表

**决策点**：
- Q-D7：RQ-15 放在哪个迭代？当前阶段五仍在测试验收，RQ-15 建议进入下迭代（阶段二后续或阶段三）。需用户确认优先级与排期。

> 完整 PRD 级设计见 `docs/02-产品设计/PRD-RQ15-侧边分类滚轮选择器.md`。
