## 二、文档 vs 代码实况：核心偏差（按严重度）

### 🔴 严重（直接影响排期/范围/合规判断）

**D-1｜RQ-01 现状描述错误**
- 需求池写："当前详情页仅支持单条查看，用户看完需返回首页再进入下一条，路径断裂"，状态 🔴 高优待开发。
- 代码实况：`pages/detail/detail.js` 已实现**同分类内**上下滑连续阅读——`onTouchStart/onTouchEnd` + `pageTo()` + `positionText`（如 "3 / 20"）+ 上/下一篇按钮；`home.js:508` 进入详情时写入 `globalData.detailContext = { category, list }`。
- **结论**：仅"跨分类衔接（滑到末尾自动接下一分类首条）"未做。范围应**收窄为"跨分类衔接"**，工作量与优先级需下调，不应按"从零建设"评估。

**D-2｜数据架构描述自相矛盾且已过期**
- 需求池基线："真实数据接入（五层降级）天行 L1 → 内存 L2 → 云库 L3 → 聚合 L4 → AI 兜底 L5"。
- `新闻自动更新-需求概要.md`："WorkBuddy → GitHub `news.json` → refreshNews 定时拉取 → 云数据库 `news_cache`"。
- 代码实况：`cloudfunctions/refreshNews/index.js` 已是 **v3＝阿里百炼 DeepSeek 联网搜索 → `validateAndClean` 质量校验 → 写入 `news_cache`**（定时 6:00/11:00/20:00 + 手动）；`getNewsList` 为 L1 天行直连 → L2 内存 → L3 `news_cache` → L4 聚合 → L5 AI 静态缓存。
- **结论**：实际需求概要描述的是**已被替代的旧架构**（GitHub news.json 路径已不存在，仓库 `data/news.json` 为遗留/未启用）；需求池基线描述的"五层降级"与代码一致，但**未说明 refreshNews 的真实数据生产方是阿里百炼**（非天行 API 本身）。两份文档口径打架，会误导 RQ-10 合规落点与 RQ-13 数据源判断。

**D-3｜分类体系与代码常量不符，RQ-14 前提不成立**
- 需求池写："`constants.js` 实际分类为 `all/recommend/tech/sports/life`，**无 `international`**"；`实时新闻-需求概要` 也把 `international` 当"不存在的分类"。
- 代码实况：`utils/constants.js` 实际为 **8 个分类**：`all / recommend / tech / international / sports / life / agriculture / science`。（**2026-08-03 owner 裁定**：agriculture/science 已下架，当前为 6 分类。）
- **结论**：① `international` **早已存在**，RQ-14「国际分类补全」前提不成立，应改为"确认 international/agriculture/science 是否真实有数据并被前台展示"；② `agriculture`、`science` 两分类**任何需求文档都未提及**，存在"代码有、需求无"的覆盖盲区，已于 2026-08-03 owner 裁定下架。

### 🟠 高（阻断搜索/合规相关决策）

**D-4｜RQ-13 搜索：不是"不一致"，是"整体缺失"**
- 需求评审纪要将 RQ-13 定为"CONTEXT 与 app.json 不一致，需核实"。
- 代码实况：`app.json` 仅注册 `pages/home/home` 与 `pages/detail/detail`（**无搜索页**）；仓库**无 `searchNews` 云函数**；`request.js` **无搜索接口**；仅历史文档引用 `searchNews`。
- **结论**：搜索功能**从页面到云函数均不存在**，`CONTEXT.md` 标注"搜索页 ✅ 已完成"为**错误陈述**。RQ-13 应升级为"搜索能力重建"评估，而非"补注册"。

**D-5｜PRD-新闻速览小程序.md（v2.0）已过时且自相矛盾**
- 路由写 `pages/index/index`，实际为 `pages/home/home`；
- 功能清单把"收藏 F11 / 搜索 F12 / 字体 F13 / 历史 F14"全列为 P2，但 §2.3 设计稿又画出"🤍 收藏 ｜ ↗️ 分享"底部操作栏——**自相矛盾**；
- 全文未覆盖 RQ-01~RQ-14 中**任何一条**新需求。
- **结论**：该 PRD 是历史 MVP 文档，**阶段二无对应 PRD**——这正是本轮需补全 D-01 的原因。

### 🟡 中（过期架构描述，需标注）

**D-6｜两份"需求概要"与"技术方案文档"为过期架构**
- `实时新闻-需求概要`/`新闻自动更新-需求概要`（Iteration 4）引用 `searchNews` 云函数、`aiNewsData.js`（已废弃）、`mock/news.js`（已不存在），目录结构含 `components/swipe-card` 等、`styles/`——均与当前仓库不符。
- `技术方案文档.md`（Iteration 2）目录结构（`pages/search`、`components/*`、`styles/*`、`mock/`）同样与现状不符，且未反映 v5 后的真实数据架构。
- **结论**：这些文档可保留作"演进历史"，但应在头部标注 **"已过期，当前架构以 RELAY/CONTEXT 与代码为准"**，避免被后续角色误读。
