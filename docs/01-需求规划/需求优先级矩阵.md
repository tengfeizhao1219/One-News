## 一、评分方法

采用 **价值-复杂度二维评分 + 风险修正**，便于排序与排期沟通。

| 维度 | 说明 | 分值 |
|------|------|------|
| **业务价值 V**（1–5） | 对用户痛点覆盖、留存/传播/合规的贡献；合规=RQ-10 顶格 |
| **用户覆盖 U**（1–5） | 命中画像 A/B/C 的广度（通勤/午休/晚间） |
| **实现复杂度 C**（1–5） | 1=改配置，5=跨模块重构+新依赖；分值越高越难 |
| **风险/依赖 R**（1–5） | 1=无阻塞，5=强依赖外部决策或技术方案未定 |
| **建议优先级** | 由 V、U 与 R 综合判定：P0（必做）／P1（本迭代）／P2（下迭代）／P3（按需） |

> **排序原则**：高价值 × 广覆盖 × 低复杂度 优先；合规（RQ-10）与核心体验断点（RQ-01）即使复杂度高也进 P0；强依赖外部决策的（RQ-02/RQ-13）先挂起、不占用排期。

## 四、结论与建议

1. **P0（必做，下版本）**：RQ-10 合规审核、RQ-01 阅读模式。两者直接关系「线上存续」与「核心体验闭环」，应优先排入阶段二 PRD 与阶段三技术方案（T-01）。
2. **P1（本迭代功能增强）**：RQ-04 字体调节、RQ-03 收藏、RQ-07 分享、RQ-13 搜索页修复（先确认现状）。
3. **挂起待决策**：RQ-02（聚合独立分类 tab）、RQ-13 现状核实、RQ-14 国际分类——待用户/项目经理拍板后再定排期，不占用当前迭代排期。
4. **P2/P3（后续/技术债）**：离线缓存、阅读历史、推荐、console 清理、SOP 更新，按资源节奏排入。
5. **权限边界提醒**：本矩阵为产品经理的「做什么/做成什么样」建议；**排期、资源、立项范围（R-06）由项目经理确认**，聚合分类体系扩展（RQ-02/RQ-14）需用户决策，阅读模式技术方案（RQ-01）由技术负责人在 T-01 主导。
