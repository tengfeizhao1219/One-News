> **编写人**：全栈开发（FS） | **重写日期**：2026-08-04
> **原始版本**：2026-07-31（基于 v3.x 五层降级，已作废）
> **重写原因**：v4.2 架构已移除 L1~L5 五层降级链，替换为 ADR-003 单层兜底（三层降级：news_cache → backup → 内置精选）。原 L1→L5→ALL_DOWN 故障注入方案完全失效。

## 一、测试目标

验证 `getNewsList` 云函数在 `news_cache` 不同空/故障状态下按 ADR-003 三层降级正确返回数据，确保：

1. **正常路径**：news_cache 有效 → 直接返回，`meta.source='db_cache'`
2. **Stale 兜底**：news_cache 过期但非空 → 仍返回过期数据（现有行为不变）
3. **Backup 降级**：news_cache 完全为空 → 查询 `news_cache_backup` 备份快照，`meta.source='cache-fallback'`
4. **内置精选兜底**：backup 也为空（极端：首次部署） → 返回硬编码精选列表，`meta.source='cache-fallback'`
5. **不空白页保障**：任何路径下 `data.list` 不为空数组（极端兜底至少返回内置精选）
6. **分类隔离**：不同分类独立降级，不会因一个分类失败影响其他

## 二、测试架构

### 2.1 数据查询优先级（v4.2 真源）

```
getNewsList(category, pageNum, pageSize)
   │
   ├─ 1. news_cache（未过期，cacheExpire > now）────── 命中 ──→ 返回 (meta.source='db_cache')
   │      │ 未命中（无未过期记录）
   ▼
   ├─ 2. news_cache（已过期，stale 兜底）────────────── 有数据 ──→ 返回 (meta.source='db_cache')
   │      │ 完全为空（0 条记录）
   ▼
   ├─ 3. news_cache_backup（上次成功快照）──────────── 有数据 ──→ 返回 (meta.source='cache-fallback')
   │      │ 为空（从未成功 refresh）
   ▼
   └─ 4. 内置精选列表（硬编码，覆盖 5 分类）────────── ──→ 返回 (meta.source='cache-fallback')
```

### 2.2 故障注入方法

| 场景 | 操作方式 | 操作人 | 恢复方式 |
|------|----------|--------|---------|
| **news_cache 正常** | 无操作（基线） | — | — |
| **news_cache 过期非空** | 手动将 `news_cache` 中某分类记录的 `cacheExpire` 设为 `now - 1h` | 后端/全栈 | `refreshNews` 触发重新写入 |
| **news_cache 完全为空** | 手动删除 `news_cache` 中某分类的全部记录 | 后端/全栈 | `refreshNews` 触发重新写入 |
| **news_cache + backup 均为空** | 删除 `news_cache` 和 `news_cache_backup` 中某分类的全部记录 | 后端/全栈 | `refreshNews` 触发重新写入 |

### 2.3 验证手段

| meta.source | 含义 | 预期触发条件 |
|-------------|------|-------------|
| `db_cache` | news_cache 正常/过期返回 | news_cache 有数据（未过期或过期 stale） |
| `cache-fallback` | 兜底路径 | news_cache 完全为空，走 backup 或内置精选 |
| — (list 非空) | 任何路径 | data.list.length > 0（绝不空白页） |

## 四、测试执行流程

```
准备阶段
├── 1. 确认 news_cache 正常 → 执行 FB-01（基线）
├── 2. 确认 backup 有数据（refreshNews 至少成功一次）
│
故障模拟阶段
├── 3. news_cache 过期 → 执行 FB-02（stale 兜底）
├── 4. 删除 news_cache 某分类 → 执行 FB-03（backup 降级）
├── 5. 删除 news_cache + backup 某分类 → 执行 FB-04（内置精选兜底）
│
特殊场景
├── 6. 分类隔离 → 执行 FB-05
├── 7. refreshNews 恢复 → 执行 FB-06
├── 8. backup 自动创建 → 执行 FB-07
├── 9. 全分类覆盖 → 执行 FB-08
│
清理
└── 10. 触发 refreshNews 恢复所有分类数据 → 执行 FB-01（确认恢复）
```
