## 一、目标

本计划定义「一页 One-News」在真机上的兼容性测试范围、设备矩阵、网络场景、执行步骤和通过标准。覆盖微信小程序在 iOS/Android 多机型、多微信版本、多网络条件下的核心用户路径验证。

**核心原则**：
- P0 场景必须全机型通过方可发布
- P1 场景覆盖主力机型
- 自动化回归（178 用例）先行，真机验证为最后一道关卡

## 三、网络场景矩阵

| 场景编号 | 网络条件 | 模拟方式 | 测试目标 |
|:--------:|----------|----------|----------|
| N-01 | 稳定 Wi-Fi（≥10Mbps） | 正常 Wi-Fi 连接 | 正常功能基线 |
| N-02 | 4G 良好（5-10Mbps） | 移动数据 | 移动网络正常使用 |
| N-03 | 4G 弱网（1-2Mbps，延迟 300ms） | Charles/Proxy 限速 | 加载中状态、超时兜底 |
| N-04 | 3G 弱网（200-500Kbps，延迟 500ms） | Charles/Proxy 限速 | 降级体验、缓存命中 |
| N-05 | 断网（完全无连接） | 飞行模式 | 离线缓存/错误兜底 |
| N-06 | 网络切换（Wi-Fi ↔ 4G） | 手动切换 | 连接恢复、数据一致性 |
| N-07 | 不稳定网络（间歇丢包 20%） | Charles/Proxy 丢包模拟 | 重试机制、UI 稳定性 |

> **工具推荐**：iOS 使用 Network Link Conditioner；Android 使用 Charles Proxy / Fiddler 限速；微信开发者工具内置网络模拟仅用于初步验证。

## 六、通过标准

### 6.1 质量门槛

| 级别 | 标准 | 不满足时 |
|:----:|------|----------|
| P0 功能 | 8 台必测机型 + 8 条 P0 场景 = 64 个组合 **100% 通过** | 🚫 **阻断发布** |
| P0 网络 | P0 场景在 N-01（Wi-Fi）下全部通过，N-05（断网）下兜底行为符合预期 | 🚫 **阻断发布** |
| P1 功能 | ≥95% 通过率（允许非核心 UI 差异，如 1px 偏移） | ⚠️ 记录遗留，评估是否降级 |
| P1 性能 | 首屏 Wi-Fi < 2s / 4G < 3s，翻页动画无肉眼可见卡顿 | ⚠️ 性能优化建议 |
| 稳定性 | 连续操作不闪退、不白屏、不 ANR | 🚫 **阻断发布** |

### 6.2 可接受的差异

以下差异在真机间可接受（记录但不阻断）：
- 系统字体渲染差异（iOS San Francisco vs Android Roboto）导致的 1-2px 偏移
- 不同屏幕圆角/刘海/挖孔区域的安全区差异（只要内容不被遮挡）
- 暗色模式下 OLED vs LCD 的黑色深度差异
- 不同机型滚动惯性/回弹效果的微妙差异

### 6.3 不可接受的差异

以下差异视为 Bug，必须修复：
- 文字截断、重叠、溢出
- 按钮/图标点击区域偏移导致误触
- 图片加载失败、变形、比例失调
- 动画卡顿、闪烁、黑屏
- 功能行为差异（如同一操作在不同机型结果不同）
- 闪退、白屏、无响应

## 七、Bug 分级与处理策略

| 级别 | 定义 | 真机场景示例 | 处理 |
|:----:|------|-------------|------|
| P0-阻断 | 核心功能不可用，影响 ≥50% 用户 | 详情页在 iOS 15 闪退；跨分类衔接在所有 Android 机不触发 | 立即修复，修复后全机型复测 |
| P1-严重 | 功能可用但体验严重受损 | 特定机型字体溢出导致内容不可读；暗色模式下文字与背景同色 | 本迭代修复 |
| P2-一般 | 功能正常但有视觉/体验瑕疵 | 某机型 1px 边框缺失；分享卡片在 Android 上封面图略模糊 | 记录，评估排期 |
| P3-建议 | 优化建议，不影响功能 | 动画曲线可优化；加载态可更友好 | 后续迭代 |

## 八、与自动化回归的关系

```
自动化回归（178 用例，开发者工具）
  └── 通过后 ──→ 真机 P0 验证（本计划）
                   └── 通过后 ──→ 性能基线采集（Q-新07）
                                    └── 通过后 ──→ 验收签署
```

- 自动化回归是**真机测试的前置条件**——数据层/逻辑层问题在开发者工具阶段解决
- 真机测试专注**设备相关**问题：渲染、触摸、网络、性能、系统 API 兼容
- 真机不重复验证自动化已覆盖的数据逻辑（如字段完整性、缓存 TTL）

## 九、风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|:----:|:----:|----------|
| P0 机型不全（如缺华为 Mate 60 Pro） | 中 | 高 | 优先确保 iOS/Android 各 ≥2 台；缺失机型用同品牌同系统版本替代 |
| 弱网模拟工具在真机不可用 | 低 | 中 | 备选：iOS 开发者模式 Network Link Conditioner；Android ADB 限速 |
| 微信体验版与正式版行为差异 | 低 | 中 | 关键场景在正式版（审核通过后发布前）快速冒烟 |
| 阶段四交付延期导致真机测试时间压缩 | 中 | 高 | 本计划先发布，测试执行人拿到即可启动；P0 场景控制在 2 小时/台 |
