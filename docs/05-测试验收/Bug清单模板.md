### BUG-20260801-007：首页刷新后卡片更新、侧边栏列表不更新（_panelCache 永不失效）

**基本信息**
- 优先级：🟡 P1
- 模块：侧边栏/首页
- 状态：待验证（QA 已提交补丁，commit `01a52ab`）
- 指派给：@前端开发
- 发现版本：v1.0（阶段五 实测）
- 发现人：QA（用户反馈「卡片和列表内容不一致」后复现）
- 环境：真机 / 微信 8.x / 基础库 3.x / 正常网络

**复现步骤**
1. 冷启动首页，首页卡片（`newsList`）与侧边栏列表（`filteredNewsList`）均为第一批数据。
2. 触发刷新：下拉刷新（`onPullDownRefresh` → `loadNews`）或点「手动刷新」（`onRefreshNews` → `refreshNews` 云函数 → `loadNews`）。
3. 首页卡片更新为新数据；左滑呼出侧边栏查看「全部新闻」列表。

**实际结果**
> 侧边栏列表仍展示**刷新前**的旧新闻，与首页当前卡片内容不一致；且只要不切换分类，侧边栏永远停留在首次加载的快照，任何刷新都不会让其更新。

**期望结果**
> 首页卡片与侧边栏列表都来自同一份数据源；任一处刷新后，另一处也应同步反映最新数据（或至少侧边栏在打开时拉取最新）。

**根因定位**
- `pages/home/home.js` 第 166 行 `this._panelCache = {}` 定义侧边栏内存缓存；
- 第 169–198 行 `loadPanelNews(category)`：命中 `_panelCache[cat]` 时直接 `return`（第 179 行），**永不重新拉取、永不失效**；
- 第 141–163 行 `loadNews()`：仅 `setData({ newsList })`（第 153 行）+ `renderCards(list)`（第 154 行），**全程不触碰 `_panelCache`**；
- 第 201–205 行 `onPullDownRefresh`、第 213–243 行 `onRefreshNews` 都只调 `loadNews()`，同样不清理 `_panelCache`。

**影响范围**
- 影响模块：首页卡片、侧边栏「全部新闻」列表
- 是否阻断核心流程：否（卡片阅读正常），但属于用户可见的**数据正确性**问题，正是用户反馈的「卡片和列表内容不一致」主因。

**修复建议**
- 方案 A（最小改动）：`onRefreshNews` / `onPullDownRefresh` 刷新成功后执行 `this._panelCache = {}`，使下次侧边栏打开重新拉取；
- 方案 B（更彻底）：侧边栏与主列表共用同一份 `newsList`，去掉独立 `_panelCache`，避免双数据源；
- 建议选 B，从结构上消除「两套数据」的不一致风险（与 BUG-20260801-008 同源）。

**修复记录**（QA 提交，待前端确认）
- 修复版本：commit `01a52ab` / 修复说明：采用方案 B — 删除 `_panelCache` + `loadPanelNews()`，新增 `syncPanelToNewsList()` 直接复用 `newsList`；`onLoad`/`onRefreshNews`/`onPullDownRefresh`/`onRetry`/`onCategoryChange` 共 5 个入口统一调用同步。净变化 `home.js` +30/−39 行。 / 关联 PR：—

**验证结论**（测试填写）
- 验证版本：待验证 / 验证结果：— / 验证人：前端开发 / 关闭时间：—

### BUG-20260801-008：详情页阅读顺序/内容与首页卡片不一致

**基本信息**
- 优先级：🟢 P2
- 模块：阅读模式/详情页
- 状态：新建
- 指派给：@前端开发
- 发现版本：v1.0（阶段五 实测）
- 发现人：QA
- 环境：真机 / 微信 8.x / 正常网络

**复现步骤**
1. 首页在「推荐」分类下，卡片列表为 A、B、C…（按首页 `getNewsList` 顺序）。
2. 点击卡片进入详情页，首页已通过 `onCardTap` 把 `app.globalData.detailContext = { category, list }` 传给详情页。
3. 详情页 `ReadingEngine.init()` 并行独立拉取 7 个非 `all` 分类（含 `all` 也走合并），用 B-06 缓存（TTL 10 分钟）构建 `mergedList`，**未使用** `detailContext.list`。
4. 通过上下翻页（跨分类）阅读。

**实际结果**
> 详情页跨分类合并后的顺序、是否包含某条新闻，取决于 7 个分类各自接口返回与 10 分钟缓存，**与首页卡片所见顺序不完全一致**；缓存命中时尤其明显（首页已刷新、详情仍用旧缓存）。

**期望结果**
> 从首页卡片进入详情后，阅读流应以用户刚看到的卡片为锚点，顺序与首页一致（至少在 `detailContext.list` 范围内保持一致）。

**根因定位**
- `pages/detail/reading-engine.js` `_fetchCategoryWithCache` 读取 `newsList:{categoryId}` 缓存（TTL 10min），命中即返回，与首页 `newsList` 解耦；
- `ReadingEngine.init()` 并行拉取 7 分类重建 `mergedList`，**忽略首页传入的 `detailContext.list`**，仅用 `entryNewsId` 做位置对齐，顺序由引擎自身决定。

**影响范围**
- 影响模块：详情页阅读顺序、跨分类浏览
- 是否阻断核心流程：否（单条阅读正常），但会造成「卡片点进去发现顺序/内容对不上」的体感。

### BUG-20260801-009：滑动动画期间触发刷新致卡片回退到旧列表（renderCards 闭包快照竞态）

**基本信息**
- 优先级：⚪ P3
- 模块：首页
- 状态：新建
- 指派给：@前端开发
- 发现版本：v1.0（阶段五 实测）
- 发现人：QA
- 环境：真机 / 微信 8.x / 弱网或手动快速操作

**复现步骤**
1. 首页上滑切下一条，触发 `_animateSwipeNext()`（第 370 行），第 371 行 `const { newsList } = this.data` **快照**当前列表。
2. 在 `SWIPE_ANIMATION_MS + 50`（350+50=400ms）的 `setTimeout` 回调执行前，触发 `onRefreshNews`/`onPullDownRefresh` → `loadNews()` 更新 `this.data.newsList` 为全新列表并 `renderCards(list)`。
3. 400ms 后 `setTimeout` 回调执行 `this.renderCards(newsList, newIndex)`，其中 `newsList` 是第 1 步的**旧快照**。

**实际结果**
> 刷新后的新数据被动画回调用旧快照覆盖，卡片回退到刷新前内容，出现「刷新了却没更新 / 卡片跳动」的观感。

**期望结果**
> 动画回调应使用刷新后的最新列表；或在刷新/列表变更时取消进行中的动画渲染。

**根因定位**
- `pages/home/home.js` 第 371 行 `_animateSwipeNext` 在闭包中捕获 `newsList` 快照，第 398–406 行 `setTimeout` 在 400ms 后用该快照调用 `renderCards`，与期间发生的 `loadNews` 更新形成竞态。

**影响范围**
- 影响模块：首页卡片渲染
- 是否阻断核心流程：否（极端时序才触发，低频）

**修复建议**
- 在 `setTimeout` 回调内改用 `this.data.newsList`（最新值）而非闭包快照；或动画开始时置 `_isAnimating` 并在 `loadNews` 中跳过/重排渲染。
