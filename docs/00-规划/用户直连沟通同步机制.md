# 用户直连沟通同步机制（User→AI Direct Communication Sync）

> **生效时间**：2026-08-02
> **制定者**：项目经理
> **适用**：项目所有 AI 角色（测试/视觉/交互/TL/后端/前端/产品/PM）
> **关联文档**：`TASK_BOARD.md` 广播区、`docs/00-规划/任务交接流转机制.md`

---

## 一、为什么需要这条机制

本项目每个 AI 角色是**独立沙箱会话**。当用户（产品 owner）**直接**在某个角色的会话里下达指令（事项 / 调整 / 改动 / 需求 / 决策）时，其他角色**看不到**这段对话。如果不主动同步，就会出现：

- A 角色按用户最新指令改了方向，B 角色还在按旧决定做事 → 重复/冲突
- 用户推翻了昨天的决定，但没人记录 → 后续会话又按旧决定执行
- 用户的需求细节散落在各角色私聊里，PM 无法统筹

**本机制目标**：让用户的每一句"直接指令"都变成**全员可见的项目事实**。

---

## 二、核心规则（硬性的）

> 🚨 **用户直接给任一角色下达的事项 / 调整 / 改动 / 需求 / 决策，接收方角色必须第一时间同步到项目日志 `COMMLOG.md`。**
>
> **不记录 = 视同未完成交接。**

---

## 三、适用范围（哪些算"需要同步"）

只要满足"用户直接对你说 + 属于项目事项"，就必须记：

| 类型 | 举例 |
|------|------|
| 事项 / 任务 | "把这个按钮去掉"、"加一个收藏功能" |
| 调整 / 变更 | "颜色改成蓝色"、"先别做 B-13 了" |
| 需求 / 范围 | "下个版本要支持搜索"、"砍掉分享" |
| 决策 / 结论 | "用方案 A"、"就按你说的来" |
| 推翻 / 反转 | "昨天说的不要了，还是用原来的" |
| 资源 / 凭证 | "token 是这个：xxx"、"用 tdrive 里那个配置文件" |

> ⚠️ **凭证类**（token、密钥）**绝不可写进 COMMLOG 明文**（GitHub Push Protection 会拦截，且有泄露风险）。只需记录"用户已提供 X 凭证，存放位置/获取方式"，不要在日志里贴明文。

---

## 四、操作要求

1. **时效**：收到用户直连指令后，**当次会话内**即在 `COMMLOG.md` 顶部追加一条记录（时间倒序，最新在最上）。
2. **涉及多人/多模块**：除 COMMLOG 外，在 `TASK_BOARD.md` 广播区**点名相关角色**并激活其任务（⏳→📋）。
3. **推翻原决定**：必须记录，并标注「**推翻原 X**」，说明新结论，避免后续会话来回反复。
4. **不要只写"请认领"**：按 `任务交接流转机制.md` §2.4，写清"交付了什么 / 下游做什么 / 注意事项 / 找谁"。

---

## 五、COMMLOG 记录模板

```markdown
## [YYYY-MM-DD] 📣 用户直连：[一句话主题] | 会话：[角色名]

### 用户原话要点
- （用你自己的话概括，不要大段复制；保留关键约束与边界）

### 影响范围
- 涉及模块 / 角色 / 文件：___
- 是否推翻既有决定：是（原 X）→ 否

### 待其他角色动作
- [角色A]：___
- [角色B]：___（如有）

### 注意事项 / 红线
- ___

> 来源：用户直连会话（非 TASK_BOARD 派发）
```

---

## 六、示例

**场景**：用户在前端开发会话里说"把详情页翻页动画改成连续滑动，去掉查看原文按钮"。

**前端开发应在 COMMLOG 追加**：

```markdown
## [2026-08-02] 📣 用户直连：详情页动画改连续滑动 + 去掉查看原文 | 会话：前端开发

### 用户原话要点
- 详情页翻页动画要连续滑动（消除中间停顿），不要两步跳变
- 移除"查看原文"按钮（平台限制下无优雅方案）

### 影响范围
- 文件：pages/detail/*（动画 + 入口）
- 是否推翻既有决定：否

### 待其他角色动作
- 无（前端独立完成，无依赖）

### 注意事项
- 与 UX-BUG11/UX-BUG10 同源，避免重复劳动
```

---

## 七、红线

- 🔴 收到用户直连指令 **不记 COMMLOG** → 视同未完成交接，PM 可打回
- 🔴 用户"推翻原决定"不标注「推翻原 X」→ 后续会话会反复，禁止
- 🔴 在 COMMLOG **明文写 token/密钥** → 安全违规 + GitHub 拦截
- 🔴 只记自己、不点名受影响的其他角色 → 同步不完整

---

## 八、QA 自检

- 我这次会话收到的用户指令，是否已逐条同步到 COMMLOG？
- 推翻类的，是否标了「推翻原 X」？
- 需要别人配合的，是否在 TASK_BOARD 广播区点名激活？
- 凭证是否只记"已提供/位置"而未贴明文？
