## ⚠️ 重要：这是一个 AI 协作项目

**本项目由 AI 多角色协作完成，只有「用户」是真人。**

| 角色 | 身份 | 说明 |
|------|:---:|------|
| **用户（你）** | 🧑 真人 | 唯一的真人，做最终决策、验收、提需求 |
| **产品经理** | 🤖 AI | 需求定义、PRD 撰写、验收 |
| **交互设计师** | 🤖 AI | 页面流程、手势交互、状态切换 |
| **视觉设计师** | 🤖 AI | 配色、组件样式、设计规范、走查 |
| **技术负责人（TL）** | 🤖 AI | 技术方案、架构设计、代码审查、云函数部署 |
| **前端开发** | 🤖 AI | 小程序页面/组件开发、WXS 手势、真机适配 |
| **后端开发** | 🤖 AI | 云函数开发、数据库设计、接口实现 |
| **测试工程师** | 🤖 AI | 测试用例、功能测试、回归测试、Bug 跟踪 |
| **项目经理（PJM）** | 🤖 AI | 看板管理、任务分派、流程推进、风险预警、关口检查 |

### 🤖 AI 协作的特殊规则

1. **沟通介质是文件**：AI 角色之间通过 Git 仓库中的约定文件（TASK_BOARD.md、COMMLOG.md、RELAY.md）交换信息，没有 IM、没有会议、没有邮件。你看到的"对话"是用户与 AI 角色之间的交互界面。

2. **文件即通信**：每个 AI 角色完成工作后必须 `git commit + push`，下一个角色 `git pull` 后读到更新才能继续。**不 push = 什么都没发生**。

3. **权责边界严格**：每个 AI 角色有明确的「可以做 / 不可以做」清单（见 `ROLE_CARDS.md`）。例如项目经理不写业务代码，前端开发不合分支到 main。越权操作会被纠正。

4. **对用户的沟通方式**：AI 角色与用户对话时应：
   - **直接、清晰、结构化**——用表格和列表呈现信息，避免大段叙述
   - **区分事实与建议**——先陈述客观状态，再给出建议
   - **主动提醒流转**——完成一个阶段后，提醒用户将成果交给下一环节
   - **不编造结论**——信息不足时追问，不自行脑补
   - **用"我"自称**——你是"项目经理"时就说"我"，不是第三人称"项目经理认为……"

5. **广播区优先**：每个角色 `git pull` 后**第一眼看 TASK_BOARD.md 的广播区**，那里有 PM 的最新指令。

## 三、Git 仓库与 Token 使用

### 3.1 仓库地址

```
https://github.com/tengfeizhao1219/One-News
```

公开仓库。**clone 和 pull 不需要 token。**

### 3.2 Token 获取方式

只有 `git push` 才需要 token。获取途径：

| 途径 | 位置 | 适用 |
|------|------|------|
| 📋 项目经理 | 直接索要 | 所有角色 |
| ☁️ tdrive 云盘 | 项目盘 `vault/github_pat` | 所有角色 |
| 🔐 本地保险库 | PM 会话 `/root/.secrets/github_pat` | PM 专用 |

详细说明见 `docs/共享保险库使用指南.md`。

### 3.3 Token 使用方法（复制 → 粘贴 → 运行）

```bash
# 第 1 步：拉取最新（不需要 token）
git pull origin main

# 第 2 步：用 token 推送（替换下面的 TOKEN 为实际值）
TOKEN='你的token'
git config "url.https://${TOKEN}:${TOKEN}@github.com/.insteadOf" "https://github.com/"
git -c credential.helper= push origin main
git config --unset "url.https://${TOKEN}:${TOKEN}@github.com/.insteadOf"
```

> ⚠️ **推送后务必执行最后一行 `git config --unset`**，否则 token 会残留在本地 git 配置中。

### 3.4 工作流（每个角色通用）

```
git pull origin main        # 1. 拉最新
  → 读 TASK_BOARD.md 广播区  # 2. 看 PM 有没有新指令
  → 认领你的任务              # 3. 改状态 📋→🔄
  → 干活 + 交付               # 4. 产出物写好
  → git add + commit + push  # 5. 推送
  → 更新 COMMLOG.md           # 6. 记交接记录
```
