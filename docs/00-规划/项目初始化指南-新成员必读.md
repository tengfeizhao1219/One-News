## ⚠️ 重要：这是一个 AI 协作项目

**本项目由 AI 多角色协作完成，只有「用户」是真人。**

| 角色 | 代号 | 身份 | 说明 |
|------|:---:|------|------|
| **用户（你）** | 🧑 真人 | 唯一的真人 | 做最终决策、验收、提需求 |
| **产品经理** | PM 🤖 | 产品负责人 + 质量负责人 | 需求→PRD→测试→验收全链路 |
| **产品设计师** | PD 🤖 | 交互 + 视觉设计负责人 | 交互原型→视觉稿→设计规范→走查 |
| **全栈开发** | FS 🤖 | 全栈开发 + 技术负责人 | 技术方案→前后端→云函数→代码审查 |
| **小程序前端开发** | FE 🤖 | 前端开发候补 | FS 任务堆叠时按需激活，分担纯前端编码 |
| **项目经理** | PJM 🤖 | 项目总控 | 看板管理、任务分派、关口检查、上线决策 |
| **Git 管理专家** | GM 🤖 | Git 版本管理负责人 | **唯一 git 操作者**（pull/add/commit/push） |

### 🤖 AI 协作的特殊规则

1. **沟通介质是文件**：AI 角色之间通过 Git 仓库中的约定文件（TASK_BOARD.md、COMMLOG.md、RELAY.md）交换信息，没有 IM、没有会议、没有邮件。你看到的"对话"是用户与 AI 角色之间的交互界面。

2. **GM 全权代理 git 操作**：只有 **Git 管理专家（GM）** 有权执行任何 git 操作（pull/add/commit/push/merge/rebase）。其他 5 个角色（PM/PD/FS/FE/PJM）**零 git 操作**——你只需要读写工作区文件，然后写入 `.git-staging/<角色>.ready` 标记文件。GM 收到"提交"指令后统一 pull → add → commit → push。

3. **文件即通信**：每个角色完成工作后写入 staging 标记，GM 统一 push 到 GitHub。**不写 staging 标记 = 什么都没发生**。

4. **权责边界严格**：每个 AI 角色有明确的「可以做 / 不可以做」清单（见 `ROLE_CARDS.md`）。例如项目经理不写业务代码，GM 不修改业务文档内容。越权操作会被纠正。

5. **资产库同步（与 GM 完全解耦）**：所有文档和代码完成 push 后，由 PJM 独立执行 `bash sync_to_asset_library.sh` 同步到 Notion 项目资产库。**这是独立于 GitHub/GM 的并行管道**，不依赖 GM 流程，任何角色都可以通知 PJM 触发同步。详见本文 §七。

6. **对用户的沟通方式**：AI 角色与用户对话时应：
   - **直接、清晰、结构化**——用表格和列表呈现信息，避免大段叙述
   - **区分事实与建议**——先陈述客观状态，再给出建议
   - **主动提醒流转**——完成一个阶段后，提醒用户将成果交给下一环节
   - **不编造结论**——信息不足时追问，不自行脑补
   - **用"我"自称**——你是"项目经理"时就说"我"，不是第三人称"项目经理认为……"

7. **广播区优先**：每个角色在用户触发后**第一眼看 TASK_BOARD.md 的广播区**，那里有 PM 的最新指令。

## 三、Git 仓库与版本管理

### 3.1 仓库地址

```
https://github.com/tengfeizhao1219/One-News
```

公开仓库。**clone 和 pull 不需要 token。**

### 3.2 GM 全权代理模式

> ⚠️ **核心规则：只有 Git 管理专家（GM）有权执行任何 git 操作。**

| 角色 | 权限 |
|------|------|
| **GM** | git pull / add / commit / push / merge / rebase（唯一） |
| PM / PD / FS / FE / PJM | **零 git 操作**（不 pull、不 commit、不 push） |

**工作流**：

```
各角色产出文件 → 写入 .git-staging/<角色>.ready 标记
                    ↓
              用户对 GM 说「提交」
                    ↓
              GM: 修复 DNS → git pull --rebase → git add -A → git commit → git push
```

### 3.3 Token 获取方式

只有 `git push` 才需要 token（仅 GM 使用）。获取途径：

| 途径 | 位置 | 适用 |
|------|------|------|
| 📋 项目经理 | 直接索要 | 所有角色 |
| ☁️ tdrive 云盘 | 项目盘 `vault/github_pat` | 所有角色 |
| 🔐 本地保险库 | PM 会话 `/root/.secrets/github_pat` | PM 专用 |

详细说明见 `docs/共享保险库使用指南.md`。

### 3.4 Token 使用方法（GM 专用）

```bash
# 第 1 步：拉取最新（不需要 token）
git pull origin main

# 第 2 步：用 token 推送（替换 TOKEN 为实际值）
TOKEN='你的token'
git config "url.https://${TOKEN}:${TOKEN}@github.com/.insteadOf" "https://github.com/"
git -c credential.helper= push origin main
git config --unset "url.https://${TOKEN}:${TOKEN}@github.com/.insteadOf"
```

> ⚠️ **推送后务必执行最后一行 `git config --unset`**，否则 token 会残留在本地 git 配置中。

### 3.5 GitHub 拉取失败怎么办

CodeBuddy 沙箱环境可能存在 DNS 污染（`github.com` 被解析到 `198.18.0.x`）。解决方案：

```bash
# 方案一：curl resolve 直接指定 IP（推荐）
git -c http.curloptResolve=github.com:443:20.205.243.166 pull --rebase

# 方案二：尝试其他 IP
# 备选：140.82.121.3、140.82.113.3

# 方案三：设置 hosts
echo '20.205.243.166 github.com' >> /etc/hosts
git pull --rebase
```

## 七、项目资产库同步（与 GM 完全解耦）

### 7.1 是什么

项目资产库是一个 **Notion 知识库**，自动汇总所有产品文档和代码快照。它独立于 GitHub，不依赖 GM 流程。

```
GitHub（代码托管）          Notion 资产库（知识汇总）
      ↕                            ↕
   GM 负责 git                PJM 独立触发同步
      ↕                            ↕
   所有角色产出          ←——  同步内容  ——→  所有角色查阅
```

### 7.2 同步了什么

| 章节 | 内容 | 来源目录 |
|------|------|---------|

| C | 技术方案文档 | `docs/03-技术方案/` |
| D | 开发实现记录 | `docs/04-开发实现/` |
