## 1. 方案选型

### 1.1 候选方案概览

#### 方案 A：天行数据（分类新闻 API）

| 维度 | 详情 |
|------|------|
| **接口地址** | `https://apis.tianapi.com/allnews/index` |
| **请求方式** | GET/POST |
| **免费额度** | 普通会员 100 次/天，高级会员 1 万次/天（¥169/年） |
| **分类支持** | 原生支持 30+ 频道，通过 `col` 参数切换（如 col=13 科技、col=12 体育、col=10 娱乐） |
| **搜索支持** | 原生支持关键词检索，通过 `word` 参数实现 |
| **分页支持** | 原生支持 `page` + `num`（最大 50 条/页） |
| **数据时效** | 更新周期 1-24 小时 |
| **返回字段** | id, title, description, ctime, source, url, picUrl |
| **接口稳定性** | 多年稳定运营，有明确的 SLA 和状态码体系 |
| **备案要求** | 无需备案域名（云函数中转） |
| **小程序兼容** | 官方文档包含微信小程序接入指南 |

### 1.3 推荐方案及理由

**推荐方案：天行数据（方案 A）为主，聚合数据（方案 B）为备**

核心理由：

1. **搜索能力原生支持**：天行数据分类新闻 API 的 `word` 参数可直接实现关键词搜索，无需自建搜索索引。聚合数据的头条 API 不支持搜索，这是致命缺陷。
2. **分类体系丰富**：天行数据 30+ 频道远超聚合数据的 10 类，更容易匹配一页的 5 个分类（推荐/科技/体育/生活/国际）。
3. **小程序官方支持**：天行数据有专门的微信小程序接入文档和示例代码。
4. **付费路径清晰**：高级会员 ¥169/年 即可获得 1 万次/天，足够支撑日均数千 DAU。
5. **备用方案**：聚合数据作为降级备用，其 5-30 分钟更新频率更快，可在天行数据不可用时切换。

### 2.2 缓存策略

由于云函数是无状态的（每次调用可能在不同实例上运行），使用**内存缓存 + 云数据库降级缓存**双层策略：

```
┌─────────────────────────────────────────────┐
│            第一层：实例内存缓存               │
│  - 存储位置：Node.js 全局变量                │
│  - 缓存内容：最近一次 API 返回的分类新闻列表   │
│  - TTL：5 分钟（每个分类独立计时）            │
│  - 命中后：直接返回，不调用外部 API           │
│  - 优势：零延迟、无额外成本                   │
│  - 局限：云函数冷启动后失效                   │
└─────────────────────────────────────────────┘
                      │ 未命中
                      ▼
┌─────────────────────────────────────────────┐
│            第二层：云数据库缓存               │
│  - 存储位置：CloudBase 云数据库 cache 集合    │
│  - 缓存内容：每个分类最近 30 条新闻           │
│  - TTL：15 分钟（定时检查 cacheExpire 字段）  │
│  - 优势：跨实例共享、持久化                   │
│  - 局限：有数据库读取延迟                     │
└─────────────────────────────────────────────┘
                      │ 未命中
                      ▼
┌─────────────────────────────────────────────┐
│            第三层：外部 API 调用              │
│  - 调用天行数据 API 获取实时数据              │
│  - 返回结果后更新两层缓存                     │
└─────────────────────────────────────────────┘
```

**缓存 Key 设计**：
```
分类列表:  news:list:{category}:{page}
搜索缓存:  news:search:{keyword}:{page}
```

**缓存更新时机**：
- 首次调用时写入
- 5 分钟 TTL 到期后自动失效
- API 调用失败时不更新缓存（保留旧数据）

### 2.3 降级方案

```
正常流程：云函数 → 天行数据 API → 返回数据
    │
    ├── API 返回 150 (次数不足)
    │   └── 返回缓存数据 + 标记"今日配额已用完"
    │
    ├── API 超时 (>8s)
    │   ├── 第1次重试（1s后）
    │   ├── 第2次重试（2s后）
    │   └── 仍失败 → 切换备用 API (聚合数据)
    │
    ├── 主 API + 备用 API 均不可用
    │   ├── 有缓存 → 返回缓存数据 + 标记"数据可能不是最新"
    │   └── 无缓存 → 返回 code: -1, message: "新闻服务暂时不可用"
    │
    └── 连续失败 3 次
        └── 触发告警（日志记录），运维介入
```

降级决策矩阵：

| 场景 | 一级降级 | 二级降级 | 三级降级 |
|------|---------|---------|---------|
| 天行 API 超时 | 重试 2 次 | 切换聚合 API | 返回缓存/错误 |
| 天行 API 限流 | 返回缓存 | 切换聚合 API | 返回错误 |
| 聚合 API 也失败 | — | — | 返回缓存/错误 |
| 全部不可用 | — | — | 返回错误码 |

## 3. 云函数改造方案

### 3.1 getNewsList 改造设计

**改造前（当前）**：
```javascript
// 查询云数据库 news 集合
const listRes = await db.collection('news')
  .where({ category })
  .orderBy('publishTime', 'desc')
  .skip((pageNum - 1) * pageSize)
  .limit(pageSize)
  .get()
```

**改造后**：
```javascript
exports.main = async (event) => {
  const category = event.category || 'all'
  const pageNum = Math.max(1, parseInt(event.pageNum) || 1)
  const pageSize = Math.min(50, Math.max(1, parseInt(event.pageSize) || 10))

  try {
    // 1. 尝试从内存缓存获取
    const cacheKey = `news:list:${category}:${pageNum}`
    const cached = cache.get(cacheKey)
    if (cached && !cache.isExpired(cacheKey)) {
      return { code: 0, data: cached, meta: { source: 'memory_cache' } }
    }

    // 2. 尝试从云数据库缓存获取
    const dbCached = await getFromDbCache(category, pageNum, pageSize)
    if (dbCached) {
      // 写入内存缓存
      cache.set(cacheKey, dbCached, { ttl: 5 * 60 * 1000 })
      return { code: 0, data: dbCached, meta: { source: 'db_cache' } }
    }

    // 3. 调用外部 API（主：天行数据）
    const apiData = await callTianApi({ category, pageNum, pageSize })

    // 4. 数据适配
    const adapted = apiData.list.map(adaptNewsItem)
    const result = {
      list: adapted,
      total: apiData.allnum,
      hasMore: adapted.length >= pageSize
    }

    // 5. 写入双层缓存
    cache.set(cacheKey, result, { ttl: 5 * 60 * 1000 })
    await saveToDbCache(category, adapted)

    return { code: 0, data: result, meta: { source: 'api' } }

  } catch (err) {
    // 降级：尝试备用 API
    try {
      const fallbackData = await callJuheApi({ category, pageNum, pageSize })
      const adapted = fallbackData.list.map(adaptNewsItem)
      return { code: 0, data: { list: adapted, total: adapted.length, hasMore: false }, meta: { source: 'fallback_api' } }
    } catch (fallbackErr) {
      // 最终降级：返回错误
      return { code: -1, message: '新闻服务暂时不可用，请稍后重试', errorCode: 'API_UNAVAILABLE' }
    }
  }
}
```

**关键改动点**：

| 改动项 | 改造前 | 改造后 |
|--------|--------|--------|
| 数据源 | 云数据库 `news` 集合 | 天行数据 API + 聚合数据备用 |
| 缓存 | 无 | 双层缓存（内存 + 云数据库） |
| 分类参数 | 直接用于 `where({ category })` | 通过 `CATEGORY_MAPPING` 映射到 API 的 `col` 参数 |
| 分页 | `skip().limit()` | 透传 API 的 `page` + `num` 参数 |
| 错误处理 | 简单 try/catch | 重试 + 降级 + 备用 API 三级策略 |
| 返回格式 | 不变 | 不变（`{ code, data: { list, total, hasMore } }`） |

### 3.2 searchNews 改造设计

**改造前（当前）**：
```javascript
// 用正则模糊匹配云数据库
const regex = db.RegExp({ regexp: escapedKw, options: 'i' })
const query = db.collection('news').where(_.or([{ title: regex }, { summary: regex }]))
```

**改造后**：
```javascript
exports.main = async (event) => {
  const { keyword } = event
  const pageNum = Math.max(1, parseInt(event.pageNum) || 1)
  const pageSize = Math.min(50, Math.max(1, parseInt(event.pageSize) || 10))

  if (!keyword || !keyword.trim()) {
    return { code: -1, message: '缺少keyword参数' }
  }

  try {
    // 1. 检查搜索缓存
    const cacheKey = `news:search:${keyword.trim()}:${pageNum}`
    const cached = cache.get(cacheKey)
    if (cached && !cache.isExpired(cacheKey)) {
      return { code: 0, data: cached, meta: { source: 'memory_cache' } }
    }

    // 2. 调用天行数据 API（word 参数实现搜索）
    const apiData = await callTianApi({
      word: keyword.trim(),
      pageNum,
      pageSize,
      category: null  // 搜索时不限制分类
    })

    // 3. 数据适配
    const adapted = apiData.list.map(adaptNewsItem)
    const result = {
      list: adapted,
      total: apiData.allnum
    }

    // 4. 写入缓存
    cache.set(cacheKey, result, { ttl: 10 * 60 * 1000 })

    return { code: 0, data: result, meta: { source: 'api' } }

  } catch (err) {
    // 降级：天行 API 搜索不可用时，拉取列表后在云函数内做客户端搜索
    try {
      const allData = await callTianApi({ pageNum: 1, pageSize: 50, category: null })
      const filtered = allData.list.filter(item =>
        item.title.includes(keyword) || item.description.includes(keyword)
      )
      const adapted = filtered.map(adaptNewsItem)
      return { code: 0, data: { list: adapted, total: adapted.length }, meta: { source: 'client_filter' } }
    } catch (fallbackErr) {
      return { code: -1, message: '搜索服务暂时不可用，请稍后重试' }
    }
  }
}
```

**搜索降级策略**：
- **主方案**：天行 API 原生 `word` 参数搜索
- **降级方案 A**：拉取全量新闻列表（最多 50 条），在云函数内用 `String.includes()` 做客户端过滤
- **降级方案 B**：返回错误提示

### 4.1 天行数据 API 返回字段 → 前端数据模型映射

```javascript
/**
 * 天行数据 API 返回字段 → 一页前端数据模型
 *
 * API 返回字段:
 * {
 *   id: "62ac899e8fcf654a74479b4239b4651f",    // 新闻唯一ID (MD5)
 *   title: "文章标题",
 *   description: "文章描述/摘要",
 *   ctime: "2015-07-17",                        // 发布时间 (YYYY-MM-DD 或 YYYY-MM-DD HH:mm)
 *   source: "文章来源",
 *   url: "https://...",                         // 文章原始地址
 *   picUrl: "https://...",                      // 封面图片
 * }
 */
function adaptTianNewsItem(apiItem) {
  const id = String(apiItem.id || '')
  return {
    id: id,
    _id: id,
    title: apiItem.title || '[无标题]',
    summary: apiItem.description || '',
    category: mapTianChannelToAppCategory(colId),  // 根据请求时的 col 参数映射
    categoryName: getCategoryName(category),
    source: apiItem.source || '未知来源',
    publishTime: apiItem.ctime || new Date().toISOString(),
    // 扩展字段（前端暂不使用，预留）
    _url: apiItem.url || '',
    _picUrl: apiItem.picUrl || ''
  }
}
```

### 4.2 聚合数据 API 返回字段 → 前端数据模型映射

## 5. 性能优化

### 5.1 缓存时间设计

| 缓存层 | 缓存内容 | TTL | 理由 |
|--------|---------|-----|------|
| 内存缓存 | 分类新闻列表（每页） | 5 分钟 | 新闻数据 1-24 小时更新一次，5 分钟足够满足时效性 |
| 内存缓存 | 搜索结果 | 10 分钟 | 搜索频率低，缓存更久以减少 API 消耗 |
| 云数据库缓存 | 每个分类最近 30 条 | 15 分钟 | 跨实例共享，避免冷启动后全部穿透到 API |

**API 调用次数估算**（100次/天免费额度下）：

```
场景 A：无缓存（最差情况）
  - 5 个分类 × 每次翻页 = 每次用户操作消耗 1 次 API
  - 假设 DAU 100，每人平均浏览 3 页 = 100 × 3 = 300 次/天 → 超出免费额度

场景 B：有缓存（预期情况）
  - 内存缓存命中率预估 70%
  - 云数据库缓存命中率预估 20%
  - 实际 API 调用：300 × 10% = 30 次/天 → 免费额度充足
```

### 5.2 并发控制

```javascript
/**
 * 并发请求锁 - 防止同一分类重复请求
 */
const pendingRequests = new Map()

async function fetchWithLock(key, fetcher) {
  // 如果已有进行中的请求，复用其 Promise
  if (pendingRequests.has(key)) {
    return pendingRequests.get(key)
  }

  const promise = fetcher()
    .finally(() => {
      pendingRequests.delete(key)
    })

  pendingRequests.set(key, promise)
  return promise
}
```

### 5.3 分页策略

| 参数 | 值 | 说明 |
|------|---|------|
| 每页条数 | 10 条 | 保持与前端 PAGE_SIZE 一致 |
| API 请求页大小 | 20 条 | 一次从 API 拉取 2 页数据，减少 API 调用次数 |
| 最大缓存页数 | 3 页 (60 条) | 超过此范围不再缓存，避免内存膨胀 |
| 前端翻页 | 从缓存中读取 | 前 3 页无 API 调用，第 4 页起实时请求 |

### 6.2 错误处理流程

```
云函数收到请求
    │
    ├── 参数校验失败
    │   └── 返回 { code: -1, message: "参数错误", errorCode: "INVALID_PARAMS" }
    │
    ├── API 调用
    │   ├── 成功 → 正常返回数据
    │   │
    │   ├── code=150 (次数不足)
    │   │   ├── 有缓存 → 返回缓存 + warning
    │   │   └── 无缓�� → 切换备用 API
    │   │
    │   ├── code=230 (Key无效)
    │   │   └── 记录日志 → 切换备用 API → 都失败则返回 { code: -1, message: "服务配置错误" }
    │   │
    │   ├── 超时 (>8s)
    │   │   ├── 重试1 (1s后) → 成功 → 正常返回
    │   │   ├── 重试2 (2s后) → 成功 → 正常返回
    │   │   ├── 仍失败 → 切换备用 API
    │   │   └── 备用也失败 → 有缓存返回缓存，无缓存返回错误
    │   │
    │   └── DNS/网络错误
    │       └── 切换备用 API → 同上
    │
    └── 所有数据源均不可用
        └── 返回 { code: -1, message: "新闻服务暂时不可用，请稍后重试", errorCode: "ALL_DOWN" }
```
