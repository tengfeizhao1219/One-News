## 二、方案要点

### 架构概览

```
WorkBuddy 搜索新闻
    ↓ git push
GitHub (data/news.json)
    ↓ 定时触发器（每天 8:00）
refreshNews 云函数
    ↓ 写入
云数据库 news_cache
    ↓ 读取
getNewsList / searchNews
    ↓
小程序前端
```

### 核心变更

| 类型 | 文件 | 说明 |
|------|------|------|
| **新增** | `cloudfunctions/refreshNews/` | 从 GitHub 拉取 news.json 写入云数据库 |
| **新增** | `data/news.json` | GitHub 托管的新闻数据（纯 JSON） |
| **新增** | `scripts/generate-news-json.js` | 从 ai-news-cache.js 生成 news.json |
| **修改** | `cloudfunctions/getNewsList/index.js` | DB 缓存从第3层提升到第2层 |
| **修改** | `cloudfunctions/searchNews/index.js` | 新增 DB 全量搜索层 |

### 降级策略

| 场景 | 行为 | 用户影响 |
|------|------|----------|
| GitHub 不可用 | refreshNews 不写入，保留旧数据 | 无感知 |
| 云数据库无数据 | getNewsList 降级到 AI 静态缓存 | 仍能看到上次部署时的新闻 |
| 静态缓存也无数据 | 降级到外部 API | 需 API Key |
| 全部不可用 | 返回 ALL_DOWN 错误 | 看到错误页面+重试按钮 |
