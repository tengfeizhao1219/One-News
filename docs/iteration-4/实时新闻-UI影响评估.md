## 1. 新增 UI 状态

从 mock 数据切换到实时新闻 API 后，首页将面临数据异步加载的完整生命周期。以下逐一分析每种新增状态及其设计建议。

### 1.1 加载中状态

#### 1.1.1 触发场景

| 场景 | 触发时机 | 用户感知 |
|------|---------|---------|
| 首次加载 | `onLoad` → `loadNews()` 发起请求 | 白屏等待，当前为 `wx.showLoading({ title: '加载中...' })` 系统级 loading 弹窗 |
| 分类切换加载 | 侧边栏 `onCategoryChange` → `loadPanelNews()` | 面板内列表区域短暂空白 |
| 下拉刷新 | 用户主动下拉（当前未实现） | 需新增下拉刷新组件 |

#### 1.1.2 当前实现分析

当前 `home.js:49` 使用 `wx.showLoading({ title: '加载中...' })` —— 微信系统级 loading 弹窗，覆盖在页面顶部居中位置。

**问题**：
1. 系统 loading 与"一页"极简设计风格不匹配，缺少品牌感
2. 无法区分首次加载 vs 分类切换加载
3. 搜索页 `search.wxml` 没有任何加载状态处理，`onSearch` 无 loading 反馈

#### 1.1.3 方案对比

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| **A. 骨架屏** | 设计规范已定义（§2.6）；视觉延续性好；可显示内容结构 | 首次实现工作量较大；需维护 skeleton 组件 | ★★★★★ |
| B. Loading 动画 | 实现简单；即时反馈 | 与极简风格冲突；无内容结构暗示 | ★★ |
| C. 品牌过渡 | 品牌感强；可作为启动页 | 增加首屏等待时间；可能让用户感到"慢" | ★★★ |

#### 1.1.4 推荐方案：分层骨架屏策略

└─────────────────────────────────┘

**关键设计决策**：
- 首次加载用**全页骨架屏**替换 `wx.showLoading`，符合"一页"极简美学
- 分类切换用**面板内行级骨架屏**，保持分类 Tab 可交互（用户可取消等待）
- 下拉刷新用微信原生 `enablePullDownRefresh` + 自定义 loading 文案
- 搜索页搜索过程中在结果区域展示**行级骨架屏**（3 行）

### 1.2 加载失败状态

#### 1.2.1 触发场景（需求概要 §6.1）

| 场景 | 触发条件 | 用户提示文案 |
|------|---------|------------|
| 网络超时 | API 响应 > 10s | "网络开小差了，请重试" |
| 无网络连接 | DNS 解析失败 | "当前无网络连接，请检查网络设置" |
| API 不可用 | HTTP 5xx | "新闻服务暂时不可用，请稍后重试" |
| 日配额耗尽 | 免费额度用尽 | "今日阅读次数已用完，明天再来吧" |
| 首次加载失败 | 用户首次打开 | 展示空状态页 + 重试按钮 |

#### 1.2.2 当前实现分析

当前 `home.js:60-63` 仅在 catch 中调用 `wx.showToast({ title: '加载失败', icon: 'none' })`，toast 2 秒后自动消失，用户无法主动重试。侧边栏 `loadPanelNews` 同样只有 toast 无重试入口。

**问题**：
1. toast 转瞬即逝，用户不知道发生了什么
2. 无重试入口，用户只能杀进程重启
3. 不同失败原因无差异化提示
4. 与 PM 需求概要 §6.1 定义的多种错误场景差距大

#### 1.2.3 推荐方案：全页错误状态

```
【首页加载失败】
┌─────────────────────────────────┐
│                                 │
│                                 │
│            📡                   │  ← 80rpx 图标（无网络信号）
│        网络开小差了              │  ← 28rpx, var(--text-primary)
│    请检查网络后点击重试          │  ← 24rpx, var(--text-secondary)
│                                 │
│        ┌──────────┐             │
│        │   重试    │             │  ← 按钮: 28rpx, 圆角 24rpx
│        └──────────┘             │     背景 var(--text-primary)
│                                 │     文字 var(--bg-card)
│                                 │
└─────────────────────────────────┘
  背景色: var(--bg-page)
  图标: 根据错误类型切换（📡 无网络 / ⏰ 超时 / 🔒 配额用完）
```

**设计要点**：
- 错误状态保持极简风格，不使用红色/感叹号等警告式设计
- 图标使用系统 emoji（与现有 🔍 图标风格一致）
- 重试按钮使用反色设计（黑底白字 / 暗色模式白底黑字）
- 搜索页错误：在结果区域展示相同风格的内嵌错误状态（非全页）

### 1.3 数据为空状态

#### 1.3.1 触发场景（需求概要 §6.3）

| 场景 | 文案 |
|------|------|
| 某分类无数据 | "暂无新闻，下拉刷新试试" |
| 搜索无结果 | "未找到相关新闻，换个关键词试试" |
| 全部无数据 | "暂无新闻" |

#### 1.3.2 当前实现分析

- 首页卡片区：`renderCards()` 当 `total === 0` 时设置 `cards: []`，卡片舞台为空 —— **无任何提示**
- 侧边栏：`panel-empty` 仅显示 "暂无新闻"（`home.wxml:95-97`）
- 搜索页：`result-empty` 仅显示 "未找到相关新闻"（`search.wxml:41-43`）

**问题**：
1. 首页卡片区空列表时完全白屏，用户困惑
2. 侧边栏和搜索页的空状态缺少引导性文案（如下拉刷新/换关键词）
3. 空状态图标缺失，纯文字略显单薄

#### 1.3.3 推荐方案

```
【首页/侧边栏空状态】
┌─────────────────────────────────┐
│                                 │
│            📭                   │  ← 复用设计规范 §2.6 定义
│         暂无新闻                 │
│      下拉刷新试试吧              │  ← 新增引导文案
│                                 │
└─────────────────────────────────┘
```

```
【搜索空状态】
┌─────────────────────────────────┐
│                                 │
│            🔍                   │  ← 搜索放大镜图标
│      未找到相关新闻              │
│   换个关键词试试吧               │  ← 引导用户换关键词
│                                 │
└─────────────────────────────────┘
```

**设计要点**：
- 空状态复用设计规范 §2.6 已定义的布局，仅补充引导文案
- 搜索页空状态图标使用 🔍（与搜索入口一致），区别于首页的 📭
- 引导文案使用 `var(--text-secondary)` 色 + 24rpx，与现有 `panel-empty` 风格一致

### 1.4 数据过期提示

#### 1.4.1 触发场景

当 API 不可用时，云函数可能返回缓存数据作为降级（需求概要 §6.2 降级策略）。用户需要知道当前看到的是缓存数据而非实时数据。

#### 1.4.2 推荐方案

```
【缓存提示条 - 轻量横幅】
┌─────────────────────────────────┐
│ 🕐 数据更新于 30 分钟前          │  ← 顶部信息条，非阻断式
└─────────────────────────────────┘
  背景: var(--tag-bg)
  文字: var(--text-secondary), 22rpx
  位置: 卡片舞台顶部，状态栏下方
  动画: 从顶部滑入，3 秒后自动收起
  行为: 点击可触发刷新
```

**设计决策**：
- **非阻断式**：不遮挡阅读内容，仅作为信息提示
- **可交互**：点击提示条触发下拉刷新
- **自动消失**：3 秒后自动向上收起，避免长时间占据视觉空间
- **暗色模式**：背景色跟随 `var(--tag-bg)` 自动适配

## 2. 现有 UI 影响分析

### 2.1 卡片流改造评估

| 评估维度 | 当前状态 | 实时 API 后变化 | 改造必要性 |
|---------|---------|---------------|-----------|
| 卡片结构 | `home.wxml:19-48` — card-body 含 title/summary/meta | 字段映射后结构不变 | **无需改造** |
| 数据渲染 | `renderCards()` 仅渲染 3 张卡片（上/当前/下） | 逻辑不变 | **无需改造** |
| 翻页机制 | 上滑切换，到末尾停止 | 需改为到末尾触发"加载更多" | **需要改造** |
| 触底加载 | 当前无触底检测 | 需新增 `onReachBottom` 或手动检测 | **需要改造** |
| 下拉刷新 | 当前无下拉刷新 | 需新增 | **需要改造** |

**关键发现**：
- PM 需求概要 §4.2 明确"保持现有交互和动画不变"，但 US-01 要求"自动加载下一页"，这意味着**翻页逻辑需要改造**
- 当前 `swipeNext()` 到达 `newsList.length - 1` 时停止，不触发加载 —— 需要改为触底时调用 `loadMoreNews()`
- 卡片视图本身（标题/摘要/元信息布局）不受影响，仅数据来源变更

**卡片流改造建议**：

```javascript
// 当前逻辑（home.js:230-236）
swipeNext() {
  const { currentIndex, newsList } = this.data
  if (currentIndex >= newsList.length - 1) {
    // 到底了 → 应改为：加载更多
    this.renderCards(newsList, currentIndex)
    this.resetCardOffset()
    this.isAnimating = false
    return
  }
  // ...
}

// 改造后逻辑
swipeNext() {
  const { currentIndex, newsList } = this.data
  if (currentIndex >= newsList.length - 1) {
    if (this.data.hasMore) {
      // 触底加载更多
      this.loadMoreNews()
      return
    }
    // 真正到底，展示"已经到底了"（见 2.4）
    this.renderCards(newsList, currentIndex)
    this.resetCardOffset()
    this.isAnimating = false
    return
  }
  // ...
}
```

### 2.2 侧边栏分类切换加载状态评估

| 评估维度 | 当前状态 | 实时 API 后变化 | 改造必要性 |
|---------|---------|---------------|-----------|
| 切换逻辑 | `onCategoryChange` → `loadPanelNews(cat)` | 逻辑不变，数据源变化 | **无需改造逻辑** |
| 加载反馈 | 无加载状态，`loadPanelNews` 失败仅 toast | 需增加加载中/失败状态 | **需要改造** |
| 分类 Tab | 始终可交互 | 加载中应保持可交互（用户可取消） | **建议优化** |
| 空数据 | `panel-empty` 仅显示"暂无新闻" | 需增加引导文案 | **需要改造** |

**设计建议**：
- 切换分类时面板列表区显示行级骨架屏（3-4 行占位）
- 加载期间分类 Tab 保持可交互 —— 用户切换到另一个分类时取消前一个请求（需求概要 §6.5）
- 加载失败时面板列表区展示内嵌错误提示 + 重试文字按钮

### 2.3 搜索页适配评估

| 评估维度 | 当前状态 | 实时 API 后变化 | 改造必要性 |
|---------|---------|---------------|-----------|
| 搜索逻辑 | `searchNews()` 调用云函数 | 云函数改为调用外部 API | **无需改造 UI** |
| 搜索中状态 | 无 loading 状态 | 需增加搜索中 loading | **需要改造** |
| 空结果 | `result-empty` 仅显示"未找到相关新闻" | 需增加引导文案 | **需要改造** |
| 搜索失败 | 无错误处理 | 需增加错误状态 | **需要改造** |
| 防抖 | 无 | 需求概要 §6.2 要求 1s 防抖 | **逻辑层，UI 无感** |

**搜索页改造建议**：
- 输入关键词确认后，结果区域显示行级骨架屏（3 行）替代空白
- 搜索结果为空时文案改为"未找到相关新闻，换个关键词试试"
- 搜索失败时在结果区域展示内嵌错误提示"搜索失败，请重试" + 重试文字链接

### 2.4 下拉刷新 / 上拉加载更多

#### 2.4.1 下拉刷新

| 评估项 | 说明 |
|--------|------|
| 当前状态 | 未实现 |
| PM 需求 | US-01 明确要求"下拉刷新" |
| 设计建议 | 使用微信原生 `enablePullDownRefresh` + `onPullDownRefresh` |
| 刷新动画 | 顶部刷新指示器（微信原生风格或自定义 loading 圈） |
| 刷新完成后 | 平滑过渡展示新数据，当前卡片保持在第一条 |

#### 2.4.2 上拉加载更多

| 评估项 | 说明 |
|--------|------|
| 当前状态 | 无加载更多，到末尾停止 |

| 已全部加载 | 底部展示"已经到底了"（需求概要 §6.5） |

## 3. 设计建议汇总

### 3.1 UI 方案总览

| 新增状态 | 方案 | 位置 | 优先级 |
|---------|------|------|--------|
| 首次加载 | 全页骨架屏 | 首页卡片区 | P0 |
| 分类切换加载 | 面板内行级骨架屏 | 侧边栏面板列表区 | P0 |
| 搜索加载 | 行级骨架屏（3 行） | 搜索结果区 | P0 |
| 下拉刷新 | 微信原生 refresher | 首页顶部 | P0 |
| 上拉加载更多 | 底部 loading 指示器 | 卡片底部 | P0 |
| 网络错误 | 全页错误状态 + 重试按钮 | 首页卡片区 | P0 |
| API 错误 | 全页/内嵌错误状态 | 首页 / 面板 / 搜索 | P0 |
| 数据为空 | 空状态（图标+文案+引导） | 首页 / 面板 / 搜索 | P0 |
| 缓存数据提示 | 顶部轻量横幅（可点击刷新） | 首页顶部 | P1 |
| 已全部加载 | 底部"已经到底了" | 卡片底部 | P1 |

### 3.2 是否需要新增动画/动效

| 动效 | 必要性 | 说明 |
|------|--------|------|
| 骨架屏 shimmer | **必须** | 设计规范 §2.6 已定义，复用现有动画参数 |
| 错误状态淡入 | **建议** | 从 toast 切换到全页错误状态时，加 300ms opacity 过渡 |
| 缓存提示条滑入/滑出 | **建议** | 顶部滑入（300ms ease-out），3 秒后滑出（250ms ease-in） |
| 加载更多指示器出现 | **建议** | 底部从透明淡入（200ms），避免突兀 |
| 下拉刷新完成过渡 | **建议** | 刷新完成后卡片从第一张重新渲染，复用现有卡片切换动画 |

**不需要新增的动效**：
- 卡片切换动画（已有，不变）
- 侧边栏滑入/滑出（已有，不变）
- 引导遮罩（已有，不变）

### 3.3 暗色模式适配

**好消息**：设计规范 §5 已定义完整的暗色模式变量体系，所有新增 UI 状态均使用 CSS 变量，**无需额外适配**。

| 新增 UI 元素 | 使用的 CSS 变量 | 暗色模式自动适配 |
|-------------|----------------|:---:|
| 骨架屏 | `--skeletonBase`, `--skeletonShine` | ✅ |
| 错误状态背景 | `--bg-page` | ✅ |
| 错误状态文字 | `--text-primary`, `--text-secondary` | ✅ |
| 重试按钮 | `--text-primary`(bg) + `--bg-card`(text) | ✅ |
| 空状态 | `--text-primary`, `--text-secondary` | ✅ |
| 缓存提示条 | `--tag-bg`, `--text-secondary` | ✅ |
| 加载更多/已到底 | `--text-secondary` | ✅ |

**需要关注的点**：
- 重试按钮使用反色设计（`--text-primary` 作背景色），暗色模式下白底黑字，对比度足够
- 错误状态图标使用 emoji，在不同系统渲染一致，不受暗色模式影响

## 5. 结论

### 5.1 影响范围评级：**中**

**判断依据**：

| 因素 | 评估 |
|------|------|
| 核心卡片流 UI | 不需要改动（布局/动画/交互不变） |
| 新增 UI 状态数量 | 4 类主要状态（加载/错误/空/缓存），约 6-8 个具体组件 |
| 现有页面改动 | 首页（主要）+ 搜索页（次要），详情页无需改动 |
| 暗色模式适配 | 零额外工作（CSS 变量全覆盖） |
| 动画/动效 | 无需新增复杂动效，复用现有参数 |

**评级逻辑**：
- "小" = 仅文案/颜色微调
- **"中"** = 需要新增 4+ 个 UI 状态组件，但不改动核心交互
- "大" = 核心交互/布局/架构级变更

### 5.2 是否需要交互式 Demo 更新：**是**

**理由**：
- 骨架屏、错误状态、空状态、缓存提示条均为全新的 UI 模式，团队需要统一的视觉参照
- 建议更新以下 Demo 场景：
  1. 首次加载 → 骨架屏 → 数据展示（完整流程）
  2. 网络错误 → 错误状态 → 点击重试 → 成功
  3. 分类切换 → 面板骨架屏 → 数据展示
  4. 下拉刷新流程
  5. 上拉加载更多流程

### 5.3 是否需要设计规范文档更新：**是**

**理由**：
- 设计规范 §2.6 仅定义了骨架屏和空状态的基础样式，缺少以下内容：
  - 错误状态组件规范（多种错误类型）
  - 缓存提示条组件规范
  - 加载更多/已到底状态规范
  - 下拉刷新组件规范
  - 搜索页加载/错误状态规范
- 建议新增"§2.7 反馈状态"章节，涵盖上述所有新增 UI 状态
