## 二、Bug 汇总

| 编号 | 严重程度 | 所属模块 | 问题描述 | 修复方案 | 状态 |
|------|---------|---------|---------|---------|------|
| **BUG-001** | 🔴 高 | `llmSearch.js` — `parseNewsFromContent()` | LLM 返回的 JSON 数组中包含 `null` 条目时，`.map()` 中访问 `item.title` 导致 `Cannot read properties of null` 崩溃 | 在 `.map()` 前增加 `.filter(item => item != null && typeof item === 'object')` 防御 | ✅ 已修复 |
| **BUG-002** | 🔴 高 | `llmSearch.js` — `parseNewsFromContent()` | 当 LLM 返回的 `source` 字段为数字等非字符串类型时，`(item.source \|\| '未知来源').trim()` 因 `.trim()` 不是数字类型方法而崩溃 | 改为 `String(item.source \|\| '未知来源').trim()` 防御性类型转换 | ✅ 已修复 |
| **BUG-003** | 🟡 中 | `mock/simulator.js` — `simulateSearchNews()` | 空关键词搜索时，`''.includes('')` 返回 `true`，导致不过滤任何数据，返回全部结果而非空列表 | 在过滤逻辑前增加空关键词判断：`if (!kw) { resolve({ list: [], total: 0 }); return }` | ✅ 已修复 |
