## 二、搜索 API 选型对比

### 2.1 候选方案

| 方案 | 实现方式 | 新增依赖 | 中文质量 | 成本 | 结论 |
|------|---------|:---:|:---:|:---:|:---:|
| **A. 智谱 web_search（推荐）** | 复用现有 `zhipuSearch.js` 的 `tools: [{type:'web_search'}]` | 无 | 优（国产模型 + 联网搜索）| 免费（已有 2000 万 token 额度）| ✅ **首选** |
| B. Bing Web Search | 新增 `BING_API_KEY` + Azure 资源 | 需注册 Azure + 付费 | 良 | 免费档 1000 次/月，超量付费 | 备选 |
| C. 博查 BoCha | 新增 `BOCHA_API_KEY` | 需注册 + 按量付费 | 优 | ¥0.02-0.08/次 | 备选 |
| D. SerpAPI | 新增 `SERP_API_KEY` | 需注册 + 按量付费 | 良 | $0.05/次起 | 不推荐 |

### 2.2 为什么选 A

1. **已在生产验证**：`refreshNews` 当前主力数据源就是智谱 web_search（`zhipuSearch.js:295` `tools: [{type:'web_search', web_search:{enable:true, search_mode:'auto'}}]`），每日刷新稳定运行，**中文搜索结果质量已通过实际内容验证**。
2. **零新增成本**：智谱 GLM-4-Flash 永久免费 + 2000 万 token 额度；RQ-18 的调用量（预估 100-300 次/日）远在免费额度内。
3. **架构一致**：追问/总结所需的"联网搜索 + 上下文理解"正是 web_search 工具的设计用途，无需额外适配层。
4. **降级链复用**：现有 `searchWithZhipu → searchWithDeepSeek` 降级链可直接复用（DeepSeek 支持 `enable_search: true`），搜索 API 故障时自动降级，满足 AC-RQ18 #9。

### 2.3 方案 A 的实现要点

```js
// 复用 zhipuSearch.js 的 httpsRequest + web_search 工具定义，新增云函数 aiSearchMore
// F-02 自动搜索：prompt 中携带当前新闻 title + content 摘要，要求返回 JSON：
//   { summary: "...", sources: [{title, source, url, snippet}] }
// F-03 追问：prompt 携带上下文 { 原文摘要, 上次query, 上次总结, 用户问题 }
//   模型自行判断是否需要新搜索（tools 触发）或直接回答
```

## 三、成本估算

| 项 | 估算 | 说明 |
|----|------|------|
| 智谱 token | 每次搜索 ≈ 2-3k token（prompt + 结果）| 2000 万免费额度 ≈ 6.6 万次调用，日 300 次可跑 7 个月+ |
| 搜索 API | **¥0**（智谱 web_search 已含在 token 计费内）| 方案 B/C 才需额外付费 |
| DeepSeek 降级 | 仅智谱故障时触发，量极小 | 现有 `DEEPSEEK_API_KEY` |
| 云函数资源 | `aiSearchMore` 轻量函数 | 微信云开发按量计费，可忽略 |

**单用户每日上限建议**（防滥用，对齐 PRD §11）：搜索 10 次 / 追问 20 次，冷却 30s/次（复用 `config.rateLimit` 模式）。

## 四、web-view 业务域名评估

### 4.1 现状

- 小程序**当前未配置任何 web-view 业务域名**（`app.json` 无 web-view，代码无使用）。
- RQ-18 F-04「来源查看」需要 web-view 打开来源 URL。

### 4.2 配置要求

微信小程序 web-view 组件要求：业务域名必须在**微信公众平台「开发管理 → 开发设置 → 业务域名」**配置，且：
1. 域名须 **HTTPS** + ICP 备案；
2. 个人主体小程序**可配置 web-view 业务域名**（需校验文件放服务器根目录）；
3. 每次配置修改需管理员扫码确认（即时生效，无需发版）。

### 4.3 推荐域名清单（智谱搜索结果高频来源）

| 域名 | 说明 |
|------|------|
| `*.xinhuanet.com` | 新华社 |
| `*.people.com.cn` | 人民日报 |
| `*.cctv.com` | 央视 |
| `*.chinanews.com` | 中新网 |
| `*.thepaper.cn` | 澎湃 |
| `*.huanqiu.com` | 环球 |
| `*.36kr.com` / `*.huxiu.com` | 科技媒体 |
| `*.reuters.com` / `*.bbc.com` 等 | 国际（可选）|

> ⚠️ **务实建议**：新闻 URL 域名极多，**逐一配置白名单不现实**。推荐策略：
> 1. 配置 Top 10 高频中文新闻域名；
> 2. **AC-RQ18 #10 降级方案为主力**：URL 不在白名单 → `wx.setClipboardData` 复制链接 + 提示「已复制，请到浏览器打开」。
> 3. 或参考 FE-B3 既有决策（原文链接用 ActionSheet），web-view 仅作增强。

### 4.4 备选：不依赖 web-view

若业务域名申请受阻（备案/审核周期），可完全**降级为「复制链接 + 外部打开」**，不阻塞 RQ-18 主体功能（搜索+总结+追问）。

## 五、风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|------|
| 搜索 API 中文质量差 | 总结相关性低 | ✅ 方案 A 已用智谱（中文优化）；上线前抽样 10 条人工评测 |
| AI 幻觉来源 | 可信度风险 | ✅ 来源必须来自搜索结果（prompt 约束 + 后置校验 URL 格式）；标注「AI 生成」|
| 成本失控 | 预算超支 | ✅ 单用户日上限 + 30s 冷却 + 智谱免费额度监控（复用 `system_kv` 配额计数）|
| web-view 域名受限 | 原文查看受阻 | ✅ 复制链接降级（AC-RQ18 #10）|
| 搜索耗时过长 | 体验差 | ✅ 智谱超时 50s 预算内 + 前端 8s loading 优化（AC-RQ18 #2）|
