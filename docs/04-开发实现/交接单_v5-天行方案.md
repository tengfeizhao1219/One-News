## 一、本次改造背景

微信云函数默认执行超时 **3 秒**，而 v4.0 智谱/DeepSeek AI 双引擎方案单分类搜索就需要 45 秒以上，导致 `refreshNews` 每次运行都超时失败、`news_cache` 长期为空。

经产品 owner 决策，执行 **方案二**：
- `refreshNews` 改为调用 **天行数据 API**，只缓存**标题列表**（标题+摘要+封面+原文链接），确保 3 秒内完成
- `getNewsDetail` 改为**按需抓取原文**并多层清洗，用户进入详情页时再请求正文

## 三、关键变更说明

### 3.1 数据流变化

**改造前（v4.0 AI 双引擎）**：
```
refreshNews → 智谱/DeepSeek(45s+) → 生成完整 content → 写入 news_cache + news
getNewsList → 读 news_cache（含正文）
getNewsDetail → 读 news（含正文）
```

**改造后（v5.0 天行方案）**：
```
refreshNews → 天行 API(2~3s) → 标题/摘要/封面/原文链接 → 写入 news_cache + news（content 空）
getNewsList → 读 news_cache（不含正文）
getNewsDetail → 读 news → 若 content 空则抓取 sourceUrl → 清洗 → 返回并缓存 content
```

### 3.2 清洗能力

`newsCleaner.js` 实现了 7 层清洗：
1. HTML 实体解码（`&nbsp;`、`&ldquo;` 等）
2. HTML 标签/脚本/样式移除
3. 空白规范化
4. 行级噪音删除（分享引导、责任编辑、版权信息等）
5. 尾部噪音删除（文末推荐阅读等）
6. 段落规范化
7. 长度截断（默认 3000 字符）

## 六、已知风险与待决策事项

| 风险 | 说明 | 建议处理方式 |
|------|------|--------------|
| **新闻质量** | 天行 API 新闻质量可能不如 AI 生成，标题/摘要可能较生硬 | PM 验收时评估是否可接受 |
| **正文清洗不彻底** | 部分网站结构特殊，清洗后可能残留噪音 | 发现具体案例后反馈给全栈开发优化清洗规则 |
| **原文抓取超时** | 部分原文网站响应慢，3 秒内抓不完 | 已做 2.5s 超时 + summary 兜底 |
| **空窗期** | `refreshNews` 首次运行前或失败时，首页可能空白 | 这是 v4.2 以来就存在的「不降级不兜底」策略，需 PM 确认是否接受 |
| **分类对齐** | 当前 5 分类（all/tech/international/sports/life），v5.0 天行接口映射了 recommend/tech/sports/international/life/finance/entertainment | 需确认最终保留哪些分类 |
