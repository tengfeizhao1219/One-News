## 三、不完善（逻辑健壮性缺口）

### 3.1 降级链降级盲区（最严重）

1. **L2 内存缓存从未写入（确定性失效）**
   `getNewsList` 的 L2 路径仅调用 `cache.get(memoryKey)`，**全文件无任何 `cache.set` 调用**。L2 永远 miss，降级链直接跳过 L2 进入 L3。设计意图（天行成功后缓存内存以加速二次访问）未实现。

2. **L3 云库缓存数据源已停用（确定性失效）**
   L3 读取的 `news_cache` 集合由 `refreshNews` 云函数写入，而 `refreshNews` 依赖**百炼 DeepSeek 联网搜索**（`DASHSCOPE_API_KEY`）。该 Key 已于 2026-07-30 由用户决策**搁置**，故 `refreshNews` 长期失败 → `news_cache` 长期为空/过期 → L3 实际不工作。
   **结果：降级链实质退化为 L1(天行) → L4(聚合) → L5(AI 静态)，L2/L3 名存实亡。**

3. **`news` 与 `news_cache` 双集合分裂**
   - `news`（供 `getNewsDetail`）：由 `getNewsList` L1 成功后 `syncNewsToCollection` 写入；
   - `news_cache`（供 L3 读取）：由 `refreshNews` 写入。
   两套数据管道无同步，L1 的成功结果**不回流**到 L3，`refreshNews` 停摆后 L3 完全失去数据源。

### 3.2 请求层健壮性

4. **超时未 abort 底层 socket**
   `tianApi.fetchWithTimeout` / `juheApi.postWithTimeout` 超时仅 `reject` Promise，**未 `req.destroy()`**，底层 HTTP 连接可能泄漏/占用资源。

5. **无响应体大小上限**
   两个 API 封装未限制下载字节（相对地，`contentExtractor` 有 2MB 上限，但 API 层没有），异常大响应可能拖垮云函数。

6. **HTTP 非 200 未处理**
   `fetchWithTimeout` / `postWithTimeout` 不检查 `res.statusCode`，遇到 429/500 仍尝试 `JSON.parse`，可能误判为 `API_INVALID_RESPONSE` 而掩盖真实原因。

### 3.3 类型 / 逻辑 bug

7. **`tianApi` 的 `result.code === 200` 严格相等（潜在误判）**
   若天行某接口返回字符串 `"200"`，`=== 200` 失败 → 走 `errorMap` 未命中 → 抛 `API_ERROR_200` 或误判为错误，导致 **L1 主源偶发失败、频繁降级**。建议宽松比较 `Number(result.code) === 200`。

### 3.4 重试策略缺陷

8. **`callWithRetry` 不区分错误类型**
   `retries=2` 实际尝试 3 次，且对 `API_KEY_INVALID` / `API_RATE_LIMIT` 等**不应重试**的错误也重试，浪费配额与延迟。应仅对超时/网络错误重试。

### 3.5 限流缺失

9. **无全局限流 / 退避**
   天行免费版有每日/每分钟配额（如 100 次/天），聚合也有 QPS 限制。多分类轮询或并发下易触发 150（次数不足）→ 频繁降级。客户端无令牌桶/计数器保护。

### 3.6 摘要兜底可能拖慢首屏

10. **`enrichMissingSummaries` 阻塞主响应且并发无控**
    L1、L4 均 `await enrichMissingSummaries(list)`，对缺摘要且有 `sourceUrl` 的条目**并发抓外站正文**（每条 3s 超时）。若一页 10 条都无摘要，最坏延迟 ≈ 3s×批次，直接拉长首屏响应。建议：首屏先返回、摘要后台异步补；或限制并发批次数。

### 3.7 缓存无淘汰

11. **`cache.js` 的 Map 无 LRU / 最大条目限制**
    不同 `category × page` 组合持续累积，`_store` 无限增长，云函数实例内存有限，存在内存膨胀风险。

## 四、遗留事项

### 4.1 降级盲区
- L2 内存缓存功能性失效（无 `set`）；
- L3 云库缓存数据源（百炼）停用，L3 实际不工作；
- `news` / `news_cache` 双集合分裂，L1 结果不回流 L3；
- 实质降级链 = L1 → L4 → L5。

### 4.2 密钥安全
- 三 Key 环境变量接入 OK、无硬编码 ✅；
- ⚠️ 百炼 Key 已搁置，但 `refreshNews` 仍尝试调用 → 每次产生 `LLM_SEARCH_FAILED` 无谓失败与日志噪音；建议搁置期显式短路返回。

### 4.3 未覆盖异常
- **云函数层零单元测试**：现有 `单元测试报告.md` 仅覆盖 `utils/`（22 用例），`cloudfunctions/` 下所有逻辑（降级链、分类映射、摘要兜底、正文抽取）无任何单测保护；
- `tianApi` code 类型比较、`HTTP 状态码`、`socket 未 abort`、`无响应上限`、`重试不分类型`、`无限流`、`无并发控制`、`缓存无淘汰` 等（见第三节）。
