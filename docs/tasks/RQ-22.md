# RQ-22 · 意见反馈留言板

> 看板任务：`col: dev` · `role: FE` · `prio: P1` · `status: doing`
> 领取人：2号前端开发（FE-2）· 领取时间 2026-08-07 13:2x

## 一、需求来源与用户价值

- **来源**：用户直连 2026-08-07（需求池 RQ-22）
- **现状**：设置页「意见反馈」当前仅调用微信原生 `wx.openFeedback()`（无实际留言功能）
- **目标**：落地为真正的留言板——用户可评论/留言、彼此回复；作者可管理留言、标识身份、维护社区文明氛围

## 二、功能清单（需求池 L315-320）

1. **留言板主页面**：留言列表（时间流展示，内容直接展示在页面）
2. **留言/评论**：用户对功能评论留言；他人可对留言评论回复
3. **作者身份标识**：作者回复带「作者」角标
4. **作者管理**：筛选留言（时间/违规标记）、删除不友好留言
5. **内容合规审核**：提交时关键词黑名单 + AI 校验，违规跳转「文明留言公约」页

## 三、已拍板技术方案（owner 2026-08-07）

| 项 | 方案 | 备注 |
|----|------|------|
| 存储 | 微信云开发云数据库，新增 `feedback` 集合（留言+回复） | 免费额度充足（当前 ~70MB / ~2万次·月） |
| 云函数 | `feedback/list` / `feedback/create` / `feedback/reply` / `feedback/delete` | FS 实现 |
| 合规 | 关键词黑名单 + AI 校验双保险（智谱/DeepSeek，复用现有 KEY） | 个人主体无法用 `msgSecCheck`（-501001） |
| 流程 | 提交 → 关键词过滤 → AI 校验 → 均过才入库；任一违规 → 跳公约页 | |

### 5.2 交互流（草案）

- 设置页点「意见反馈」→ `wx.navigateTo` 留言板
- 留言板加载 `feedback/list`（分页时间流）
- 提交留言/回复：本地先跑关键词黑名单（前端层）→ 调 `feedback/create|reply`（云函数内再做 AI 校验）→ 成功刷新列表；被拒 → 跳公约页
- 作者回复：服务端返回 `isAuthor` → 渲染「作者」角标
- 作者管理入口：`feedback/delete`（+ 筛选）

### 5.3 接口契约（草案，待 FS 确认）

```jsonc
// feedback/list  { pageNum, pageSize } -> { list: [{id, content, nickname, isAuthor, replyTo, createdAt, status}], hasMore }
// feedback/create { content, replyTo? }  -> { ok } | { code: 'VIOLATION' }  // 违规拦截
// feedback/reply  { id, content }        -> { ok } | { code: 'VIOLATION' }
// feedback/delete { id }                 -> { ok }   // 作者权限
```
