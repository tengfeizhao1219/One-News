## 变更详情

### CHG-009：新增 sourceUrl 字段

**变更前**：新闻数据模型仅有 `source`（来源名称），无法跳转到原始新闻页面。

**变更后**：新增 `sourceUrl` 字段，存储新闻的原始 URL 链接：
- Mock 数据（36 条）每条增加 `sourceUrl` 字段
- 外部 API 适配器将 `apiItem.url` 映射为 `sourceUrl`（天行/聚合数据）
- `formatNewsItem` 统一格式化透传 `sourceUrl`
- 详情页新增「📎 查看原文」入口，点击复制链接到剪贴板
- 向下兼容：无 `sourceUrl` 时返回空字符串，不显示链接入口

**影响范围**：
- `mock/ai-news-cache.js` — 36 条数据增加 `sourceUrl: ''` 占位
- `utils/request.js` — `formatNewsItem` 增加 `sourceUrl` 字段
- `cloudfunctions/getNewsList/index.js` — DB 查询映射增加 `sourceUrl`
- `cloudfunctions/searchNews/index.js` — DB 搜索映射增加 `sourceUrl`
- `cloudfunctions/common/adapter.js` — `_url` → `sourceUrl` 重命名
- `pages/detail/detail.wxml` — 新增「查看原文」入口
- `pages/detail/detail.js` — 新增 `openSourceUrl` 方法
- `pages/detail/detail.wxss` — 新增链接样式
- `cloud-import-data.json` — 重新生成，包含 `sourceUrl`

**影响分析**：低风险变更，完全向后兼容。9 套回归测试全量通过（~605 用例）。Mock 模式下 sourceUrl 为空，详情页不显示链接入口；接入真实数据后自动展示。

### CHG-004：设计方向大改

**变更前**：传统新闻 App 布局（TabBar + 分类 Tab + 大图 Banner + 图文列表）

**变更后**：抖音式沉浸卡片流（全屏卡片 + 上下滑动 + 左滑侧边栏 + 点击详情）

**影响范围**：
- PRD v1.0 → v2.0 全面重写
- 设计规范文档全面重写
- 线框图全面重做
- 技术方案中组件树重新设计
- 已有代码（11个组件、9个页面）全部废弃重建

**影响分析**：此变更属于产品方向级调整，工作量增加约40%，但用户确认这是核心产品理念，不可妥协。

### CHG-010：百炼 DeepSeek 实时新闻接入 sourceUrl

**背景**：接入真实数据阶段，确定采用阿里百炼 DeepSeek 联网搜索（`cloudfunctions/common/llmSearch.js`）作为 refreshNews 主力数据源。实测发现原实现只让模型返回 `title/summary/source`，**未索取也未解析原文链接**，导致实时新闻链路缺失 `sourceUrl`（与 CHG-009 全链路字段不一致）。

**变更内容**：
- `llmSearch.js` 各分类 Prompt 增加 `url(原文链接)` 字段要求（system 指令强约束必须以 http/https 开头、禁止占位符）
- `parseNewsFromContent` 解析时新增 `sourceUrl: item.url || item.sourceUrl`
- `config.js` 移除硬编码的百炼 API Key，改为仅读 `process.env.DASHSCOPE_API_KEY`（密钥已存入 `/root/.secrets/bailian_api_key`，符合敏感信息管理规范）

**影响范围**：
- 实时新闻（LLM 路径）每条新闻现均携带真实原文链接
- `getNewsList` / `searchNews` 经 L2 云库读取后可透传 `sourceUrl` 至详情页"📎 查看原文"
- 部署时需在云函数环境变量中配置 `DASHSCOPE_API_KEY`

**影响分析**：
- 实测：tech / international 分类各返回 5 条，5/5 带有效 `sourceUrl`
- ⚠️ 风险：LLM 生成的 URL 可能存在部分失真（搜索结果弱时模型回退自身知识，source 显示为"你的知识库"）。URL 真实性弱于天行/聚合 API 直接返回的 `url` 字段。建议在 `refreshNews` 写入云库前增加 URL 格式/可达性校验兜底。
- 🔴 安全：原硬编码 Key 已在历史提交中暴露，建议前往阿里百炼控制台轮换该 Key。

### CHG-011：天行 allnews 接入就绪

**背景**：接入真实数据源阶段，确定天行数据 `allnews` 作为 `getNewsList` L4 主降级源（失败再降级到聚合 Juhe）。实测发现代码存在字段名不匹配与错误码缺失。

**变更内容**：
- `cloudfunctions/common/tianApi.js`：修复返回数组字段名（`result.result.newslist`，原代码误读为 `list` → 永远空列表）；错误码映射新增 `160: API_NOT_APPLIED`（尚未申请该 API）
- 天行 API Key 存入保险库 `/root/.secrets/tian_api_key`，`config.tian.apiKey` 仅读 `process.env.TIAN_API_KEY`

**影响范围**：
- 修复后 `getNewsList` L4 天行路径可正常返回新闻
- 适配器 `adaptTianNewsItem` 将天行原生 `url` 字段直接映射为 `sourceUrl`（**真实链接、零幻觉**，优于 LLM 路径）

**影响分析**：
- 实测：key 有效（HTTP 200 认证通过），适配器样例 2/2 正确产出 `sourceUrl`
- 🔶（已解决，见 CHG-012）：该天行账号**未申请 `allnews` 接口**（API 返回 `code:160 尚未申请该API`）。后续改为分类路由方案，不再依赖 allnews。

### CHG-012：天行分类路由改造（方案 B）

**背景**：CHG-011 发现 `allnews` 聚合接口未申请（code:160），且 `allnews` 还需 `col` 频道参数（实测 code:280 缺少必要参数），属于冗余且受限的入口。用户已在控制台申请一批**分类专属接口**（`generalnews/world/keji/ai/it/internet` 等）。因此将 L4 天行路径改为**按一页分类直连对应 endpoint**，彻底绕开 allnews。

**变更内容**：
- `cloudfunctions/common/config.js`：天行 `baseUrl` 由完整 endpoint `https://apis.tianapi.com/allnews/index` 改为 host 基址 `https://apis.tianapi.com`（具体路径由 `callTianApi` 按 endpoint 拼接为 `${baseUrl}/${endpoint}/index`）
- `cloudfunctions/common/tianApi.js`：`callTianApi` 入参由 `col` 改为 `endpoint`（默认 `generalnews`），URL 构造逻辑同步更新；保留 newslist 字段解析与错误码映射（含 160/280）
- `cloudfunctions/common/adapter.js`：移除 `TIAN_COL_TO_APP`/`APP_TO_TIAN_COL`（col ID 映射），新增 `APP_TO_TIAN_ENDPOINT`（一页分类 → 天行 endpoint）与 `TIAN_ENDPOINTS_AVAILABLE`（已确认可用清单）；`adaptTianNewsItem` 直接接收 app 分类字符串
- `cloudfunctions/getNewsList/index.js`：`fetchFromTianApi` 取 `APP_TO_TIAN_ENDPOINT[category]` 作为 endpoint，并把 app 分类透传给适配器
- `cloudfunctions/searchNews/index.js`：`searchViaTianApi` 改用 `generalnews` 接口 + `word` 关键词搜索
- `test/v4-regression-data-layer.js`：断言 `TIAN_COL_TO_APP` 改为断言 `APP_TO_TIAN_ENDPOINT`

**分类路由映射**（实测可用）：
| 一页分类 | 天行 endpoint | 状态 |
|----------|--------------|------|
| recommend（推荐） | `generalnews`（综合） | ✅ |
| tech（科技） | `keji`（科技） | ✅ |
| international（国际） | `world`（国际） | ✅ |
| sports（体育） | `generalnews`（兜底，tiyu 未申请） | ⚠️ |
| life（生活） | `generalnews`（兜底，无对应接口） | ⚠️ |
| all（全部） | `generalnews` | ✅ |

> 已确认可用的额外接口（暂未映射，留作扩展）：`ai`(AI) / `it`(IT) / `internet`(互联网)。
> 不可用：allnews(需 col 参数)、guonei(160 未申请)、tiyu(160 未申请)、shehui(404)。

**影响分析**：
- 实测（真实 key 探测，2026-07-29）：generalnews / world / keji / ai / it / internet 全部 code=200，每条新闻均携带真实 `sourceUrl`（来源如 163.com / ithome.com / china.com），**0 占位符**，L1 URL 校验全通过
- `getNewsList` / `searchNews` L4 天行路径现已完全跑通真实数据，原生 `url` → `sourceUrl` 零幻觉
- 回归测试 180/180 通过
- 后续若需体育/生活专属数据，需用户在天行控制台申请 `tiyu` 等接口并更新 `APP_TO_TIAN_ENDPOINT`

### CHG-013：新增独立分类「农业」「科学」

**背景**：用户补充申请天行 `nongye`(农业)、`sicprobe`(科学探索) 两个分类专属接口（实测 code=200，每条带真实 sourceUrl）。经确认采用「**新增独立分类**」方案，而非并入现有分类造成语义错位。

**变更内容**：
- `utils/constants.js`：`CATEGORIES` 新增 `{ id:'agriculture', name:'农业' }` 与 `{ id:'science', name:'科学' }`（侧边栏/首页经 `wx:for` 动态渲染，自动出现新标签；`app.js` 的 `categoryNames` 映射同步）
- `cloudfunctions/common/adapter.js`：
  - `CATEGORY_NAMES` 新增 `agriculture:'农业'`、`science:'科学'`
  - `APP_TO_TIAN_ENDPOINT` 新增 `agriculture→nongye`、`science→sicprobe`
  - `TIAN_ENDPOINTS_AVAILABLE` 新增 `nongye:'农业'`、`sicprobe:'科学探索'`
- `cloudfunctions/common/aiNewsService.js`：`CACHE_META.categories` 初始值与 `initCacheStats` 重置值均补 `agriculture:0`、`science:0`
- `test/v4-regression-integration.js`、`test/v4-regression-data-layer.js`：分类计数断言同步（6→8 / 5→7）

**数据链路**：新分类的 L3（AI 缓存）无数据 → 自动落到 **L4 天行**（nongye/sicprobe），返回真实新闻与真实 `sourceUrl`（零幻觉）。实测农业/科学各 5 条、有效 url=5、零占位符。

**未做（后续增强）**：未给新分类加 LLM 刷新 prompt。原因：`refreshNews` 写 L2 时经 `validator.VALID_SOURCES` 白名单（仅 12 家媒体）过滤，`nongye/sicprobe` 来源（如 农业新闻、IT家科学探索）会被剔除，加了 prompt 也填不进 L2，且徒增百炼调用。若需 L2 缓存与现有 5 类持平，需先扩展 `validator.js` 的 `SOURCE_DOMAIN_MAP` 白名单。

**影响分析**：
- 回归测试：data-layer 186/186、integration（getNewsList 20 + searchNews 13 + async 56）全通过
- 前端需用户在微信开发者工具中预览验证侧边栏新标签渲染（沙箱无法运行 devtools）
