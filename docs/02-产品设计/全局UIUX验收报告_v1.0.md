### 维度一：视觉一致性（最严重问题）

#### ❌ 发现 #G01：新旧页面"半成品感"

| 页面 | 当前版本 | 与 v2.0 对齐度 |
|------|----------|---------------|
| 首页列表 | 介于 v1/v2 之间 | ~40% |
| 详情页 | 接近 v2 但缺操作栏 | ~60% |
| 侧边栏菜单 | 基础实现 | ~30% |
| 浏览记录页 | **v1 旧版** | ~10% |
| 收藏页 | **v1 旧版** | ~10% |
| 设置页 | **v1 旧版** | 0% |

**影响**: 用户在不同页面间跳转时感受到明显的"拼接感"，品牌信任度受损。

**建议优先级**: P0 — 全局统一到 v2.0 是最高优先级任务。

#### ❌ 发现 #G02：色彩系统几乎失效

从 4 张截图中观察到的色彩使用：

| 颜色 | v2.0 规范要求 | 实际现状 | 差距 |
|------|-------------|---------|------|
| **品牌主色** (`--primary`) | 用于标题强调、选中态、CTA | **几乎不可见** — 整体纯黑白 | 🔴 严重 |
| **分类选中高亮** | 淡蓝高亮底 `rgba(0,122,255,0.06)`（v5.3-final） | 背景色块填充（错误方式）或无明显高亮 | 🔴 严重 |
| **收藏激活态** | 实心红心 `#FF3B30`（浅）/ `#FF453A`（暗） | 点击后不变色 | 🔴 严重 |
| **语义色（成功/警告/错误）** | Toast/提示中使用 | Toast 无背景装饰 | 🟡 中等 |
| **中性灰阶** | 5 级灰 (#1C1C1E/#6B6B70/#5E5E60/#8A8A8E/#A0A0A0) | 仅用 #333 和浅灰，缺乏层次 | 🟡 中等 |

**根因分析**: 开发阶段可能只实现了基础布局，CSS 变量/Design Token 未全面落地。

### 维度二：信息架构与导航

#### ✅ 通过项
- [x] 侧边栏菜单入口清晰（截图1：4个功能项排列合理）
- [x] 浏览记录页导航栏有返回入口（🏠 图标 + "浏览记录"标题）
- [x] 详情页元信息行存在（分类 · 来源 · 时间）

#### ❌ 发现 #G03：详情页底部信息层级混乱（截图3）

**现状**:
```
关于·反馈          ztengfei@hotmail.com    ⚙️
                  微信: jiaowotengfei
```

**问题**:
1. "关于·反馈"、邮箱、微信、设置 四个不同性质的信息堆在同一区域
2. 邮箱和微信用了下划线（看起来像链接），但在小程序内无法点击
3. **收藏❤️ 和分享↗ 操作按钮在此截图中完全缺失**
4. 字体大小选择器（大/特大/超大）直接嵌入正文底部，打断阅读流

**权威规范要求（v2.2 修正）**: 详情页底部操作栏 = 收藏 / 分享 两按钮（毛玻璃 `rgba(250,249,247,0.55)` + `blur(20px)`）；「关于·反馈 / 邮箱 / 微信」应归入**设置页「关于」组**（独立全屏页），字体调节走 `/pages/settings/` 分段控制器 + 实时预览。

**建议优先级**: P1

#### ❌ 发现 #G04：首页缺少新闻卡片元信息（截图2）

**现状**: 首页列表仅显示纯文本标题，**没有来源、时间、摘要、缩略图**。

**v2.0 规范要求**: 每条新闻应为卡片形式，包含：
- 标题（15px Regular, max-lines 2）
- 元信息行（来源 · 分类标签 · 时间）
- 可选缩略图（右置 80×80 或 120×80）

**影响**: 用户无法快速判断新闻价值，降低浏览效率。

**建议优先级**: P1

#### ❌ 发现 #G05：浏览记录页无日期分组（截图4）

**现状**: 所有记录平铺在一个长列表中，无"今天/昨天/更早"分组。

**v2.0 规范要求**: 按日期分组，每组有分组标题（13px Medium / #999）。

**建议优先级**: P2

### 维度三：交互反馈

#### ❌ 发现 #G06：分类选择器交互缺陷（截图2，复述 P0-02）

| 子项 | 当前 | 应为 |
|------|------|------|
| 选中高亮 | 背景色块填充 | **文字颜色淡淡高亮** |
| 滑动热区 | 仅文字区域 (~40px) | **整列宽度 (72px)** |
| 分类位置 | 有顶部偏移 | **紧贴标题下方顶对齐** |
| 顶部标题 | "今日新闻 全部·15条" | 格式需对齐 Demo |

#### ❌ 发现 #G07：收藏状态无视觉反馈（P1-05 复述）

点击收藏后图标颜色不变。用户无法感知操作是否生效。

#### ❌ 发现 #G08：分类切换 Toast 无样式（P1-03 复述）

切换分类时的提示文字裸露，无胶囊背景、无动画过渡。

#### ⚠️ 发现 #G09：侧边栏菜单无关闭手势（截图1）

弹出菜单后，除了点击菜单项外，**未见明确的关闭方式**（如点击遮罩层关闭、左滑关闭）。需确认是否支持遮罩点击关闭。

**建议优先级**: P2（需开发确认）

### 维度五：组件规范

#### ❌ 发现 #G12：首页列表非卡片式（截图2）

**现状**: 纯文字列表，无边框、无背景、无圆角、无阴影、无分割线。

**v2.0 要求**: 新闻条目应为卡片组件（白底/微圆角/轻阴影/内边距 16px）。

#### ❌ 发现 #G13：详情页操作栏缺失或位置异常（截图3）

截图3 底部只有"关于·反馈 + 邮箱 + 微信 + 设置"，**收藏❤️ 和分享↗ 不见踪影**。

两种可能：
1. 操作栏被字体面板挤出了可视区域（滚动后才可见）
2. 操作栏根本未实现

**建议优先级**: P0（若确实缺失）/ P1（若只是位置问题）

#### ❌ 发现 #G14：字体大小选择器嵌入方式不当（截图3）

**现状**: "字体大小 大/特大/超大" 直接嵌入详情页正文底部，每个选项带预览文字，占用大量屏幕空间。

**v2.0 建议**: 字体调节应为：
- 方案 A：设置页内的一个选项组
- 方案 B：详情页底部的紧凑横向选择器（不带预览文字，仅显示字号名称）
- 方案 C：点击标题旁的小图标触发的浮层

**当前实现的问题**:
- 打断阅读流的连续性
- 占用过多纵向空间（在小屏设备上可能占满整屏）
- 预览文字与正文混淆

**建议优先级**: P1
