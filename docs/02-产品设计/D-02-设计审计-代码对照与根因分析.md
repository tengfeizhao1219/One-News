## 二、根本原因分析

### 2.1 🔴 翻页按钮与操作栏重叠 —— UX 设计遗漏

**问题回顾**：
- `.pager-hint` 位于 `bottom: 140rpx`，高度约 80rpx
- `.detail-bottom-bar` 位于 `bottom: 0`，高度 `calc(100rpx + safe-area)`
- 两个元素都是 `position: fixed`，但 z-index 分别为 18 和 20
- 操作栏 z-index 更高，视觉上压住翻页按钮下半部

**UX 设计端的责任**：

回顾 D-02 §4.1 的底部操作栏线框图：
```
├──────────────────────────────────┤
│     🤍 收藏      │      ↗️ 分享   │
└──────────────────────────────────┘
  ↑ 毛玻璃 fixed bottom
  ↑ 栏高 100rpx + env(safe-area-inset-bottom)
```

**问题**：D-02 原型在设计底部操作栏时，**只规定了操作栏自身的规格**（高度、毛玻璃、收藏左/分享右），但**没有重新评估翻页按钮与操作栏共存时的空间关系**。

翻页按钮（`.pager-hint`）是阶段一的遗留元素，D-02 在新增底部操作栏时，应该做但没做的事：
1. ❌ 没有调整 `.pager-hint` 的 `bottom` 值，为操作栏腾出空间
2. ❌ 没有明确两个 fixed 元素的 z-index 层级关系
3. ❌ 没有在 D-02 线框图中画出翻页按钮 + 操作栏同时存在的场景

**根因定性**：**UX 设计不完整**——新增底部操作栏时，未考虑与现有翻页按钮的共处策略。

**改进措施**：
- D-02 新增 fixed 元素时，必须列出**所有同页面 fixed 元素的层级表**（元素、位置、z-index、安全间距）
- 线框图必须包含**多元素共存场景**，不能只画单个组件的理想态

### 2.2 🟡 元信息多余分隔符 —— UX 设计遗漏

**问题回顾**：
```xml
<text>{{news.source}}</text>
<text>·</text>
<text>{{news.time}}</text>
```
当 `news.time` 为空时，显示为 "大河网 ·"

**UX 设计端的责任**：

D-02 原型和线框图中，元信息的写法始终是"新华社 · 3小时前"，从未展示过时间缺失时的状态。这导致：
1. ❌ 交互原型缺少**空数据状态**的定义
2. ❌ 前端实现时按"总有时间"处理，未做条件渲染

**根因定性**：**UX 边界场景覆盖不全**——D-02 没有为元信息区域定义空数据降级规则。

**改进措施**：
- 每个数据展示区域必须定义**空/缺/异常三态**的显示规则
- 线框图模板增加「数据为空时」「数据异常时」的变体图

---

### 2.3 🟢 "← 返回" 底部按钮 —— 设计如此，非 bug

D-02 原型线框图（原始版本 v1.0，`线框图与交互原型.md` §4.1）中明确有底部返回按钮：
```
<!-- 底部返回 -->
<view class="back-bottom" bindtap="goBack">← 返回</view>
```

这是为了方便长文阅读后快速返回。D-02 阶段二设计时保留了这个元素，没有移除。属于**有意的设计决策**，不是 bug。

---

### 2.4 🟢 操作栏图标偏大 —— 视觉层问题

44rpx 图标是 D-03 视觉设计规范中确定的，属于视觉层决策。交互层不做调整。

### BUG-20260731-005 🔴 翻页按钮与底部操作栏重叠

| 项 | 内容 |
|----|------|
| **Bug ID** | BUG-20260731-005 |
