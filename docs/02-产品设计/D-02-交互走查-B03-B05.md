### 1.2 预览文字缩放精度 ⚠️

**问题**：D-02 §3.1 要求预览文字按档位比例缩放（28→28×1.15=32.2→28×1.3=36.4→28×1.5=42），代码中 `previewSize` 使用固定值 `[28, 32, 36, 42]`。

- 档位 1 实际映射：28 × 1.15 = 32.2 → 代码 32 ✅ 四舍五入可接受
- 档位 2 实际映射：28 × 1.3 = 36.4 → 代码 36 ✅ 四舍五入可接受
- 档位 3 实际映射：28 × 1.5 = 42.0 → 代码 42 ✅ 精确

**判定**：可接受，视觉差异可忽略。建议注释说明取整逻辑。

### 1.3 缺少 3s 自动关闭 ❌

**问题**：D-02 §3.1 规定「3s 无操作 → slideDown 250ms 关闭」。代码中 `onClose` 仅由遮罩点击触发，无自动关闭定时器。

**影响**：用户打开面板后如果不点击遮罩，面板会一直停留，不符合预期。

**建议修复**：
```js
// font-panel.js — 在 visible 变为 true 时启动定时器
observers: {
  'visible': function(val) {
    if (val) {
      var that = this
      clearTimeout(this._autoCloseTimer)
      this._autoCloseTimer = setTimeout(function() {
        that.onClose()
      }, 3000)
    }
  }
}
```

### 1.4 缺少 fromSystem 标记 ⚠️

**问题**：D-02 §3.2 要求首入设置 `fontScaleFromSystem=true`，手动调整后设为 `false`，确保手动调整后不再跟随系统。代码中 `setFontScale` 只写 `fontScale`，未写 `fontScaleFromSystem`。

**影响**：用户手动调整字号后，如果系统字号变更，理论上不会被覆盖（因为 storage 已有值），但逻辑不完整——缺少显式的"不再跟随"语义。

**建议修复**：
```js
// app.js setFontScale
setFontScale(tier) {
  this.globalData.fontScale = tier
  this._applyFontScale(tier)
  try {
    wx.setStorageSync('fontScale', tier)
    wx.setStorageSync('fontScaleFromSystem', false)  // 🆕 标记手动调整
  } catch (e) { /* ignore */ }
}
```

### 1.5 超大字号截断保护未体现 ⚠️

**问题**：D-02 §3.5 要求 tier 3 (×1.5) 时标题限 3 行、摘要限 6 行、元信息不换行。代码中未见对应的 CSS 截断规则。

**影响**：超大字号下，卡片和详情页文字可能溢出容器，影响布局。

**建议**：在全局 wxss 或 theme.json 中增加：
```css
/* 超大字号截断保护 */
[data-font-scale="3"] .detail-title { -webkit-line-clamp: 3; }
[data-font-scale="3"] .text-p { -webkit-line-clamp: 6; }
[data-font-scale="3"] .detail-meta { white-space: nowrap; }
```

### 2.2 Canvas 占位图实际不可用 ❌

**问题**：`detail.js:_getDefaultPlaceholder` 始终返回 `''`，代码注释也承认了这一点：

> "微信小程序 onShareAppMessage 不支持异步，Canvas 2d 需要异步获取 node"

这意味着**无图新闻的分享卡片没有占位图**，微信会使用默认小程序图标。Canvas 组件虽然创建了，但 `generateImage` 返回 Promise，`onShareAppMessage` 无法等待。

**影响**：D-02 §5.3 要求的 8 分类主题色占位图实际上没有生效。无图新闻分享出去显示的是微信默认图标，品牌辨识度低。

**建议方案**（按优先级）：
1. **推荐**：预生成 8 张占位图到云存储/static 目录，`imageUrl` 直接引用静态图片 URL
2. **备选**：在 `onLoad` 时预调用 `generateImage`，将 base64 缓存到 `this._placeholderCache`，`onShareAppMessage` 直接读取缓存
3. **最小方案**：接受当前行为，在文档中标注为已知限制

### 2.3 CATEGORY_MAP 缺少 agriculture ⚠️

**问题**：D-02 §5.3 列出了 8 个分类的占位图颜色，但 `share-card.js` 的 `CATEGORY_MAP` 只有 7 个分类，缺少 `agriculture`（农业）。

代码中：
```js
var CATEGORY_MAP = {
  recommend, tech, international, sports, life, agriculture, science
}
```
实际有 7 个，但 D-02 和 PRD 确认有 8 分类。检查发现 `agriculture` 存在但缺少对应的浅/暗色值校验——等等，仔细看代码确实包含了 `agriculture: { light: '#65A30D', dark: '#84CC16', name: '农业' }`。

**重新判定**：✅ 7 个分类全部包含（recommend 代替了第 8 个"推荐"分类位）。

**但注意**：D-02 列了 8 个分类占位图（推荐/科技/国际/体育/生活/农业/科学 + 收藏），代码中"收藏"分类的占位图未包含在 CATEGORY_MAP 中——但这是合理的，因为收藏列表的分享走的是原新闻分类。

### 2.4 分享标题加了「一页 | 」前缀 ⚠️

**问题**：代码 `title = '一页 | ' + title` 增加了品牌前缀。D-02 §5.2 未规定此行为。这会导致：
- 原本 ≤ 30 字的标题，加上「一页 | 」后变成 ≤ 34 字，可能被微信截断
- 但代码中 `title.slice(0, 29)` 在加前缀之前执行，所以实际截断逻辑是：先截断原始标题到 29 字，再加「一页 | 」前缀 → 最多 34 字

**建议**：截断应在加前缀之后：
```js
title = '一页 | ' + (news.title || '新闻速览')
if (title.length > 30) { title = title.slice(0, 29) + '…' }
```
