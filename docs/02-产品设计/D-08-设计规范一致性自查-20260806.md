## 二、核心发现：暗色兜底硬编码块（51 处，5 文件）⚠️

### 2.1 现状

各文件均存在 **「暗色模式兜底」** 块（`.page--dark` 前缀）：

```css
/* ============ 暗色模式兜底（D-07 S2 迁移：media query → .page--dark 前缀）============
   BUG-20260805-002 引入硬编码兜底（应对真机 theme.json CSS 变量偶发失效）。
   D-07 治理：删除 @media，迁移为 .page--dark 前缀……（G-02） */
.page--dark { background-color: #000000; }
.page--dark .card { background-color: #0D0D0D; }
.page--dark .card-title, ... { color: #FFFFFF; }
...
```

**分布**：home 20 处（L663-741）/ favorites 12 处（L285-325）/ settings 8 处（L278-310）/ history 7 处（L174-192）/ detail 4 处（L446-462）

### 2.2 问题定性

- **双轨并行（违反单一来源）**：这些硬编码值全部抄自 theme.json dark（注释自证：`色值来源：theme.json dark`），但**未引用 `var()`** → theme.json/app.wxss 变量块改值（如品牌色微调）时，兜底块**不跟随** → 漂移风险，正是 v13 契约测试（值一致性防漂移）要防的对象；
- **G-07 治理未完全达成**：D-07 S2 只完成了「media query → .page--dark 前缀」的**选择器迁移（G-02）**，未完成「硬编码值 → var()」的**值回归**；G-07 裸色收敛口径（70→10，8 豁免）**未覆盖兜底块**——实际裸露 51 处，远超既有结论；
- **兜底存在的理由**：BUG-20260805-002 时"真机 theme.json CSS 变量偶发失效"。D-07 S1-S4 后变量注入已改为 `app.wxss .page--dark/.page--light` 变量块（非原生 darkmode），注入路径已变。

### 2.3 建议（需 FS/FE 工程判断，PD 不直接定）

| 方案 | 内容 | 条件 |
|------|------|------|
| **A（推荐）** | 评估"真机变量偶发失效"是否已解决（app.wxss 注入稳定 + v13 契约 84/0 通过后）→ **删除 5 文件兜底块**，回归 var() 单一来源 | FS/FE 真机确认变量注入稳定 |
| **B（保守）** | 保留兜底但**纳入 v13 契约测试**（断言兜底块值与 theme.json 逐值一致），防漂移 | 真机变量仍偶发失效 |

> 🔔 **归属**：FS/FE 评估 + 执行；PD 走查结论 = **G-07 治理存在 51 处兜底硬编码残留，需闭环**。
