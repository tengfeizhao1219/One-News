## 二、D-03a：全局字号系统 `--font-scale`

### 2.1 方案设计

**核心思路**：在 `theme.json` 的 `light` / `dark` 块中新增一个 `--font-scale` 变量（值为乘数），所有 wxss 中的 `font-size` 通过 `calc()` 引用该变量。

#### 2.1.1 四档定义

| 档位 | 名称 | `--font-scale` 值 | 说明 | 对标场景 |
|------|------|-------------------|------|----------|
| 0 | 标准 | `1` | 默认，跟随当前实现 | 年轻人 / 默认 |
| 1 | 大 | `1.15` | +15% | 中年用户 |
| 2 | 特大 | `1.3` | +30% | 老花眼用户 |
| 3 | 超大 | `1.5` | +50% | 重度视力障碍 |

#### 2.1.2 theme.json 注入方案

```json
{
  "light": {
    "--bg-page": "#F5F3F0",
    "--bg-card": "#FAF9F7",
    "--text-primary": "#1C1C1E",
    "--text-secondary": "#A0A0A0",
    "--text-body": "#3A3A3C",
    "--divider": "#E8E6E1",
    "--tag-bg": "#EEECE8",
    "--tag-text": "#7A7A7A",
    "--overlay": "rgba(0, 0, 0, 0.25)",
    "--font-scale": "1"
  },
  "dark": {
    "--bg-page": "#000000",
    "--bg-card": "#0D0D0D",
    "--text-primary": "#FFFFFF",
    "--text-secondary": "#999999",
    "--text-body": "#D4D4D4",
    "--divider": "#1C1C1E",
    "--tag-bg": "#1C1C1E",
    "--tag-text": "#999999",
    "--overlay": "rgba(0, 0, 0, 0.7)",
    "--font-scale": "1"
  }
}
```

> ⚠️ **技术注意**：微信小程序的 `theme.json` 不支持动态修改 CSS 变量值。`--font-scale` 在 theme.json 中始终为 `1`（默认），**实际档位切换通过 JS 调用 `wx.setStorageSync('fontScale', N)` + 页面级 `setData` + WXML 动态 style 或 CSS class 实现**。具体实现方案由技术负责人（T-01）评估以下两种路径：
>
> - **方案 A（推荐）**：页面根节点注入 `style="--font-scale: {{scale}}"` → 子元素 `calc()` 引用
> - **方案 B**：切换全局 className（`.font-scale-0` / `.font-scale-1` ...），每档维护独立字号

#### 2.1.3 WXSS 改造范围（按页面）

| `.pager-btn text` | `font-size: 22rpx` | `font-size: calc(22rpx * var(--font-scale))` |

**不缩放的元素**（固定尺寸，不受 `--font-scale` 影响）：
- 图标类（`.refresh-icon`、`.pager-btn` 的箭头字符）
- 骨架屏占位块（`.sk-title`、`.sk-line` 等——加载态不应受字号设置影响）
- 状态图标（`.state-icon`）
- 导航指示点（`.nav-dot`）

#### 2.1.4 超大字号（档位 3：×1.5）边界保护

档位 3 下 `52rpx × 1.5 = 78rpx` 标题 + `32rpx × 1.5 = 48rpx` 摘要。需保护：

| 场景 | 问题 | 保护策略 |
|------|------|----------|
| 标题过长 + 大字号 | 3 行溢出卡片可视区 | 保持 `-webkit-line-clamp: 3`，行高改用 `calc(1.35 * var(--font-scale))` 自适应 |
| 摘要段落 + 大字号 | 正文撑破卡片 | 摘要区 `max-height: calc(50vh)` + `overflow: hidden` |
| 卡片底部留白被压缩 | 元信息与滑动提示重叠 | `.card-body` 的 `padding-bottom` 改为 `calc(48rpx * var(--font-scale))` |
| 侧边栏列表项 | 标题 2 行溢出 | 保持 `-webkit-line-clamp: 2`，`line-height` 用 `calc()` 自适应 |

**关键 CSS 片段**：
```css
/* 标题行高跟随字号缩放 */
.card-title {
  font-size: calc(52rpx * var(--font-scale));
  line-height: calc(1.35 * var(--font-scale));  /* 缩放下行高也等比放大 */
  -webkit-line-clamp: 3;  /* 保持 3 行上限 */
}

/* 摘要区最大高度保护 */
.card-summary {
  max-height: calc(55vh);  /* 防止撑爆卡片 */
  overflow: hidden;
}

/* 卡片底部间距跟随缩放 */
.card-body {
  padding: calc(120rpx * var(--font-scale))
           calc(64rpx * var(--font-scale))
           calc(48rpx * var(--font-scale));
}
```

## 三、D-03b：收藏 / 分享按钮样式

### 3.1 底部操作栏布局

详情页底部新增固定操作栏，与 PRD v2.0 §2.3 设计稿一致：

```
┌─────────────────────────────────────┐
│                                     │
│          [正文内容区]                 │
│                                     │
├─────────────────────────────────────┤
│                                     │
│     🤍 收藏      │      ↗️ 分享      │
│                                     │
└─────────────────────────────────────┘
      ↑ 毛玻璃底 + 安全区适配
```

#### 3.1.1 视觉规格

| 属性 | 值 | 说明 |
|------|-----|------|
| 栏高度 | `100rpx` + `env(safe-area-inset-bottom)` | 含安全区 |
| 背景 | `var(--bg-card)` + `backdrop-filter: blur(20px)` | 毛玻璃，浅色 `rgba(250,249,247,0.85)`、暗色 `rgba(13,13,13,0.9)` |
| 顶部分割线 | `1rpx solid var(--divider)` | 与内容区分隔 |
| 布局 | `display: flex` 均分两列 | 收藏左 / 分享右 |
| 图标尺寸 | `44rpx × 44rpx` | 点击热区 ≥ `88rpx`（2倍） |
| 文字字号 | `calc(24rpx * var(--font-scale))` | 跟随全局字号 |
| 文字颜色 | `var(--text-secondary)` | `#A0A0A0` / `#999999` |

#### 3.1.2 收藏按钮状态

| 状态 | 图标 | 颜色 | 动效 |
|------|------|------|------|
| 未收藏（默认） | 🤍 空心爱心 | `var(--text-secondary)` | — |
| 按压中 | 🤍 scale(0.9) | — | `150ms ease` |
| 已收藏 | ❤️ 实心红心 | `#FF3B30`（浅色/暗色统一） | `scale(1)→scale(1.25)→scale(1)`，`300ms ease-out` |
| 取消收藏 | ❤️→🤍 | 恢复 `var(--text-secondary)` | `150ms ease` |

> **设计决策**：已收藏态用红色 `#FF3B30` 而非跟随分类强调色——红色是「收藏/喜欢」的跨平台通用心智模型（微信收藏、Twitter Like、Instagram Save），用户无需学习。

#### 3.1.3 分享按钮

| 状态 | 图标 | 说明 |
|------|------|------|
| 默认 | ↗️ 分享图标 | `var(--text-secondary)` |
| 按压中 | scale(0.9) | `150ms ease` |
| 点击后 | 系统自动拉起微信转发面板 | `open-type="share"` |

**分享按钮与微信原生风格一致性**：
- 使用微信官方推荐图标风格（线性、2rpx 描边）

## 四、D-03c：分享卡片兜底视觉

### 4.1 问题定义

`onShareAppMessage` 返回的转发卡片需要 `imageUrl`（封面图）。当前新闻数据中约 30% 无图（来源：线框图文档）。无图时需要分类主题色占位图兜底。

### 4.2 兜底方案：分类主题色占位卡

为 5 个分类各生成一张 400×300 的纯色占位图（或使用 Canvas 动态生成），作为 `imageUrl` 的 fallback。

#### 4.2.1 分类占位色定义

| 分类 | 占位底色 | 渐变（若有条件） | 图标/文字 |
|------|---------|------------------|-----------|
| 推荐 | `#FF3B30` | `linear-gradient(135deg, #FF3B30, #FF6B6B)` | 「一页·推荐」 |
| 科技 | `#007AFF` | `linear-gradient(135deg, #007AFF, #5AC8FA)` | 「一页·科技」 |
| 国际 | `#5856D6` | `linear-gradient(135deg, #5856D6, #9B59B6)` | 「一页·国际」 |
| 体育 | `#FF9500` | `linear-gradient(135deg, #FF9500, #FFB84D)` | 「一页·体育」 |
| 生活 | `#34C759` | `linear-gradient(135deg, #34C759, #7ED321)` | 「一页·生活」 |

#### 4.2.2 实现路径（三选一，待技术负责人确认）

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| **A. 本地静态图（推荐）** | 5 张预生成的 400×300 PNG 放入 `/assets/share/` | 零运行时开销、分享秒出 | 需设计师出图、占主包体积约 15KB×5=75KB |
| **B. Canvas 动态生成** | 分享时 `wx.createOffscreenCanvas` 绘制纯色+文字 | 不占包体积、灵活 | 首次生成有延迟（约 200ms）、调试复杂 |
| **C. 纯色 dataURL** | 1×1 像素 dataURL 拉伸 | 极简 | 微信可能压缩模糊、不够精致 |

> **视觉建议**：**方案 A**（本地静态图），品质可控、性能最优。75KB 在主包 2MB 上限下可忽略。

#### 4.2.3 占位图视觉规格

```
┌─────────────────────────────────────┐
│                                     │
│          ████████████████            │
│          ██  渐变背景  ██            │  ← 400×300
│          ██            ██            │
│          ██   「一页」  ██            │  ← 白色 36px PingFang SC Bold
│          ██   ·科技·    ██            │  ← 白色 20px 半透明
│          ██            ██            │
│          ████████████████            │
│                                     │
└─────────────────────────────────────┘
```

#### 4.2.4 分享语截断保护

```javascript
// onShareAppMessage 中
const MAX_TITLE_LEN = 40;   // 微信限制约 40 个中文字
const MAX_DESC_LEN  = 80;   // 摘要截断

onShareAppMessage() {
  const news = this.data.currentNews;
  const title = news.title.length > MAX_TITLE_LEN
    ? news.title.slice(0, MAX_TITLE_LEN - 1) + '…'
    : news.title;
  const summary = (news.summary || '').slice(0, MAX_DESC_LEN);

  return {
    title: `一页 | ${title}`,
    path: `/pages/detail/detail?id=${news.id}&index=${news.index}&category=${news.category}`,
    imageUrl: news.image || this.getFallbackShareImage(news.category)
  };
}

getFallbackShareImage(category) {
  const map = {
    recommend: '/assets/share/recommend.png',
    tech:     '/assets/share/tech.png',
    world:    '/assets/share/world.png',
    sports:   '/assets/share/sports.png',
    life:     '/assets/share/life.png'
  };
  return map[category] || map.recommend;
}
```

## 五、D-03d：暗色模式兼容核查

### 5.1 当前暗色模式实现机制

项目使用**双机制并存**：

1. **theme.json 变量**（`app.wxss` 通过 `var(--bg-page)` 等引用）——主力
2. **`@media (prefers-color-scheme: dark)` 硬编码**（`app.wxss:12-42`）——真机兜底

### 5.2 兼容核查清单

| 核查项 | 文件 | 当前状态 | A-12c 评价 |

### 5.3 发现的风险项

#### ⚠️ 风险 1：`!important` 硬编码与 `--font-scale` 冲突

`app.wxss:12-42` 的暗色兜底块使用了 `!important`，会覆盖页面根节点通过 `style="--font-scale: 1.5"` 动态注入的 CSS 变量（如果未来需要动态注入颜色变量）。

**建议**：
- 短期：保持现状。`--font-scale` 不影响颜色，`!important` 不冲突。
- 长期（D-03 正式设计阶段）：将 `!important` 硬编码值迁移到 `theme.json` 的 `dark` 块，由微信原生 `darkmode` 机制接管，消除 `@media` 兜底。

#### ⚠️ 风险 2：`.swipe-hint` 暗色值不在 theme.json

```css
/* app.wxss:32 */
.swipe-hint { color: #666666 !important; }
```

`#666666` 不在 `theme.json` 的任何变量中。如果设计规范中暗色辅助文字是 `#999999`（`--text-secondary`），这里应该统一。

**建议**：改为 `color: var(--text-secondary) !important;`（保持 `!important` 兜底但引用变量）。

#### ⚠️ 风险 3：新增底部操作栏的暗色适配

底部操作栏（§三）使用了 `backdrop-filter: blur()`，暗色下背景为 `rgba(13,13,13,0.9)`。这需要确认微信小程序真机是否支持 `backdrop-filter`（已知部分 Android 机型不支持）。

**建议**：提供 fallback：
```css
.bottom-bar {
  background-color: var(--bg-card);  /* fallback */
}
@supports (backdrop-filter: blur(20px)) {
  .bottom-bar {
    background-color: rgba(250, 249, 247, 0.85);
    backdrop-filter: blur(20px);
  }
}
```

#### ✅ 通过项：分类强调色暗色兼容

5 分类强调色（`#FF3B30`、`#007AFF`、`#5856D6`、`#FF9500`、`#34C759`）在暗色背景下均有 ≥ 4.5:1 对比度（白底黑字标准），无需暗色变体。
