## 一、背景与目标

### 1.1 背景

设置页「意见反馈」当前仅调用微信原生 `wx.openFeedback()`（官方反馈入口），**无实际留言/互动能力**，用户无法在 App 内针对功能留言或与产品作者沟通。

### 1.2 产品目标

1. **打通双向沟通**：用户可对功能评论/留言，内容直接展示在页面，形成社区感；
2. **作者可控**：作者可回复（带身份标识）、筛选、删除不友好留言，维护社区氛围；
3. **合规兜底**：留言提交自动进行内容合规检查（文明/涉黄等），违规引导至「文明留言公约」。

### 1.3 非目标（Non-goals）

- ❌ 不做用户注册/登录体系（匿名 + openid 标识）
- ❌ 不做留言点赞/置顶/话题分类（后续迭代可扩展）
- ❌ 不做富文本/图片/语音留言（纯文本）
- ❌ 不做消息推送通知（被回复不主动提醒）
- ❌ 不做多级管理员角色（仅产品作者一个管理身份）

## 二、用户故事（标准格式）

- **作为** 普通用户，**我希望** 在设置页进入意见反馈留言板并提交留言，**以便** 反馈对功能的建议/问题。
- **作为** 普通用户，**我希望** 看到自己的留言与其他用户的留言直接展示在页面，**以便** 了解他人的反馈并参与讨论。
- **作为** 普通用户，**我希望** 对某条留言进行评论回复（支持楼中楼嵌套），**以便** 深入讨论。
- **作为** 产品作者，**我希望** 回复留言时带上「作者」角标，**以便** 用户识别官方身份。
- **作为** 产品作者，**我希望** 筛选/删除不友好留言，**以便** 维护社区文明氛围。
- **作为** 系统，**我希望** 对每条留言做合规检查（关键词黑名单 + AI 校验），**以便** 拦截涉黄/违规内容；**如果** 违规，跳转「文明留言公约」页面。

## 三、功能范围

### 3.1 In-Scope（本期）

| # | 功能 | 说明 |
|---|------|------|
| F1 | 留言板主页面 | 留言列表（时间流倒序展示，内容直接展示） |
| F2 | 留言提交 | 用户可发留言；纯文本；仅限频（30s/条），不限字数 |
| F3 | 评论回复 | 支持**多级嵌套**（楼中楼），回复展示在对应留言下 |
| F4 | 作者角标 | 作者回复时昵称旁显示「作者」角标 |
| F5 | 作者管理 | 筛选留言（按时间/违规标记）+ 删除不友好留言 |

| F7 | 文明留言公约页 | 新页面：公约文案 + 违规提示 + 返回 |

### 3.2 Out-of-Scope（后续可扩展）

- 留言点赞 / 举报 / 置顶 / 分话题板块
- 图片/语音/富文本留言
- 被回复推送通知
- 多级管理角色 / 用户封禁体系

## 四、详细功能设计

### 4.1 页面结构

```
设置页
 └─「意见反馈」入口（现有 onFeedback 改为 navigateTo 留言板页）
     └─ pages/feedback/feedback（留言板主页面）
         ├─ 顶部：标题「意见反馈」+ 返回
         ├─ 留言输入区（底部固定）：文本框 + 发送按钮 + 30s 冷却提示
         ├─ 留言列表（scroll-view，倒序）：
         │    ├─ 留言卡片：昵称（作者角标）+ 时间 + 内容
         │    ├─ 展开回复（嵌套列表）：回复卡片（昵称/作者角标 + 时间 + 内容）
         │    └─ 回复输入框（点击「回复」展开）
         └─ （作者专用）每条留言「删除」按钮 + 顶部「筛选」入口
 └─ pages/feedback/rules（文明留言公约页，违规跳转）
```

### 4.2 关键流程

#### 流程 1：用户提交留言

```
用户输入内容 → 点「发送」
  → ① 前端 30s 限频校验（本地记录最近提交时间）
  → ② 调 feedback/create（云函数）
       ├─ 关键词黑名单过滤（云函数内本地词库）
       │    ├─ 命中 → 返回 code=BLOCKED → 前端跳转「文明留言公约」页
       │    └─ 未命中 → 继续
       ├─ AI 校验（智谱/DeepSeek 文本审核）
       │    ├─ 违规 → 返回 code=BLOCKED → 前端跳转「文明留言公约」页
       │    ├─ 合规 → 入库 status='visible'
       │    └─ ⚠️ AI 超时/失败 → **仅黑名单兜底放行**（owner 决策：AI 失败不再单独拦截）
  → ③ 成功 → 刷新列表，新留言置顶
```

#### 流程 2：作者管理

```
作者打开留言板
  → 每条留言可见「删除」按钮（openid 白名单判断 isAuthor）
  → 删除 → feedback/delete → 软删除（status='deleted'，对普通用户不可见）
  → 顶部「筛选」：全部 / 仅我的回复 / 违规标记（可选，见待确认 Q）
```

### 4.3 身份与权限

| 角色 | 识别方式 | 权限 |
|------|---------|------|
| 普通用户 | 云函数 `cloud.getWXContext().OPENID`（匿名）| 发留言、回复、浏览 |
| 产品作者 | **openid 白名单**（云函数环境变量/配置）| 作者角标 + 删除 + 筛选 |

**昵称生成**：首次留言时系统生成「微信用户 + 随机 4 位」（如「微信用户 8a3f」），存入留言记录；后续同 openid 复用。

### 4.4 内容合规设计（关键词黑名单 + AI 校验）

| 层 | 实现 | 位置 |
|----|------|------|
| ① 关键词黑名单 | 违规词库（涉黄/涉政/暴力/辱骂/广告等） | 云函数内置常量（初版）+ 云端集合可扩展（后续）|
| ② AI 校验 | 智谱 GLM-4-Flash 文本审核（复用 `ZHIPU_API_KEY`），失败降级 DeepSeek | 云函数 feedback/create 内 |
| 降级策略 | **AI 超时/失败 → 仅黑名单兜底放行**（owner 已确认）| — |
| 违规结果 | `BLOCKED` → 前端跳转「文明留言公约」页 | — |

## 五、数据设计

### 5.1 云端集合 `feedback`

| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | string | 自动 |
| `parentId` | string | 父留言 ID；`null` = 顶层留言，非空 = 回复（支持嵌套）|
| `rootId` | string | 顶层留言 ID（楼中楼归属）|
| `content` | string | 内容（纯文本）|
| `openid` | string | 提交者 openid（云函数写入）|
| `nickname` | string | 展示昵称（微信用户+随机）|
| `isAuthor` | bool | 是否作者（回复时 true）|
| `status` | string | `visible` / `deleted`（软删除）|
| `createdAt` | number | 时间戳（毫秒）|
| `updatedAt` | number | 更新时间戳 |

**查询**：列表 = `where(rootId=null, status='visible')` 按 createdAt 倒序；回复 = `where(rootId=留言id, status='visible')` 正序。

### 5.2 云函数

| 函数 | 入参 | 出参 |
|------|------|------|
| `feedback/create` | `{content, parentId?}` | `{code, data}`；`BLOCKED` 时返回违规标记 |
| `feedback/list` | `{pageNum, pageSize, filter?}` | `{code, data:{list,total}}` |
| `feedback/delete` | `{id}`（校验 isAuthor）| `{code}` |
| （可选）`feedback/reply` | 复用 create（parentId 非空）| — |

> 建议：create 一个函数处理「留言+回复」（parentId 区分），减少函数数量。

## 七、风险与合规

| 风险 | 等级 | 缓解 |
|------|:---:|------|
| UGC 内容违规 | 🔴 高 | 关键词黑名单 + AI 校验双保险；违规不入库；公约页引导 |
| AI 审核失败窗口 | 🟡 中 | 黑名单兜底 + 后续可补「人工复核」|
| 个人主体限制 | 🔴 高 | 不依赖 msgSecCheck；用智谱/DeepSeek 文本审核替代 |
| 昵称冒充作者 | 🟡 中 | 作者角标由 openid 白名单判断，不可伪造 |
| 恶意刷留言 | 🟡 中 | 30s 限频 + 长度限制（可选 maxLength）|
| 数据量增长 | 🟢 低 | 单用户 demo 量级，免费额度足够 |
