## 1. 背景与目标

### 1.1 背景
阶段一已完成需求规划与评审（GATE-1 通过），产品定位、用户画像、竞品差异化维持不变。当前线上已具备：首页卡片流、详情页**同分类**上下滑连续阅读、五层降级真实数据、refreshNews 自动更新、暗色模式。

但在**需求梳理与代码核对**中发现：阶段二缺乏对应 PRD，且 RQ-01/RQ-03/RQ-04/RQ-07/RQ-10 等仅停留在需求池"一句话 EARS 要点"，无 PRD 级设计；同时 RQ-01 的"同分类翻页"其实**已实现**，真正缺口是"跨分类衔接"。本 PRD 补全上述未完成设计，作为 D-02 交互/视觉 与 T-01 技术方案的输入。

### 1.2 目标
- 闭环核心阅读体验：详情页支持**跨分类连续阅读**（RQ-01）。
- 补齐基础交互增强：字体调节（RQ-04）、收藏（RQ-03）、分享（RQ-07）。
- 守住合规底线：在内容入库链路接入**微信内容安全 API**（RQ-10，P0）。
- 为弱网与回看场景预留离线缓存（RQ-05）、阅读历史（RQ-06）概要设计（P2）。

### 1.3 成功指标（北极星）
- 详情页"看完一条→下一条"路径无需返回首页即可完成（跨分类）。
- 合规内容 100% 经内容安全 API 校验后入库。
- 字体/收藏/分享功能渗透率（使用过至少一次的用户占比）≥ 30%（上线 2 周后）。

## 5. 功能详细设计

### 5.1 RQ-01 阅读模式·跨分类衔接（P0）

> **范围校正**：`detail.js` 已实现**同分类**上下滑（`pageTo` + `positionText` + 上/下一篇），本期限"跨分类衔接"——滑到末尾自动接下一分类首条，无需返回首页。

**核心行为（EARS）**
- **WHEN** 用户在详情页上滑且当前处于本分类**最后一条**
- **THEN THE SYSTEM SHALL** 加载并展示**下一分类的首条**（跨分类切换），位置指示更新为「1 / N（下一分类）」。
- **WHILE** 阅读模式激活 **THE SYSTEM SHALL** 维持分类上下文与进度指示，且**不**阻断子元素 tap（复用首页 WXS 纯 ES5 红线，禁止 `return false`）。
- **IF** 网络不可用且目标分类本地无缓存 **THEN THE SYSTEM SHALL** 展示「网络开小差，下拉重试」而非空白，并停在最后一条。
- **IF** 已是全部分类的最后一条 **THEN THE SYSTEM SHALL** 展示「已经是最后一条」边界提示。

**方案选项（待技术负责人 T-01 定夺）**
| 方案 | 做法 | 取舍 |
|------|------|------|
| A（推荐） | 进入详情时，`globalData.detailContext` 由"单分类 list"扩展为"全分类合并的有序列表"（按 constants 顺序拼接各分类前 N 条），翻页即在同一列表上移动 | 体验最连贯；首屏需预拉多分类，注意流量/性能 |
| B | 到达末尾时按需 `getNewsList(nextCategory)` 拉下一分类首条 | 流量省；衔接处有短暂加载，体验略断 |

**交互/边界**
- 进度指示从「3 / 20」升级为「3 / 20 · 科技」（显示当前分类名）。
- 跨分类衔接动画复用现有 `out-up/in-up`。
- 回写阅读位置逻辑（`goBack` 已写 `_detailReturnState`）需兼容跨分类索引。

**依赖/风险**：依赖 T-01 给出列表组织与分页数据方案；技术负责人主导，产品据此定验收细则。

### 5.2 RQ-10 内容合规审核（P0）

> 现状：`common/validator.js` 仅做字段完整性/来源白名单/垃圾词/URL 占位符检测，**未接微信内容安全 API**。违规内容（政治敏感、色情、暴力等）可致小程序下架，影响极高。

**核心行为（EARS）**
- **IF** 待入库新闻命中微信内容安全 API（msgSecCheck 文本 / imgSecCheck 图片）拒识
- **THEN THE SYSTEM SHALL** 拦截该条、记录日志并告警，**不**写入 `news_cache`。
- **WHERE** 新闻含图片 **THE SYSTEM SHALL** 对图片一并做 `imgSecCheck`。
- **WHILE** 内容安全 API 不可用（超时/限频） **THE SYSTEM SHALL** 采用"保守策略"：该批内容暂缓入库并告警，待 API 恢复后重试，而非绕过校验直接入库。

**设计要点**
1. **落点**：在 `refreshNews` 的 `validateAndClean` 之后、`batchInsert` 之前，串行调用内容安全 API（与现有 validator 互补：validator 管"质量/来源"，内容安全 API 管"违规"）。
2. **实现路径**：云函数中通过 `cloud.callContainer`/微信服务端 `imgSecCheck`/`msgSecCheck` 接口（或经 `access_token`）调用；批量内容建议异步队列 + 失败重试。
3. **日志与告警**：命中记录 `sync_logs`（含命中类型、来源、时间）；超阈值告警至运维通道。
4. **兜底**：保留现有 validator 作为第一道低成本防线；内容安全 API 为第二道强约束。

**风险**：内容安全 API 有 QPS/配额限制，需在 T-01 评估批量调用的限频与成本；敏感词兜底与 API 结果冲突时以"拦截"为准。

### 5.3 RQ-04 字体大小调节（P1）

**核心行为（EARS）**
- **WHILE** 用户设置大字号 **THE SYSTEM SHALL** 全局应用并记忆（写入本地存储）。
- **WHEN** 用户首次进入 **THEN THE SYSTEM SHALL** 跟随系统字体设置（不强制覆盖）。
- **WHEN** 用户调整字号 **THEN THE SYSTEM SHALL** 即时生效，无白屏/闪烁。

**设计要点**
- 在 `theme.json` 既有颜色 CSS 变量基础上，**新增字号变量**（如 `--font-scale`），首页卡片、详情正文、侧边栏列表统一引用。
- 提供 3–4 档（标准 / 大 / 特大 / 超大），入口：详情页或首页"设置"浮层（建议复用左滑面板增加"设置"区）。
- 记忆：`wx.setStorageSync('fontScale', x)`；启动时读取并注入 `globalData`，各页 `onShow` 同步。
- 兼容性：与暗色模式同属全局样式系统，避免互相覆盖。

**边界**：超大字号下标题/摘要换行与卡片布局需做截断与行高保护（可参考 v13 标题截断加固）。

### 5.4 RQ-03 收藏功能（P1）

> 现状：详情页 `detail.wxml` 无收藏入口与逻辑。无登录体系。

**核心行为（EARS）**
- **WHEN** 用户点击收藏 **THEN THE SYSTEM SHALL** 将该条加入收藏列表并本地持久化，按钮态变为"已收藏"。
- **WHERE** 用户进入收藏列表 **THE SYSTEM SHALL** 展示其收藏项，点击可回看详情。
- **IF** 用户再次点击已收藏项 **THEN THE SYSTEM SHALL** 取消收藏。
- **WHILE** 网络不可用 **THE SYSTEM SHALL** 仍可读本地收藏（本地优先）。

**设计要点（本地优先方案，待技术负责人确认 Q-04）**
1. **存储**：本期 `wx.setStorageSync('favorites', [{id, title, category, addedAt}])`，无登录即可用。
2. **入口**：详情页底部操作栏新增「🤍 收藏 / ❤️ 已收藏」（与分享并列，呼应 PRD v2.0 §2.3 设计稿）。
3. **收藏列表**：建议复用左滑侧边栏新增"收藏"分类 Tab，或在面板顶部加"我的收藏"入口；**不本期新建独立页面**（控制范围）。
4. **后续**：云端 openid 同步作为下迭代，保证换设备不丢。

**依赖**：Q-04 存储方案（本地 vs 云端 openid）由技术负责人确认；产品建议本地优先。

### 5.5 RQ-07 分享功能（P1）

**核心行为（EARS）**
- **WHEN** 用户点击分享 **THEN THE SYSTEM SHALL** 调起微信转发卡片（标题 + 摘要 + 封面图）。
- **WHERE** 用户从转发卡片进入 **THE SYSTEM SHALL** 直达对应新闻详情。

**设计要点**
1. 详情页底部操作栏新增「↗️ 分享」；实现 `Page.onShareAppMessage` 返回 `{ title, path: 'pages/detail/detail?id=...&index=...&category=...', imageUrl }`。
2. 封面图：优先 `picUrl`，缺失用分类主题色占位图。
3. 分享语：标题 + 一句摘要（≤ 推荐字数，避免被截断）。
4. 可顺带开通「分享到朋友圈」（`onShareTimeline`，可选）。

**边界**：无图新闻的分享卡片样式需有兜底视觉。

---

### 5.6 RQ-05 离线/弱网缓存（P2，概要）

- **WHILE** 网络不可用 **THE SYSTEM SHALL** 展示已缓存新闻列表（首页列表 + 已读详情写入本地）。
- **WHEN** 恢复网络 **THEN THE SYSTEM SHALL** 静默补充新内容，不打断阅读。
- 概要：依赖 `wx.setStorageSync` 缓存 `getNewsList` 结果与详情；与 RQ-01/RQ-03 共用本地存储层，建议统一封装 `localCache`。

### 5.7 RQ-06 阅读历史（P2，概要）

- **WHEN** 用户打开一条新闻 **THEN THE SYSTEM SHALL** 记录已读（id + 时间）至本地。
- **WHERE** 用户查看历史 **THE SYSTEM SHALL** 展示时间倒序列表，支持「接着看」。
- 概要：与 RQ-03 共享存储层（合并规划），避免重复建设。

## 8. RQ-13 搜索重建（已砍掉，方案留档仅供参考）

> 实况：搜索**整体缺失**（无 `pages/search`、无 `searchNews` 云函数、request.js 无接口）。CONTEXT 标注"搜索页 ✅"为误标。

**建议方案（供开发/项目经理决策）**
- **前端**：新增 `pages/search/search`（在 `app.json` 注册），含搜索框 + 结果列表（可复用卡片样式）。
- **云函数**：新增 `searchNews`，对 `news_cache` 做标题/摘要模糊查询（或复用 `getNewsList` 加 keyword 参数）。
- **入口**：首页增加搜索入口（导航栏或面板顶部）。
- **决策点**：用户已拍板**不做搜索**，本节方案留档备用，不再排期。
