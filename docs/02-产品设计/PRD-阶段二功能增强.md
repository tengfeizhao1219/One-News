## 1. 背景与目标

### 1.1 背景
阶段一已完成需求规划与评审（GATE-1 通过），产品定位、用户画像、竞品差异化维持不变。当前线上已具备：首页卡片流、详情页**同分类**上下滑连续阅读、五层降级真实数据、refreshNews 自动更新、暗色模式。

但在**需求梳理与代码核对**中发现：阶段二缺乏对应 PRD，且 RQ-01/RQ-03/RQ-04/RQ-07/RQ-10 等仅停留在需求池"一句话 EARS 要点"，无 PRD 级设计；同时 RQ-01 的"同分类翻页"其实**已实现**，真正缺口是"跨分类衔接"。本 PRD 补全上述未完成设计，作为 D-02 交互/视觉 与 T-01 技术方案的输入。

### 1.2 目标
- 闭环核心阅读体验：详情页支持**跨分类连续阅读**（RQ-01）。
- 补齐基础交互增强：字体调节（RQ-04）、收藏（RQ-03）、分享（RQ-07）。
- 守住合规底线：在内容入库链路接入**微信内容安全 API**（RQ-10，P0）。
- **【v1.1 新增】浏览记录**：用户可查看近 7 天浏览历史，支持"接着看"（RQ-06，升级 P1）。
- **【v1.1 新增】数据保留分级**：收藏/分享新闻数据库保留 30 天，普通新闻保留 7 天，过期自动清理（RQ-16，P0）。
- **【v1.1 新增】收藏上云**：收藏数据从纯本地升级为云端同步，换设备不丢（RQ-03 增强）。
- **【v1.2 新增】全局返回主页入口**：在所有非首页页面（详情页、浏览记录页、收藏列表页等）固定位置提供"返回主页"图标，用户一键跳转首页，无需逐层回退（RQ-17）。
- 为弱网场景预留离线缓存（RQ-05）概要设计（P2）。

### 1.3 成功指标（北极星）
- 详情页"看完一条→下一条"路径无需返回首页即可完成（跨分类）。
- 合规内容 100% 经内容安全 API 校验后入库。
- 字体/收藏/分享功能渗透率（使用过至少一次的用户占比）≥ 30%（上线 2 周后）。
- **【v1.1】浏览记录入口点击率 ≥ 15%（DAU 基准）**。
- **【v1.1】收藏/分享内容 30 天保留无丢失；普通内容 7 天过期清理率 100%**。
- **【v1.2】"返回主页"入口点击率 ≥ 10%（非首页 PV 基准）**。

## 5. 功能详细设计

### 5.1 RQ-01 阅读模式·跨分类衔接（P0）

> **范围校正**：`detail.js` 已实现**同分类**上下滑（`pageTo` + `positionText` + 上/下一篇），本期限"跨分类衔接"——滑到末尾自动接下一分类首条，无需返回首页。

**核心行为（EARS）**
- **WHEN** 用户在详情页上滑且当前处于本分类**最后一条**
- **THEN THE SYSTEM SHALL** 加载并展示**下一分类的首条**（跨分类切换），位置指示更新为「1 / N（下一分类）」。
- **WHILE** 阅读模式激活 **THE SYSTEM SHALL** 维持分类上下文与进度指示，且**不**阻断子元素 tap（复用首页 WXS 纯 ES5 红线，禁止 `return false`）。
- **IF** 网络不可用且目标分类本地无缓存 **THEN THE SYSTEM SHALL** 展示「网络开小差，下拉重试」而非空白，并停在最后一条。
- **IF** 已是全部分类的最后一条 **THEN THE SYSTEM SHALL** 展示「已经是最后一条」边界提示。

**方案选项（待技术负责人 T-01 定夺）**
| 方案 | 做法 | 取舍 |
|------|------|------|
| A（推荐） | 进入详情时，`globalData.detailContext` 由"单分类 list"扩展为"全分类合并的有序列表"（按 constants 顺序拼接各分类前 N 条），翻页即在同一列表上移动 | 体验最连贯；首屏需预拉多分类，注意流量/性能 |
| B | 到达末尾时按需 `getNewsList(nextCategory)` 拉下一分类首条 | 流量省；衔接处有短暂加载，体验略断 |

**交互/边界**
- 进度指示从「3 / 20」升级为「3 / 20 · 科技」（显示当前分类名）。
- 跨分类衔接动画复用现有 `out-up/in-up`。
- 回写阅读位置逻辑（`goBack` 已写 `_detailReturnState`）需兼容跨分类索引。

**依赖/风险**：依赖 T-01 给出列表组织与分页数据方案；技术负责人主导，产品据此定验收细则。

### 5.2 RQ-10 内容合规审核（P0）

> 现状：`common/validator.js` 仅做字段完整性/来源白名单/垃圾词/URL 占位符检测，**未接微信内容安全 API**。违规内容（政治敏感、色情、暴力等）可致小程序下架，影响极高。

**核心行为（EARS）**
- **IF** 待入库新闻命中微信内容安全 API（msgSecCheck 文本 / imgSecCheck 图片）拒识
- **THEN THE SYSTEM SHALL** 拦截该条、记录日志并告警，**不**写入 `news_cache`。
- **WHERE** 新闻含图片 **THE SYSTEM SHALL** 对图片一并做 `imgSecCheck`。
- **WHILE** 内容安全 API 不可用（超时/限频） **THE SYSTEM SHALL** 采用"保守策略"：该批内容暂缓入库并告警，待 API 恢复后重试，而非绕过校验直接入库。

**设计要点**
1. **落点**：在 `refreshNews` 的 `validateAndClean` 之后、`batchInsert` 之前，串行调用内容安全 API（与现有 validator 互补：validator 管"质量/来源"，内容安全 API 管"违规"）。
2. **实现路径**：云函数中通过 `cloud.callContainer`/微信服务端 `imgSecCheck`/`msgSecCheck` 接口（或经 `access_token`）调用；批量内容建议异步队列 + 失败重试。
3. **日志与告警**：命中记录 `sync_logs`（含命中类型、来源、时间）；超阈值告警至运维通道。
4. **兜底**：保留现有 validator 作为第一道低成本防线；内容安全 API 为第二道强约束。

**风险**：内容安全 API 有 QPS/配额限制，需在 T-01 评估批量调用的限频与成本；敏感词兜底与 API 结果冲突时以"拦截"为准。

### 5.3 RQ-04 字体大小调节（P1）

**核心行为（EARS）**
- **WHILE** 用户设置大字号 **THE SYSTEM SHALL** 全局应用并记忆（写入本地存储）。
- **WHEN** 用户首次进入 **THEN THE SYSTEM SHALL** 跟随系统字体设置（不强制覆盖）。
- **WHEN** 用户调整字号 **THEN THE SYSTEM SHALL** 即时生效，无白屏/闪烁。

**设计要点**
- 在 `theme.json` 既有颜色 CSS 变量基础上，**新增字号变量**（如 `--font-scale`），首页卡片、详情正文、侧边栏列表统一引用。
- 提供 3–4 档（标准 / 大 / 特大 / 超大），入口：详情页或首页"设置"浮层（建议复用左滑面板增加"设置"区）。
- 记忆：`wx.setStorageSync('fontScale', x)`；启动时读取并注入 `globalData`，各页 `onShow` 同步。
- 兼容性：与暗色模式同属全局样式系统，避免互相覆盖。

**边界**：超大字号下标题/摘要换行与卡片布局需做截断与行高保护（可参考 v13 标题截断加固）。

### 5.4 RQ-03 收藏功能（P1，v1.1 升级为本地+云端双写）

> 现状：详情页 `detail.wxml` 无收藏入口与逻辑。无登录体系。
> **v1.1 变更**：收藏从"纯本地（localCache 200 条上限）"升级为"本地 + 云端双写"，解决换设备丢失问题。

**核心行为（EARS）**
- **WHEN** 用户点击收藏 **THEN THE SYSTEM SHALL** 将该条加入收藏列表并**同时写入本地缓存和云端 `favorites` 集合**（双写），按钮态变为"已收藏"。
- **WHERE** 用户进入收藏列表 **THE SYSTEM SHALL** 展示其收藏项（**云端优先**，本地兜底），点击可回看详情。
- **IF** 用户再次点击已收藏项 **THEN THE SYSTEM SHALL** 取消收藏（双删：本地 + 云端）。
- **WHILE** 网络不可用 **THE SYSTEM SHALL** 仍可读本地收藏并正常展示；恢复网络后静默同步。
- **WHEN** 用户收藏一条新闻 **THEN THE SYSTEM SHALL** 调用 `setNewsRetained` 标记该条 `isRetained: true`，触发 30 天保留（见 §5.10）。

**设计要点（本地+云端方案，owner 已确认）**
1. **存储架构**：
   - 本地：`wx.setStorageSync('favorites', [{id, title, category, addedAt, synced}])`，上限 200 条 LRU
   - 云端：新增 `favorites` 集合（`openid + newsId` 唯一索引），通过 `setUserFavorite` / `getUserFavorites` 云函数操作
2. **入口**：详情页底部操作栏新增「🤍 收藏 / ❤️ 已收藏」（与分享并列）。
3. **收藏列表**：复用左滑侧边栏新增"收藏"入口，或面板顶部"我的收藏"；**不本期新建独立页面**（控制范围）。
4. **同步策略**：首次打开收藏列表时拉取云端全量 → 合并本地 → 展示；收藏/取消操作双写；网络恢复后自动重试失败队列。
5. **数据保留联动**：收藏操作触发 `setNewsRetained(newsId, true)`，标记对应 `news_cache` 记录 `isRetained: true`（30 天保留）。

**与旧版差异**
| 维度 | 旧方案（v1.0） | 新方案（v1.1） |
|------|---------------|---------------|
| 存储 | 纯本地 `localCache` | 本地 + 云端 `favorites` 集合双写 |
| 换设备 | 丢失 | 云端同步恢复 |
| 数据保留 | 无联动 | 收藏触发 `isRetained: true` → 30 天 |

**依赖**：`setUserFavorite` / `getUserFavorites` 云函数；`openid` 由 `wx.cloud.getWXContext()` 获取。

### 5.5 RQ-07 分享功能（P1，v1.1 增强：分享标记保留）

**核心行为（EARS）**
- **WHEN** 用户点击分享 **THEN THE SYSTEM SHALL** 调起微信转发卡片（标题 + 摘要 + 封面图）。
- **WHERE** 用户从转发卡片进入 **THE SYSTEM SHALL** 直达对应新闻详情。
- **【v1.1 新增】WHEN** 用户点击分享按钮（无论是否完成转发）**THEN THE SYSTEM SHALL** 调用 `setNewsRetained` 标记该条 `isRetained: true`，触发 30 天保留。

**设计要点**
1. 详情页底部操作栏新增「↗️ 分享」；实现 `Page.onShareAppMessage` 返回 `{ title, path: 'pages/detail/detail?id=...&index=...&category=...', imageUrl }`。
2. 封面图：优先 `picUrl`，缺失用分类主题色占位图。
3. 分享语：标题 + 一句摘要（≤ 推荐字数，避免被截断）。
4. 可顺带开通「分享到朋友圈」（`onShareTimeline`，可选）。
5. **【v1.1】分享判定**：微信 `onShareAppMessage` 无成功回调，**owner 拍板：点击分享按钮即算**。在 `onShareAppMessage` 调用前执行 `setNewsRetained(newsId, true)`。
6. **【v1.1】数据保留联动**：标记 `isRetained: true` → 该新闻在 `news_cache` 中保留 30 天（见 §5.10）。

**边界**：无图新闻的分享卡片样式需有兜底视觉。

### 5.6 RQ-05 离线/弱网缓存（P2，概要）

- **WHILE** 网络不可用 **THE SYSTEM SHALL** 展示已缓存新闻列表（首页列表 + 已读详情写入本地）。
- **WHEN** 恢复网络 **THEN THE SYSTEM SHALL** 静默补充新内容，不打断阅读。
- 概要：依赖 `wx.setStorageSync` 缓存 `getNewsList` 结果与详情；与 RQ-01/RQ-03 共用本地存储层，建议统一封装 `localCache`。

### 5.7 RQ-06 浏览记录（P1，v1.1 从 P2 升级为完整设计）

> **范围升级**：原 §5.7 仅为 P2 概要，v1.1 升级为完整 P1 设计，含前端页面、存储方案、去重规则。

**核心行为（EARS）**

*Ubiquitous（始终）*
- **WHEN** 用户打开任意新闻详情 **THEN THE SYSTEM SHALL** 自动记录浏览（newsId + category + title + viewedAt），无需用户手动操作。

*Event-driven（事件驱动）*
- **WHEN** 用户点击浏览记录入口 **THEN THE SYSTEM SHALL** 展示近 7 天浏览历史列表，按时间倒序排列。
- **WHEN** 用户点击历史列表中的某条记录 **THEN THE SYSTEM SHALL** 跳转至对应新闻详情页。
- **WHEN** 用户对同一新闻多次浏览 **THEN THE SYSTEM SHALL** 刷新 `viewedAt` 时间戳（去重，不新增记录）。

*State-driven（状态驱动）*
- **WHILE** 浏览记录超过 200 条 **THE SYSTEM SHALL** 按 LRU 淘汰最早记录。
- **WHILE** 浏览记录超过 7 天 **THE SYSTEM SHALL** 自动清理过期记录（7 天窗口）。

*Unwanted（异常）*
- **IF** 网络不可用 **THEN THE SYSTEM SHALL** 仍展示本地缓存的浏览记录（本地优先）。
- **IF** 云端同步失败 **THEN THE SYSTEM SHALL** 仅使用本地记录，不阻塞展示。

**存储方案：本地为主 + 云端兜底**
| 层级 | 存储 | 说明 |
|------|------|------|
| 本地 | `wx.setStorageSync('browseHistory', [...])` | 主存储，200 条 LRU 上限，离线可用 |
| 云端 | `browse_history` 集合（openid + newsId 唯一） | 兜底备份，通过 `recordBrowse` / `getBrowseHistory` 云函数操作 |

**去重规则**
- 同一 `newsId` 重复浏览：仅更新 `viewedAt`，不新增记录
- 7 天窗口：`viewedAt` 早于 `now - 7d` 的记录在列表渲染时过滤，定期清理

**数据模型（browse_history 集合）**
| 字段 | 类型 | 说明 |
|------|------|------|
| `_openid` | string | 自动，用户标识 |
| `newsId` | string | 新闻唯一 ID |
| `title` | string | 新闻标题（冗余，方便离线展示） |
| `category` | string | 分类 |
| `viewedAt` | Date | 最近浏览时间 |
| `createdAt` | Date | 首次浏览时间 |

**入口设计**（需 UI 设计，见 §11 UI-01~UI-06）
- 侧边栏新增「浏览记录」入口（时钟图标）
- 或首页顶部/底部增加入口图标
- 列表页：时间倒序 + 日期分组（今天/昨天/更早），每条显示标题 + 分类标签 + 浏览时间

### 5.8 RQ-03 收藏上云（P1，v1.1 新增云端同步）

> 本节为 §5.4 收藏功能的数据层补充，聚焦云端存储与同步逻辑。

**云端数据模型（favorites 集合）**
| 字段 | 类型 | 说明 |
|------|------|------|
| `_openid` | string | 自动，用户标识 |
| `newsId` | string | 新闻唯一 ID |
| `title` | string | 新闻标题（冗余） |
| `category` | string | 分类 |
| `addedAt` | Date | 收藏时间 |
| `isActive` | bool | true=已收藏 / false=已取消（软删除，支持恢复） |

**云函数接口**

**`setUserFavorite(newsId, title, category, action)`**
- `action: 'add'` → 写入/更新 `favorites` 集合（upsert by openid+newsId），`isActive: true`
- `action: 'remove'` → 设置 `isActive: false`（软删除）
- 返回 `{ success, newsId }`

**`getUserFavorites()`**
- 查询 `favorites` 集合 `isActive: true`，按 `addedAt` 倒序

- 用于首次打开收藏列表时同步

**同步策略**
1. **首次加载**：`getUserFavorites()` 拉取云端全量 → 与本地合并（云端为准，去重）→ 写入本地缓存
2. **收藏操作**：本地即时更新 + 异步调用 `setUserFavorite`；失败入重试队列
3. **取消收藏**：本地即时更新 + 异步调用 `setUserFavorite(action:'remove')`
4. **网络恢复**：遍历重试队列，逐条同步

### 5.9 RQ-07 分享标记保留（P1，v1.1 新增）

> 本节为 §5.5 分享功能的数据保留补充。

**判定规则（owner 已确认）**
- 微信小程序 `onShareAppMessage` **无成功/失败回调**，无法判定用户是否完成转发
- **决策：点击分享按钮即算** — 在 `onShareAppMessage` 被调用前执行标记
- 这可能导致少量"点了分享但未完成转发"的新闻也被标记保留（可接受的误标，不影响用户体验）

**实现**
```javascript
// detail.js onShareAppMessage
onShareAppMessage() {
  const news = this.data.news;
  // 标记保留（点击即算）
  wx.cloud.callFunction({ name: 'setNewsRetained', data: { newsId: news.id, retained: true } });
  return {
    title: news.title,
    path: `/pages/detail/detail?id=${news.id}&category=${news.category}`,
    imageUrl: news.picUrl || ''
  };
}
```

**联动**：标记 `isRetained: true` → 该新闻在 `news_cache` 中享受 30 天保留（见 §5.10）。

### 5.10 RQ-16 数据保留分级策略（P0，v1.1 新增）

> **背景**：当前 `refreshNews` 的 `dbCacheTTL` 为 65 分钟，所有新闻统一过期清理。用户收藏/分享的新闻也在 65 分钟后消失，体验割裂。同时 `setNewsRetained` 云函数操作的是已停写的 `news` 集合，标记失效。

**核心行为（EARS）**

*Event-driven*
- **WHEN** 用户收藏或分享一条新闻 **THEN THE SYSTEM SHALL** 标记该条 `isRetained: true`（在 `news_cache` 集合中），享受 30 天保留。
- **WHEN** refreshNews 执行定时清理 **THEN THE SYSTEM SHALL** 跳过 `isRetained: true` 的记录，仅清理普通记录（超过 7 天）。

*State-driven*
- **WHILE** 新闻未被收藏且未被分享（`isRetained` 不存在或为 `false`）**THE SYSTEM SHALL** 在 7 天后自动清理。
- **WHILE** 新闻 `isRetained: true` **THE SYSTEM SHALL** 在 30 天后自动清理。

*Unwanted*
- **IF** 单批清理超过 100 条 **THEN THE SYSTEM SHALL** 分批执行，每批 ≤ 2 秒，避免云函数超时。
- **IF** 云数据库配额接近上限 **THEN THE SYSTEM SHALL** 优先清理非保留记录，必要时告警。

**数据模型变更（news_cache 集合）**
| 字段 | 类型 | 变更 | 说明 |
|------|------|------|------|
| `isRetained` | bool | **新增** | true=收藏或分享过，享受 30 天保留 |
| `retainedAt` | Date | **新增** | 标记保留的时间（用于计算 30 天） |
| `retainedBy` | string | **新增** | 标记来源：`favorite` / `share` |
| `cacheExpire` | Date | **语义变更** | 旧语义 65 分钟 → 新语义：普通=创建后 7 天，保留=标记后 30 天 |

**清理策略**
| 类型 | 条件 | 保留时长 | 清理方式 |
|------|------|----------|----------|
| 普通新闻 | `isRetained` 不存在或 false | 7 天（自 `createdAt` 起） | refreshNews 定时清理 |
| 收藏/分享新闻 | `isRetained: true` | 30 天（自 `retainedAt` 起） | refreshNews 定时清理 |
| 超限保护 | 单批 > 100 条 | — | 分批 ≤ 100 条/批，≤ 2s/批 |

**分级清理流程（refreshNews 改造）**
```
1. 查询 news_cache 中 cacheExpire < now 的记录（≤ 100 条/批）
2. 过滤 isRetained === true → 跳过
3. 对剩余记录执行 remove()
4. 循环至无更多过期记录
5. 单独处理 isRetained === true 且 retainedAt + 30d < now → 同样分批清理
```

**成本估算**
- 当前日均新增约 1,700 条（8 分类 × ~200 条/分类），7 天 ≈ 1.2 万条
- 需评估云数据库配额（免费版 2GB / 50 万条），1.2 万条远在配额内
- 收藏/分享标记比例预估 < 5%，对配额影响极小

**现状修正：setNewsRetained 改造**
- 当前 `setNewsRetained` 云函数操作的是 `news` 集合（自 v5.1 已停止写入）
- **改造**：将操作目标从 `news` 改为 `news_cache` 集合
- 字段：设置 `isRetained: true`、`retainedAt: now`、`retainedBy: 'favorite'|'share'`

### 5.7 RQ-17 全局返回主页入口（v1.2 新增）

> **来源**：用户直连 2026-08-03。当前详情页无快捷返回主页入口，用户只能通过微信系统左上角返回箭头逐层回退；后续新增的浏览记录页、收藏列表页等同样面临此问题。

#### 5.7.1 背景

当前页面层级：
- **一级（首页）**：`pages/home/home` — 卡片流
- **二级（详情页）**：`pages/detail/detail` — 新闻阅读（已有）
- **二级（规划中）**：`pages/history/history` — 浏览记录（RQ-06）、`pages/favorites/favorites` — 收藏列表（RQ-03）

现状：所有非首页页面均无快捷返回主页的入口。用户在详情页阅读多条新闻后，只能通过微信系统返回按钮逐层回退（或多次左滑），无法一键回到首页卡片流。

#### 5.7.2 EARS 需求描述

| 类型 | 需求 |
|------|------|
| **Ubiquitous** | **THE SYSTEM SHALL** 在除首页外的所有页面（二级/三级/四级）的导航栏固定位置提供"返回主页"图标入口（🏠 房屋图标）。 |
| **Event-driven** | **WHEN** 用户点击"返回主页"图标 **THEN THE SYSTEM SHALL** 跳转至首页 `pages/home/home`，使用 `wx.reLaunch` 清除导航栈（避免用户返回时回到已离开的页面）。 |
| **State-driven** | **WHILE** 用户在非首页页面 **THE SYSTEM SHALL** 始终在导航栏左侧展示该图标（不受页面滚动影响，`position: fixed`）。 |
| **Unwanted** | **IF** 用户已在首页 **THEN THE SYSTEM SHALL** 不展示该图标。 |
| **Optional** | **WHERE** 页面导航栏已有其他元素（如详情页进度指示）**THE SYSTEM SHALL** 将主页图标置于左侧、进度指示保持居中/右侧，互不遮挡。 |

| 编号 | 用例 | 预期 |
|------|------|------|
| C-01 | 普通新闻创建超过 7 天 → refreshNews 触发 | 被清理，news_cache 中不再存在 |
| C-02 | 收藏新闻标记 isRetained → 超过 7 天但未到 30 天 | 不被清理，仍存在于 news_cache |
| C-03 | 分享新闻标记 isRetained → 超过 7 天但未到 30 天 | 不被清理 |
| C-04 | 保留新闻超过 30 天 → refreshNews 触发 | 被清理 |
| C-05 | 过期记录超过 100 条 → refreshNews 触发 | 分批清理，每批 ≤ 100 条，无超时 |
| C-06 | setNewsRetained 调用 | 操作目标为 `news_cache` 集合（非 `news`） |

**R 组：回归（4 条）**
| 编号 | 用例 | 预期 |
|------|------|------|
| R-01 | refreshNews 正常拉取新内容 | 新内容正常写入 news_cache，cacheExpire = now + 7d |
| R-02 | 首页卡片流正常展示 | 不受 isRetained 字段影响 |
| R-03 | 详情页收藏+分享按钮共存 | 两个按钮正常展示，不冲突 |
| R-04 | 暗色模式下浏览记录页 | 样式正常，无颜色异常 |
