# 全局深浅色模式（明暗主题）治理方案

> **文档编号**：D-07 | **版本**：v1.0 | **日期**：2026-08-05
> **出品**：产品经理（PM） | **适用对象**：全栈开发（FS）、小程序前端（FE）实施 + 产品设计师（PD）走查 + owner 裁定
> **背景**：暗色模式已多轮修补（BUG-20260805-001/002/003），但均为点状修复。当前**三套主题机制并存**，存在"修了这里、漏了那里"的结构性风险。本方案给出**全局统一架构 + 全场景清单 + 实施步骤 + 验收清单**，一次性根治。

---

## 一、现状诊断

### 1.1 当前并存的三套机制

| # | 机制 | 实现 | 管什么 | 问题 |
|---|------|------|--------|------|
| ① | **原生 darkmode** | `app.json` `"darkmode": true` + `themeLocation: "theme.json"`；WXSS 通过 `var(--xxx)` 引用，微信按**系统**深浅色注入变量值 | 跟随系统 | 只认系统，不认手动 |
| ② | **自建手动主题** | `app.js` `_initTheme()`/`applyTheme()` → 计算 `themeClass` → 广播注入 5 页面根节点 `class="page {{themeClass}}"` | 手动深色 | 只覆盖深色，浅色无 class |
| ③ | **真机 fallback 兜底** | 5 页面 `.wxss` 内 `@media (prefers-color-scheme: dark) { ... }` 硬编码色值（BUG-002 引入，应对真机 var() 间歇失效） | 跟随系统兜底 | 只认系统，手动模式下失效 |

### 1.2 遗留缺口清单（本方案必须关闭）

| 编号 | 缺口 | 严重度 | 现象 |
|------|------|:---:|------|
| **G-01** | **手动浅色模式失效** | 🔴 P0 | `applyTheme()` 仅当 `!followSystem && darkMode` 时注入 `page--dark`；手动浅色（`!followSystem && !darkMode`）时 `themeClass=''` → 系统深色下页面被机制①/③ 覆盖为深色，**用户选浅色无效** |
| **G-02** | **media query 兜底与手动模式冲突** | 🔴 P0 | 5 页面 + category-wheel 的 `@media (prefers-color-scheme: dark)` 只跟随**系统**；「手动深色 + 系统浅色」时兜底不生效（元素漏变深色）；「手动浅色 + 系统深色」时兜底仍生效（元素保持深色） |
| **G-03** | **分类轮盘手动深色文字不可见** | 🔴 P0 | `category-wheel.wxss` 轮盘文字色走 `@media (prefers-color-scheme: dark)` → 手动深色 + 系统浅色时，文字为 `rgba(0,0,0,0.5)`（浅色值）落在深色底上，**不可见** |
| **G-04** | **无 `wx.onThemeChange` 监听** | 🟡 P1 | 跟随系统模式下，运行中切换系统主题，仅机制① 的 var() 自动刷新；机制③ 硬编码兜底不刷新 → 部分元素颜色滞后 |
| **G-05** | **窗口背景色写死** | 🟡 P1 | `app.json` `window.backgroundColor: "#F5F3F0"` + `backgroundTextStyle: "dark"` 固定 → 深色模式下拉回弹/露底为浅色，观感突兀 |
| **G-06** | **系统组件手动模式不可控** | 🟡 P2 | `wx.showToast/loading/actionSheet/modal` 跟随**系统**深浅色；手动模式下无法强制（微信原生限制）→ 需明确接受口径 |
| **G-07** | **硬编码颜色未收敛** | 🟡 P1 | 全仓 109 处裸色（详情见 §四·S3），其中多数是机制③ 兜底块；另有零星浅色硬编码（如 `settings.wxss` 圆形开关 `background:#fff`）在深色下无覆盖 |
| **G-08** | **分享卡片 canvas 链路待核对** | 🟢 P2 | `share-card.js` 已支持 `isDark` 参数（`bg = isDark ? info.dark : info.light`），`detail.js` 已传 `isDark`；需核对 isDark 取值来源是否始终为**当前生效主题**（含手动模式） |

### 1.3 已闭环（不复述，仅引用）

- BUG-20260805-001：dock 菜单蒙版调参（WXSS）——蒙版透明度/模糊/阴影已修，**保留**（深浅色通用，无需改动）
- BUG-20260805-002：5 页面 media 兜底——**将迁移**（见 §四·S2）
- BUG-20260805-003：手动深色全局广播（`app.js` applyTheme + 5 页面根节点注入）——**保留并扩展**（补 `page--light` + onThemeChange）

## 二、目标模型（产品口径）

### 2.1 三态定义

| 模式 | 设置页状态 | 系统浅色时 | 系统深色时 | 用户直觉 |
|------|-----------|:---:|:---:|------|
| **跟随系统**（默认） | 「跟随系统」开 | 浅色 | 深色 | 跟手机走 |
| **手动浅色** | 「跟随系统」关 + 「深色模式」关 | 浅色 | **浅色** | 我就要浅色 |
| **手动深色** | 「跟随系统」关 + 「深色模式」开 | 深色 | 深色 | 我就要深色 |

> 依据：`docs/02-产品设计/D-02-增量-UI-B9-设置页重构.md` §3.4「跟随系统 + 深色模式双开关联动」——跟随系统开启时深色由系统决定；关闭后由「深色模式」开关手动覆盖外观。**三态在任何系统主题下都必须严格成立**，这是本次治理的验收底线。

### 2.2 状态机（开发侧）

```
输入：followSystem（Storage: settings_followSystem）、darkMode（Storage: settings_darkMode）、系统主题（wx.getSystemInfoSync().theme / wx.onThemeChange）

followSystem = true  → effectiveTheme = 系统主题（并随 onThemeChange 实时更新）
followSystem = false → effectiveTheme = darkMode ? 'dark' : 'light'

根节点注入：effectiveTheme = 'dark' → class="page page--dark"
           effectiveTheme = 'light' → class="page page--light"（新增，G-01 修复关键）
```

## 三、全局架构方案

### 3.1 核心原则

1. **单一事实源**：`app.globalData.theme` 是唯一主题状态源；任何页面/组件不得自行判断主题。
2. **始终注入生效 class**：无论哪种模式，根节点都注入**实际生效**的主题 class（`page--dark` / `page--light`）——不再依赖原生 var() 注入，从根上规避真机 var() 失效（BUG-FE-002），也让机制③ 失去存在意义。
3. **变量双层**：
   - 设计层：`theme.json`（light/dark 两套 token）——**唯一色值来源**，禁止在别处定义色值
   - 运行时层：`app.wxss` 的 `.page--dark { --xxx: … }` 与新增 `.page--light { --xxx: … }`——**全仓唯一允许出现硬编码色值的两个块**；页面/组件一律 `var(--xxx)` 引用
4. **删除全部 `@media (prefers-color-scheme: dark)`**：迁移为 `.page--dark .selector { … }` 作用域写法（手动机/系统机统一），杜绝两套判定。
5. **原生 darkmode 保留**：`app.json` 的 `"darkmode": true` + `themeLocation` 保留——为 window 配置与系统组件提供原生适配底；自建 class 作为精确控制层叠加。

### 3.2 改造点（对应现有代码）

| 文件 | 改动 |
|------|------|
| `app.js` | ① `applyTheme()` 计算 `effectiveTheme` 并**始终注入** `page--dark`/`page--light`（不再输出 `''`）；② `onLaunch` 读取系统主题；③ 新增 `wx.onThemeChange` 监听（仅在 `followSystem=true` 时更新并广播）；④ `globalData` 增 `effectiveTheme` 字段 |
| `app.wxss` | ① 保留 `.page--dark` 变量块（色值与 theme.json dark 保持一致）；② **新增 `.page--light` 变量块**（色值与 theme.json light 保持一致） |
| `app.json` | `window.backgroundColor` / `backgroundTextStyle` 改为跟随主题（见 §四·S4 两种实现） |
| 5 页面 `.wxss` | 删除 `@media (prefers-color-scheme: dark)` 兜底块，改为 `.page--dark` 前缀（迁移规则见 §四·S2） |
| `category-wheel.wxss` | 删除 media 块，改 `.page--dark .wheel-label` / `.page--light .wheel-label`（G-03） |
| 5 页面 `.js/.wxml` | 无需改动（`themeClass` 注入机制已就位）；仅需确认 onShow/onLoad 已取 `globalData.themeClass`（现状 ✅） |

### 3.3 切换即时性

- 手动切换：`settings.js` toggle → `app.applyTheme()` → `getCurrentPages()` 广播（BUG-003 机制，保留）
- 系统切换（跟随模式）：`wx.onThemeChange(res => res.theme)` → 更新 `effectiveTheme` → `applyTheme()` 广播（新增）
- CSS 变量原子更新 → 无闪烁、无页面重载

## 五、实施步骤（给开发）

## 八、风险与注意

1. **WXS 红线**：`touch.wxs` 为纯 ES5，本次无涉；若有任何主题逻辑进 WXS 须遵守（本方案不涉及）。
2. **`.page--light` 与原生注入的优先级**：`.page--light` 定义在页面根 view，原生 var() 注入在 page 容器，子元素 var() 优先取最近定义 → `.page--light` 覆盖生效。S1 完成后需真机验证优先级（尤其系统深色 + 手动浅色）。
3. **迁移不可漏**：S2 的 media 块删除必须与 `.page--dark` 前缀新增同 commit，否则中间态某系统主题下样式缺失。
4. **浅色默认值**：`.page--light` 块补全后，浅色显示与现状完全一致（值取自 theme.json light），不允许顺手"优化"色值——避免视觉漂移。
