## 4. 发现与修改建议（按优先级）

### 🔴 P0（设计系统完整性 / 无障碍硬伤）

**F1 · `--primary` 悬空引用**
- 现象：D-02 §2.2 / §5 / RQ-15-D §2.2/§5 均引用 `var(--primary)`（选中项着色），但 `theme.json` 未定义该变量（仅 `--flash-tech` 等按分类）。滚轮/选中态在真机可能回退到无效值。
- 建议：在 `theme.json` 补 `--primary`：浅 `#007AFF`、暗 `#0A84FF`；并让 `--flash-*` 在需要时继承 `--primary`。**owner：视觉设计师（RQ-15-UI 顺带）/ 前端开发**。

**F2 · 「R」刷新语义 ≠ 下拉刷新，S4 不可零损合并**
- 现象：`onRefreshNews` 调云函数 `refreshNews`（强制拉取新 AI 新闻）；`onPullDownRefresh` 仅 `loadNews`（重读列表，可能命中缓存）。两者能力不同。
- 建议：S4 若采纳，须让下拉刷新也调用 `refreshNews`（或保留「R」但重设计为更轻量的「刷新本类」）。**owner：PM（PD-B4 裁定 S4 采纳口径）/ 前端开发**。

**F11 · 顶栏「R」按钮触控热区不足 + 标准自相矛盾**
- 现象：§6.3 写明最小触控 44px(88rpx)，但其示例却标「顶栏按钮 56rpx×56rpx ✅」——56rpx≈28px < 44px。实际 `top-bar-refresh` 仅 56rpx。
- 建议：将顶栏按钮热区补足至 ≥88rpx（或 56px@2x）；并修订 D-02 §6.3 示例，使其不与 44px 下限自相矛盾。**owner：交互设计师（修标准）/ 前端开发（修按钮）**。

### 🟡 P1（标准漂移 / 一致性）

**F8 · §3「边界 Chip」与代码（Toast）漂移**
- 现象：D-02 §3 反馈表列「边界 Chip 2000ms」，但 home.wxml 已移除边界 Chip（`<!-- 边界提示已移除 -->`），代码改用 Toast。
- 建议：二选一固化——(a) 恢复 Chip 符合标准；(b) 将 §3 改为「边界用 Toast」。推荐 (b)（更简洁），并同步 D-02 §3 + §10。**owner：交互设计师（修标准）**。

**F5 · 配色暖白 vs 中性灰偏差**
- 现象：`theme.json --bg-page: #F5F3F0`（暖）+ D-02 §9 暗示中性 `#F2F2F7`（COMMLOG #1153）。二者长期并存，易被认为「体验差」。
- 建议：产品/视觉定调——若暖白是品牌「纸感」刻意选择，则在 D-02 §9 正式记录为品牌色；否则对齐中性灰。**owner：视觉设计师 / 产品经理**。

**F6 · S8 与用户直报冲突（已知，PD-B4 已否决 S8）**
- 现象：S8 建议「设置入口合并到侧边栏底部」，但 BUG-20260802-005（用户直报）要求「卡片右下角 3D 浮动」。
- 建议：S8 否决，以用户直报为准；D-02 §10 标记。**owner：PM（PD-B4 落 §10）**。

**F12 · 元信息 22rpx 锁定 → 不随四档字号缩放（owner 直连例外，需登记）**
- 现象（补充审计，基线 `d0da200`）：owner 直连要求「元信息锁定 22rpx，禁止回退」，`home.wxss:147` `.card-meta{font-size:22rpx}`、`:355` 同值，**均未带 `* var(--font-scale)`**；而同页 `.card-title`(52rpx)、`.summary-p`(30rpx) 等全部走缩放。`[data-font-scale="3"] .card-meta` 只加了 `text-overflow: ellipsis`（截断保护），**不放大**。
- 影响：用户切到「大 / 特大 / 超大」时，正文放大而来源·时间等元信息恒定 22rpx（≈11px），与 D-02 §6.4「文字缩放 200% 仍可用」及 WCAG 1.4.4 存在偏差；且 tier3 下正文与元信息字号比拉大到 ~3.5:1，视觉层级过冲。
- 判定：**这是 owner 明确裁定的红线，不作为缺陷推翻**。TASK_BOARD `PD-B7` 已记载「元信息及操作栏字号强制锁定 22px，不参与字体缩放，后续禁止修改，如需调整须 owner 确认」——本条与该红线同源。交互侧的职责不是推翻它，而是按 D-02 §0「先标准后例外」**让例外从隐式变显式**。
- 建议：
  1. **（交互侧自行闭环）** D-02 §6.4 增设「例外登记表」，录入本条：适用范围 `.card-meta` / `.detail-meta` / `.bottom-bar-*`，来源 owner 直连 `06bfa0b`，对应任务 PD-B7，状态「已接受」，并注明「已知与 WCAG 1.4.4 存在偏差，产品有意为之」。作用是让后续任何人改动前先看到红线，**避免被当成 bug「顺手修好」而反复回退**。
  2. **（仅供 owner 参考，不主动推进）** 若日后收到无障碍反馈，可考虑 `calc(22rpx * min(var(--font-scale), 1.15))` —— 最高只跟涨到 25rpx，既守住「元信息必须视觉退后」的版式意图，又不完全冻结缩放。**在 owner 主动改口之前不实施。**
  3. **（提示 PM）** PD-B7 的 PRD 文案建议同时写明「此为已知无障碍取舍」，而不仅写「锁定 22px」——否则后续做无障碍验收时会被当作缺陷重复提报。
- **owner：交互设计师（§6.4 登记）+ 产品经理（PD-B7 文案补充取舍说明）**。

### 🟢 P2（体验增强）

**F4 · 首启手势引导缺口**
- 现象：引导遮罩已移除，swipe-hint 成唯一引导，但仅文字「^ 上滑阅读下一条」，可发现性弱。
- 建议：① S2 采纳图标化 `⇅`；② 首启一次性 coachmark（3~4s 自动消失，不阻塞）；③ 收藏/分享等无歧义图标保持。**owner：交互设计师（规范）+ 前端开发**。

**F9 · 缺 `prefers-reduced-motion` 适配**
- 现象：§2.2 要求 reduced-motion 用户动画 ≤100ms，但 wxss 未见对应媒体查询。
- 建议：全局加 `@media (prefers-reduced-motion: reduce){ * { animation-duration:≤100ms; transition-duration:≤100ms } }`。**owner：前端开发**。

**F7 · S6「全部/推荐」合并依赖 PD-B1**
- 现象：`constants.js` 中 `all`(全量) 与 `recommend`(推荐) 为独立语义 Tab；S6 合并会丢分流，且与「农业/科学」裁定（PD-B1/BUG-P1-011）强耦合。
- 建议：S6 暂缓，待 PD-B1 裁定后同批处理（避免二次 tab 重构）。**owner：PM（PD-B4）/ 前端开发（FE-B6 同批）**。

**F3 · RQ-15 分类滚轮即将引入，需预对齐**
- 现象：滚轮上线后移除 `panel-tabs`（AC-RQ15-10），分类切换主入口从「侧栏 Tab」变为「滚轮」。S6 合并逻辑须与滚轮分类集一致。
- 建议：RQ-15-FE 启动时，交互侧复核滚轮与 S6/面板高亮的一致性。**owner：交互设计师（RQ-15-D 已交付，待 FE 认领）**。
