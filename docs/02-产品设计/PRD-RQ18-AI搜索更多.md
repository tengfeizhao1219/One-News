# PRD — RQ-18 AI 搜索更多（基于当前新闻的 AI 深度探索）

> **版本**：v0.1（探讨稿）
> **作者**：产品经理
> **日期**：2026-08-04
> **状态**：🟡 需求探讨稿 · 待技术可行性评估后定稿排期
> **需求池**：RQ-18
> **关联**：基于现有「一页 One-News」详情页阅读体验的延伸

---

## 一、背景

当前产品定位「精选阅读」：用户读完一条新闻后即结束。但一条新闻往往关联大量背景、同主题后续进展、不同信源观点。用户需要手动搜索才能继续深挖，跳出产品。

**机会**：把「读完一条新闻」升级为「基于这条新闻的深度探索」，让 AI 主动为用户检索相关内容和总结，形成阅读延伸闭环。

---

## 二、目标

| # | 目标 | 衡量 |
|---|------|------|
| G1 | 用户读完新闻后能一键探索相关背景/延伸内容 | 详情页「AI 搜索更多」点击率 ≥ 5% |
| G2 | AI 总结质量可接受（不答非所问、来源可溯源）| 搜索总结满意度 ≥ 70%（问卷/评分）|
| G3 | 用户可追问，形成"新闻→探索→追问"闭环 | 追问率 ≥ 20%（点击搜索的用户中）|
| G4 | 来源可信、可核实 | 来源可点击查看原文，无幻觉来源 |

| ID | 用户故事 | 优先级 |

## 五、流程说明

### 5.1 主流程（AI 自动搜索）

```
用户点击「AI 搜索更多」
  → 前端进入 loading 态（骨架/进度提示）
  → 云函数 aiSearchMore
      ① 取当前新闻（title + content 摘要）
      ② AI(DeepSeek) 基于本文生成 1-3 个搜索关键词
      ③ 调通用搜索 API（Bing/博查等）拉取相关结果
      ④ 结果清洗（去重/过滤低质/保留 title+source+url+snippet）
      ⑤ AI 对结果做总结（合并同主题/提炼要点/标注信源）
  → 返回 { summary, sources: [{title, source, url, snippet}], query }
  → 前端渲染：
      总结卡片（标注「AI 生成」）
      来源列表（可展开/收起）
      追问输入框
```

### 5.2 追问流程

```
用户在输入框输入问题
  → 云函数 aiSearchMore（模式=talk）
      携带上下文：{ 原文摘要, 上次query, 上次总结, 用户问题 }
      AI 判断是否需要新搜索：
        - 需要 → 生成新 query → 搜索 → 总结
        - 不需要 → 基于已有上下文直接回答
  → 返回回答 + 可能新增的来源
```

### 5.3 来源查看流程

```
用户点击来源卡片
  → 小程序内 web-view 打开原文 URL（业务域名白名单内）
  → web-view 加载失败/不在白名单 → 降级为「复制链接 + 提示外部打开」
```

## 六、交互说明

### 6.1 入口（详情页底部）

- 位置：正文结束后、底部操作栏上方
- 形态：卡片式按钮「🔍 AI 搜索更多 · 基于本文探索相关资讯」
- 首次进入详情页即展示（不随滚动隐藏）

### 6.2 Loading 态

- 点击后进入加载：展示「AI 正在搜索相关资讯…」+ 轻量骨架
- 超时兜底：N 秒未返回 → 提示「搜索超时，请重试」

### 6.3 结果态

- **总结区**：AI 总结段落，顶部小标签「AI 生成」（与「AI 摘要」胶囊视觉体系一致，参考 UI-B8）
- **来源区**：来源卡片列表（标题 + 来源名 + 摘要一行），点击进 web-view
- **追问区**：输入框 + 发送按钮；Enter/发送触发

### 6.4 异常态

| 场景 | 表现 |
|------|------|
| 搜索 API 失败 | 提示「搜索失败，请稍后重试」，保留重试按钮 |
| AI 总结失败 | 展示原始搜索结果（不加总结），标注「AI 总结失败」|
| 无搜索结果 | 提示「暂未找到相关资讯」，引导换个问题 |
| 追问超出限流 | 提示「今日探索次数已用完」|
| 网络弱 | 进入 loading 超时兜底 |

## 九、Non-goals（非目标）

- ❌ **不做通用聊天**：只做「基于当前新闻」的相关探索与追问，不做开放域对话
- ❌ **不承诺实时性**：AI 生成内容不保证最新，靠来源标注让用户自行核实
- ❌ **本期不接图片搜索**：只做文本新闻搜索
- ❌ **不做搜索历史管理**：追问会话不持久化到用户账号（单次会话内有效）
- ❌ **不做站内内容搜索**：搜索范围为全网新闻资讯，不局限于本 app 已有缓存

## 十、技术依赖与风险

### 10.1 技术依赖（需全栈开发确认）

| 依赖 | 说明 | 状态 |
|------|------|:---:|
| **通用搜索 API** | Bing Web Search / 博查(BoCha) AI 搜索 / SerpAPI 等，需新增 Key + 评估中文质量与配额 | ⚠️ 待选型 |
| **AI 模型** | 现有 `DASHSCOPE_API_KEY`（DeepSeek）用于生成 query + 总结 + 追问 | ✅ 已有 |
| **新云函数** | `aiSearchMore`（搜索+总结）/ 追问复用同函数 | 待开发 |
| **web-view 域名** | 业务域名白名单需在微信公众平台配置 | ⚠️ 需申请 |
| **成本预算** | 每次搜索 ≈ DeepSeek 调用 + 搜索 API 调用 | 需评估 |

### 10.2 风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| 搜索 API 中文质量差 | 总结相关性低 | 选型对比（博查 vs Bing）；A/B 抽样人工评测 |
| AI 幻觉来源 | 可信度风险 | 来源必须来自搜索结果（非 AI 编造）；标注「AI 生成」|
| 成本失控 | 预算超支 | 每日/每用户次数上限 + 冷却；监控成本 |
| web-view 域名受限 | 原文查看受阻 | 降级为复制链接；优先配置主流新闻源域名 |
| 搜索耗时过长 | 体验差 | 搜索 API 超时控制 + 前端 loading 优化 |
