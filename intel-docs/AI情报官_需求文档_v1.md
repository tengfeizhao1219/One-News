## 1. 需求背景

### 1.1 动机
AI 发展极快、每天有新产物，前沿信息散、门槛高，普通人容易陷入两种状态：**错过**（不知道发生了什么、跟我有什么关系）或**空看**（知道但用不上、也判断不了未来）。本工具的本质价值是三层：

> **汇总 → 翻译成「和我的生活/工作有什么关系、怎么用」→ 给未来方向感**
> 它是「翻译器 + 减压阀」，不是资讯聚合器本身。

### 1.2 目标用户
- **底层是「通用普通人」**：不绑定任何具体项目或身份，越通用越好。
- **具体的人是通用模板的实例化**：老赵当前的 RCBC / One News / 装修只是「初始化问卷的一份示例答案」，**不写死在系统里**。
- 老赵的角色：本工具的**首个打磨样本**（以产品域上下文试点），未来可给任意普通人用。

### 1.3 定位与语气（决策 7、8）
- **翻译优先（A）**：有趣但暂时用不上的资讯，也讲清「是什么、和你有什么关系」，不硬塞行动；行动只在真有低门槛时才附。
- **有则汇报，无则不打扰**：Push 不为打卡而发；定时巡检可以有，但「发布」必须绑定「确有值得说的内容」，空更新本身会造成焦虑噪音。

### 1.4 非目标（v1 明确不做）
- 不覆盖工作域（RCBC / TrustDecision）与家庭域（装修 / 育儿）的专项情报内容（接口与模板预留）。
- 不接入受限制的 RCBC 内部合规信息。
- 不定技术栈、不落地代码（本阶段只定需求）。
- 不自动修改 One News 任何代码 / UI（含 hex 色值）；v1 仅出设计方案。

## 5. 核心输出单元

### 5.1 筛选门槛（两层，决策 9）
1. **第一层粗筛**：来自初始化「关注领域」——只在该范围内挑。
2. **第二层精筛**：工具判断「这条对普通人到底有没有用 / 有没有影响 / 是不是趋势拐点」，过滤纯参数堆砌、行业内部噪音、八竿子打不着的。

### 5.2 单条 SOP 内容粒度（决策 10，已认可）
1. **溯源**：来源（媒体/官网/论文/社区）+ 时间 + 原文链接。1–2 行。
2. **定义**：这是什么、边界在哪（不夸大）。1 句，≤40 字为佳。
3. **场景映射**：落到「和你（普通人）有什么关系」，至少 1 个真实生活/工作场景。2–4 行。
4. **实操案例**：默认写「为什么值得关注 + 大致怎么用」；**仅当确有低门槛动作时**，才补「具体工具 + 步骤 + 收益 + 坑点」。
5. **最小行动**：仅当第 4 步有低门槛动作时，给「今日/本周做一件小事」；否则留空或写「暂观察」。

> ④⑤ 为「条件式填写」，与定位 A（翻译优先、不硬塞）一致。

### 5.3 模板结构（三段，决策 11）
- **🔹 今日关注**（日更，有则汇报）：当天通过两层筛选的每条情报，按 SOP 五步呈现；无内容则整块静默、不出产。
- **🔹 本周可试用清单**（周更）：把本周「最小行动」里低门槛、可上手的项聚成清单，方便周末一口气试。
- **🔹 本周趋势小结**（周更，决策 6-C）：不进单条；给一段「本周 AI 往哪走 / 对普通人意味着什么」的轻量方向判断。

### 5.4 双版本 × 多通道（决策 12）
| 通道 | 渲染版本 | 说明 |
|---|---|---|
| One News 模块（主力） | **完整版** | 五步全展开 + 溯源链接 + 趋势小结全文 |
| IM / 微信 / WhatsApp | **极简版** | 压成「定义 + 和你什么关系 + （有则）一步动作」，控长度 |

> 双版本不是两份独立文档，而是「按通道自动选渲染」。

### 5.5 部署载体（决策 13，暂定）
- 暂定**融入现有 One News 小程序**（作为站内模块），不开独立小程序。
- 可复用 One News 现有能力（AI 阅读引擎做精读、RSS 做源接入）呈现情报。
- 触发 **One News UI 红线（见 §7 专属约束）**：模块任何 UI 改动须先出方案确认、禁止新增 hex 色值；v1 仅出设计方案。

## 5A. 详情页话题搜索深挖（2026-08-21/22 新增功能）

> 本节为 8-21/22 落地的话题搜索深挖功能需求，intel 情报详情页与 One News 新闻详情页双端生效。
> 交互/UI 细节见《情报详情页话题搜索_前端UIUX交互设计.md》；接口契约见《情报详情页话题搜索_技术设计.md》。

### 5A.1 功能定位（为什么做）
- 用户在详情页读完情报/新闻后，常有「进一步了解」诉求（这项技术原理？对我有什么影响？同类怎么比？）
- 需求：提供**话题搜索深挖**入口，用户输入话题 → 联网搜索 → 得到**贴合用户真实意图**的总结回答 + 引用来源。

### 5A.2 入口与交互
1. **入口**：详情页右下角**搜索悬浮按钮**（自绘放大镜，对齐首页 FAB 形态：96rpx 圆 + floatY）。
2. **展开**：点击后面板从底部升起，**把标题以下内容整体顶上去**（同页过渡不切页）；标题保留，呼吸间距 18rpx。
3. **展开动画**：面板升起同时，搜索横线作为**系统蓝进度条**从左侧加载（0.65s）。
4. **输入**：极简**横线式输入**（无边框容器，高度 1.5 倍）；放大镜 icon 按钮（无圆形边框）。
5. **收起**：三种途径——点 FAB / 下滑到面板顶（内容超出时）/ 退出页面；**任何离开都自动折叠历史**。

### 5A.3 搜索处理管线（后端 intelSearch）
```
用户输入
  → ① 相关性判断（AI 相关 / 与新闻主题相关；不相关返回友好提示）
  → ② 真实意图理解（结合：新闻主题 + 用户画像 + 历史搜索）
       → 推断 {意图, 使用场景, 精准搜索词}
  → ③ 联网搜索（Tavily 主通道 1-3s → 智谱 web_search 兜底）
  → ④ 总结回答（DeepSeek，注入意图与场景，贴合用户诉求）
  → 返回 answer + sources
```
- **真实意图理解**（8-21 新增）：结合文章主题、用户初始化画像（identitiesSummary/focusTags）、最近 5 条历史搜索词，推断用户「想知道什么、用在哪」，优化搜索词与回答方向——避免泛泛而谈。
- **双端差异**：intel 详情页传画像+历史+新闻；One News 详情页传历史+新闻（无画像时后端降级）。

### 5A.4 结果展示（四层组织）
1. **分组**（话题）：同话题多次深挖合并，互斥展开，默认折叠，展开自动置顶。
2. **条目**（每次深挖）：带时间戳，同话题下多条按时间倒序。
3. **内容**（sections）：小标题 / 段落 / 列表结构化排版（LLM 返回结构化，前端按类型渲染；清洗 markdown 标记）。
4. **来源**：内置条目内，**默认折叠**（「参考来源(N) 展开 ›」），点击展开、复制链接。

### 5A.5 历史与状态
- **持久化**：深挖历史存本地（按新闻/情报 id 隔离），退出再进保留；上限 10 话题 × 10 条目；全局 200 key 上限防累积超限。
- **默认折叠**：展开面板时、退出页面时、新搜索发起时历史均折叠；仅搜索完成当前话题展开。
- **防重复**：并发触发（连点/confirm+按钮）防重——同步锁 + 内容指纹去重 + 历史加载清洗。
- **状态边界**：翻页切新闻清空上一条深挖历史；切后台/退出折叠；首次进入详情未就绪时搜索提示等待。

### 5A.6 边界与兜底
- 详情加载中搜索 → toast 等待（防面板顶到屏幕最上方）。
- 面板内容不足一屏 → 不因滑动收起（防误触）。
- 搜索失败 / 不相关 → 友好提示条，不影响已有历史。
- 来源为空 / answer 为空 / engine 为空 → 前端容错。

## 6. 信息源（混合模式，决策 3、16、21–24）

### 6.1 三类来源

| 类型 | 落地方式 |
|---|---|
| 实时检索 | 巡检时按「用户关注领域标签 + 一套基线 AI 大事件监控词」自动检索，抓最新 |
| 固定信源 | **系统内置默认精选信源清单**（综合 / 均衡，中英文兼顾，用户可增删）——通用用户开箱即有料 |
| 用户投喂 | 随时粘贴链接 / 原文 / 截图，直接进处理管线 |

### 6.2 固定信源默认清单（综合 / 均衡版）

> 取向：更综合、不偏中文（决策 22）。默认开启 **A–E 五层（国际均衡）**；**F 层中文 / 公众号** 为补充层，由用户初始化「语言偏好 / 关注面」决定是否拉起。完整条目与抓取方式见《AI 信息源调研》§2。

| 层 | 目标 | 默认包含的源（摘要）|
|---|---|---|
| A 广度扫描（日）| 5–10 分钟知道发生了什么 | The Rundown AI / TLDR AI / The Neuron / Ben's Bites + TechCrunch·VentureBeat·The Verge·MarkTechPost（RSS）+ Google News RSS（兜底）|
| B 深度阅读（周）| 搞清「为什么重要」 | The Batch / Import AI / Ahead of AI / Latent Space / SemiAnalysis / One Useful Thing |
| C 趋势判断（月/季）| 感知方向 | Stanford AI Index / Exponential View + OpenAI·Anthropic·DeepMind·Meta·Mistral·xAI·Hugging Face 官方博客 + arXiv |
| D 社区信号（实时）| 草根 / 热度 | Hacker News（Algolia API）/ Reddit（r/singularity 等）/ LessWrong |
| E 工具发现（日）| 普通人找工具 | Product Hunt / There's An AI For That / GitHub Trending |
| F 中文补充（按需）| 国内视角 | 机器之心 / 量子位 / 新智元 / 36氪·AI / 极客公园 / 微信公众号（合规路径）|

### 6.3 抓取方案（不同源不同方案，决策 23）

> 结论：**不存在一套统一方案套所有源**。详细映射见《AI 信息源调研》§3–§4。

| 源类别 | 抓取方案 |
|---|---|
| 综合日报 / 新闻站 / 实验室博客 | **RSS 直连**（零密钥、最稳）|
| 无 RSS 的官方博客（Anthropic / Meta / The Batch / The Neuron 实测确认）| **官网网页抓取**（结构化解析标题/日期，守 robots.txt）|
| Hacker News | **Algolia Search API**（无密钥、可关键词 + points 阈值）|
| Reddit | **RSS（无密钥，无评分）** 或 OAuth API（免费 100 QPM 非商用；2026 未认证 .json 返回 403）|
| arXiv | **export.arxiv.org API**（无密钥，3 秒限速，分类检索）|
| 兜底聚合 | **Google News RSS**（无密钥，~100 条上限、重定向链接、无 SLA）|
| 强聚合器（NewsAPI 类等）| 官方 API（需密钥，免费层受限，仅作补充）|
| 工具发现 / 部分官方页 | RSS 或网页抓取（守 robots.txt 与速率）|
| YouTube（可选）| **YouTube Data API v3**（需密钥，1 万配额/日）|
| X / Twitter | **默认不纳入**（2026 无免费层、ToS 灰区）；如需走付费第三方并明示成本/风险 |
| 用户投喂 | 解析管线（链接 / 原文 / 截图）|

### 6.4 微信公众号抓取（合规条款，决策 24）

用户指令：**公众号源在不违反相关版权的前提下可以抓取**。纳入但受严格合规约束：

1. **仅个人使用**：结果只用于本用户自己的情报处理，不对外分发、不商用、不二次传播；
2. **尊重版权**：输出标注来源公众号 + 原文链接 + 作者，不整篇搬运，摘要 / 翻译优先；
3. **最小必要**：只抓用户主动订阅 / 关注的号，不广撒网；
4. **可关停 + 自降级**：用户可一键关闭；平台政策变化致路径失效时自动静默降级，不报错刷屏；
5. **本地优先**：默认走**本地 SQLite 解析**（ChatLog / wechat_db_parser，读自己客户端已同步数据，离线、检测面最小、维护常规）；需要公众号**正文**时补**微信读书 API**（私有部署、自有账号）；**不接** RSSHub 公众号路由 / 网页抓取 / 公共第三方托管（路径对比与推荐见调研 §5.2、§5.4）；
6. **风险告知**：初始化时明确提示「公众号抓取处于平台合规灰区，仅限个人学习研究」。
> 技术路径与合规细节见《AI 信息源调研》§5。

### 6.5 巡检频率（决策 21）

- **每日固定三次巡检：05:00 / 11:00 / 18:00，仅此三次，不做更多。**
- 巡检 = 拉取 / 检索；**发布绑定内容**——确有值得说的内容才出「今日关注」，空更新不出产（与决策 8「有则汇报、无则不打扰」一致）。
- **发布策略（已定，决策 21 细化）**：**18:00 为当日汇总结案时点**——把全天三次巡检累积的候选做一层精筛后产出「今日关注」；**05:00 / 11:00 仅补抓入库**，不直接推送（除非捕获到重大突发，可破例即时推送，需标注「突发」）。

## 7. 约束（硬规则，决策 17）

### 7.1 通用约束（所有用户）
- 中文、务实、不堆参数、不软文；
- 不确定一律标「待验证」；
- 翻译优先、不硬塞动作（决策 7）；
- 有则汇报、无则不打扰（决策 8）；
- 结合用户初始化提供的个人上下文（原「RCBC / One News / 装修」改为「用户自己填的」）。

### 7.2 专属 / 条件约束（仅特定情形生效）
- **合同 / 接口变更先走 commlog 广播**：仅当使用者有项目 / 合同、且工具要提变更时（通用用户无 commlog，不触发）；
- **英文邮件先中文梳理再出稿**：仅当用户要求英文输出时；
- **One News UI 红线（先方案确认 + 禁新增 hex）**：仅当在 One News 内建 / 改模块 UI 时（v1 只出方案不改码）。

## 8. Pull 交互边界（拒绝清单，决策 18）
1. **不直改代码 / UI**：任何 One News 或他处代码、UI 改动，只出方案不落地；
2. **不编造 / 不夸大**：能力定义必须含边界，存疑标「待验证」；
3. **不越权对外**：替你发邮件 / 对外沟通前先中文确认；
4. **不空产出**：无有价值内容就静默，不为打卡硬凑；
5. **不越界专业建议**：投资 / 医疗 / 法律等只给信息、标注「非专业建议、请核实」；
6. **不碰隐私外传**：只用你初始化填的上下文，不外传。

---

## 9. 非功能需求（决策 19）
- **可溯源**：每条结论可回溯来源 + 时间；
- **时效性**：资讯以「新」为优先，陈旧信息须注明时间；
- **精准去噪**：两层筛选保证「有则汇报」，不空推、不刷屏；
- **个性化**：输出随用户初始化上下文变化，不千人一面；
- **可演进**：内核通用，域（产品→工作→家庭）与通道（小程序→IM）可平滑扩展；
- **轻量无压**：交互与推送降低焦虑，不制造噪音；
- **隐私合规**：仅用用户填的上下文，不外传。

---

## 10. 验收标准（v1 完成定义，决策 20）
1. **初始化可用**：新用户填完 4 字段问卷，系统据此建立关注面 + 个人上下文；
2. **信息源跑通**：实时检索 + 默认固定信源 + 用户投喂三条均能产生候选情报；
3. **两层筛选生效**：按关注面粗筛 + 工具精筛「对普通人有用/有影响」；无内容时静默、不空推；
4. **单条 SOP 跑通**：一条情报走完五步（④⑤条件式），产出符合既定粒度；
5. **三段模板产出**：能产出「今日关注 / 本周可试用清单 / 本周趋势小结」；
6. **双版本×多通道**：One News 模块 = 完整版、IM / 微信 / WhatsApp = 极简版，渲染正确；
7. **约束与拒绝清单**全部生效、可验证；
8. **One News 模块（暂定）**：产出经确认的设计方案（v1 只出方案不改码），UI 红线已遵守。
