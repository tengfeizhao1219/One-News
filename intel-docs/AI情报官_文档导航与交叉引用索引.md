## 2. 术语与缩写表（Glossary）

| 术语 | 含义 | 出现位置 |
|---|---|---|
| **AI 情报官 / 情报官** | 本系统产品名（老赵的 AI 情报官 + 落地教练），把新 AI 信息翻译成老赵明天能用的行动方案 | 全局 |
| **One News** | 宿主小程序产品（老赵的产品，AI 阅读引擎 / RSS / theme.json）；情报官**嵌入**其中作「AI 情报」模块 | 需求 §5.4、设计 §2 |

| **Brief（当日滚动简报）** | 处理层产出、推送层发布的当日结构化情报；含「🔹 今日关注」「🔹 本周可试用清单」 | 需求 §5.3、设计 §7.4 |
| **发布闸门（Release Gate）** | 内容先 staged，到目标时刻 T 才升级 `currentIssue` 指针，保证准点呈现 | 设计 §7.2（承接 §5.9）|
| **SOP 五步** | 溯源 / 一句话定义 / 场景映射 / 可落地实操 / 最小行动——每条高相关信息的硬性结构 | 需求 §5.2（决策 10）、设计 §6.2 |
| **场景映射** | 把 AI 信息映射到老赵三重身份（RCBC / One News / 装修育儿）的相关性权重，命中越多排序越前 | 需求 §5.2、设计 §6.4 |
| **默认信源清单 A–F** | A 广度/B 深度/C 趋势/D 社区/E 工具/F 中文补充；**A–E 默认开、F 中文按需** | 需求 §6.2、调研 §2 |
| **差异化抓取** | 不同源用不同适配器：RSS / API / 官网抓取 / Google News 兜底 / 公众号本地 | 需求 §6.3（决策 23）、调研 §3–§4、设计 §5 |

| **intel\_* 命名空间** | 情报官数据在 One News 库中独立命名空间，与现有阅读数据物理隔离 | 设计 §8.3 / §8.6 / §10.5 |
| **commlog** | 合同 / 接口变更广播落点（`~/.workbuddy/whiteboard/commlog/`）；硬约束「先广播再呈现」 | 需求 §7.2、设计 §6.7 |
| **有则汇报、无则不打扰** | 输出原则：确有内容才出「今日关注」，空更新不出产 | 需求 §1.3（决策 8）、设计 §7.3 |
